## 5. 기존 설정에 추가하고 실제 호출 확인하기

```text
현재 환경의 공식 훅 설정 방식에 맞춰, 방금 스크립트를
Edit|Write에 대한 동기식 PreToolUse command 훅으로 연결해줘.
기존 설정을 유지하고 이 실습 항목만 추가해줘.
프로젝트의 절대 위치를 안전하게 참조하고 경로의 공백도 처리해줘.
스크립트 시작 실패·시간 초과 때의 실제 동작과 적용 조건도 설명해줘.
현재 버전이 지원하면 해당 차단 검사의 실패도 막도록 설정해줘.
지원되지 않는 설정값은 만들어 넣지 마.
```

앱이 새 세션이나 설정 재적용을 요구하면 그 안내를 따른다. 메뉴가 없는 환경에서 `/hooks` 메뉴가 있다고 단정하지 않는다. Code 설정 파일과 실제 훅 호출 기록으로 확인한다.

다음 두 요청을 **하나씩** 실행한다.

```text
normal-demo.md의 '수정 전'을 '수정 후'로 Edit 도구로 바꿔줘.
```

```text
protected-demo.md의 문장을 Edit 도구로 바꾸려고 한 번만 시도해줘.
훅이 차단하면 멈추고 이유를 보고해줘.
Bash·다른 도구·이름 변경으로 우회하지 마.
```

## 6. 예상 결과와 검수

| 검사 | 기대 결과 | 확인할 증거 |
|---|---|---|
| 일반 파일 수정 | 성공 | 실제 파일에 '수정 후' |
| 보호 파일 수정 | 차단 | 훅 차단 메시지 + 보호 파일 내용 동일 |
| 잘못된 가짜 입력 | 코드 2 | 스크립트 시험 결과 |
| 기존 설정 | 유지 | 변경 전후 차이에서 추가한 항목만 확인 |

도구를 호출하지 않고 Claude가 스스로 거절했다면 **훅 차단 검증은 미수행**이다. 오류나 시간 초과 때의 실제 호출은 아직 시험하지 않았다면 미확인으로 남긴다. 검사 스크립트의 `catch`는 실행 시작조차 못한 문제를 처리하지 못한다.

## 7. 해제와 복구

실습 훅 항목만 제거한다. 시작할 때 설정 파일이 없었다면 이번에 만든 내용만 있는지 확인한 뒤 처리한다. 다른 작업이 설정을 바꿨다면 백업을 통째로 덮어쓰지 말고 차이를 합친다. 훅 해제 후 같은 보호 파일의 무해한 수정이 허용되는지도 확인한다.

| 증상 | 확인할 것 |
|---|---|
| 정상 파일도 막힘 | 입력 JSON·도구 이름·파일 경로·실제 stderr |
| 보호 파일이 수정됨 | 해당 수정 도구가 매칭됐는지, 훅 호출 로그가 있는지 |
| 스크립트가 아예 실행 안 됨 | 실행 파일·경로·공백 처리·현재 버전의 셸 설정 |
| 끝나지 않고 반복함 | Stop 훅 등 다른 종료 검사가 연결됐는지 |
