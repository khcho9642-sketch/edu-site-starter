## [강좌] D24. 서브에이전트 — 만든 사람과 확인하는 사람을 나누자

> Codex 앱 선택 심화 · Windows 중심 · 공식 확인: 2026-11-14
> 먼저 읽을 강의: D14 · D22. D23의 실습 훅은 종료·해제한 뒤 진행합니다.

## 3줄요약

1. 서브에이전트는 특정 역할을 맡겨 결과를 받는 보조 작업자다.
2. 이번에는 회의록 결과를 직접 고치지 않는 검토자를 만든다.
3. '읽기만 해'라는 설명과 실제 도구 제한은 구분한다. 검토 의견도 원문과 대조한다.

## 1. 일을 나누는 이유

한 대화에 조사·작성·테스트·검토를 전부 넣으면 어느 단계에서 틀렸는지 찾기 어렵다. 역할을 나누면 입력과 완료 기준을 따로 줄 수 있다. 그렇다고 AI 검토가 사람 검토를 없애주는 것은 아니다. 같은 오해를 공유할 수도 있다.

| 역할 | 맡기는 일 | 이번 실습 |
|---|---|---|
| 조사 | 관련 자료와 구조 파악 | 입력 회의 A 확인 |
| 작성 | 기준에 따라 결과 생성 | D22의 스킬 결과 |
| 검토 | 누락·추정·근거 확인 | 일부러 틀린 결과 검사 |
| 사용자 | 근거 비교와 최종 판단 | 지적한 오류 3개 확인 |

일반적으로 위임할 때 필요한 배경과 파일을 명확하게 전달한다. 환경에 따라 대화 분기처럼 컨텍스트를 이어받는 방식도 있으므로 '모든 보조 작업자는 항상 완전한 백지'라고 외우지 않는다. 이번에는 필요한 입력을 지시문에 직접 적는다.

## 2. 준비물

1. D22의 입력/회의A.md와 [공통 오류 결과](/chatgpt-materials/extensions)를 준비한다.
2. 원문과 오류 결과의 작업 전 해시·내용을 기록한다. D23에서 실제 훅을 설치했다면 실습 항목을 해제한 뒤 진행한다.
3. Codex 앱에서 실제 서브에이전트 지원과 부모 작업의 권한을 확인한다. 웹 Work의 위임과 로컬 Codex의 사용자 정의 설정을 혼동하지 않는다.
4. 사용자 정의 이름은 `meeting-reviewer-demo`다. 같은 이름이 있으면 덮어쓰지 않는다.

## 3. 검토자 파일 만들기

Codex 사용자 정의 에이전트는 `.codex/agents/meeting-reviewer-demo.toml` 예시를 사용한다. Claude의 YAML `tools: Read, Glob, Grep`, `model: inherit`, `maxTurns`를 그대로 옮기지 않는다.

```toml
name = "meeting-reviewer-demo"
description = "회의 원문과 결과의 담당자·기한·실행 상태를 근거로 비교하는 검토자"
developer_instructions = """
두 입력 파일을 읽고 오류를 보고만 합니다.
파일 수정, 외부 연결, 메일 발송을 하지 않습니다.
근거ID·현재값·원문값·수정 제안을 제시합니다.
정상 항목과 확인하지 못한 부분도 구분합니다.
"""
```

특정 모델을 강제로 지정하지 않아 부모 설정을 따르게 한다. 위의 역할 지시는 기술적 읽기 전용 권한 설정이 아니다. 부모 권한·실제 도구 범위를 따로 확인해야 한다. 현재 지원되는 옵션으로 권한을 좁힐 수 없다면 “수정 금지 요청, 기술적 제한 미검증”으로 기록한다.

```text
이 연습 프로젝트의 사용자 정의 검토자 초안을 위 TOML 형식으로 보여줘.
기존 이름과 충돌하지 않는지, 현재 버전이 각 필드를 지원하는지 확인해줘.
에이전트 파일에 sandbox_mode나 MCP 설정을 넣어 권한이 독립적으로 바뀐다고 가정하지 마.
아직 에이전트 실행이나 전역 설정 변경은 하지 마.
```

## 4. 검토를 맡기기

먼저 부모 작업의 권한과 외부 연결 상태를 확인한다. 승인 방식만 바꾸는 것을 읽기 전용 격리라고 부르지 않는다. 지원되는 읽기 전용 환경을 선택할 수 있을 때는 그 적용 범위를 확인한다.

```text
실제 meeting-reviewer-demo 서브에이전트에 아래 검토를 위임해줘.
원문: 입력/회의A.md
대상: 검수/회의A_오류예시.md
기준: 실행/보류, 담당자·기한 원문 일치, 근거ID.
파일을 수정하지 말고 검토 결과만 반환해줘.
실제 보조 작업 이름·사용한 도구·완료 상태를 확인할 수 있게 보고해줘.
지원되지 않으면 메인 작업이 대신했다고 구분해줘.
```

활동 표시나 실제 위임 기록을 확인한다. 메인 답변에서 검토자 말투만 흉내 낸 것은 서브에이전트 실행 증거가 아니다.
