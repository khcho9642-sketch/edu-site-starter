## 5. 같은 자료와 다른 자료에 적용하기

현재 앱의 Skills 목록이나 제공되는 선택 UI에서 `meeting-actions`가 있는지 확인한다. 명시 선택이 가능하면 선택하고 입력 경로를 적는다.

```text
meeting-actions 스킬을 사용해 입력/회의A.md를 정리해줘.
어떤 스킬을 실제 사용했는지 표시하고, 출력/회의A_스킬.md에 결과를 저장해줘.
원본은 변경하지 마.
```

회의 B에도 같은 요청을 하되 경로와 결과 파일명을 바꾼다. A의 담당자·기한을 B에 복사하지 않는다.

목록에 없으면 폴더·파일명과 현재 세션의 스킬 발견 상태를 확인한다. 여전히 안 되면 SKILL.md를 직접 첨부해 실행하되 **절차 첨부, 스킬 호출 미확인**으로 기록한다. Codex CLI 전용 `/skills` 또는 `$` 입력을 앱의 필수 조작이라고 가르치지 않는다.

## 6. 예상 결과와 검수

| 검수 항목 | 회의 A | 회의 B |
|---|---:|---:|
| 실행할 일 | 3개 | 2개 |
| 실행할 일 중 담당자 미정 | 1개 | 0개 |
| 실행할 일 중 기한 미정 | 1개 | 1개 |
| 보류 | 1개 | 1개 |

`출력/스킬_검수.md`에 입력 경로, 스킬 경로, 호출 확인 여부, 예상값과 실제값을 적는다. 수동 결과와 스킬 결과의 문장이 달라도 괜찮다. 분류·건수·근거가 같아야 한다.

## 7. 막혔을 때

| 증상 | 확인 |
|---|---|
| 스킬을 못 찾음 | 선택한 프로젝트 아래 .agents/skills/meeting-actions/SKILL.md와 메타데이터 |
| 다른 회의가 섞임 | 요청한 입력 경로와 실제 읽은 파일 |
| 담당·기한을 채움 | 원문 항목ID와 미정 유지 규칙 |
| 호출 표시가 없음 | 실제 사용 증거가 없으면 미확인으로 기록 |
| 저장 결과가 없음 | 실제 파일 경로와 출력 내용 |

사용자 지침으로 자동 호출을 확실히 차단했다고 주장하지 않는다. 한 번 쓰는 요청을 모두 스킬로 만들 필요는 없다.

**준비:** ZIP의 회의A.md·회의B.md를 각각 준비합니다.

[공통 실습 파일 ZIP 받기](/materials/walkthrough/cd-practice-starter.zip) · ZIP을 모두 푼 뒤 00_먼저읽기.md부터 확인합니다.

**내 화면에서:** Codex 프로젝트 위치는 .agents/skills/meeting-actions/SKILL.md입니다. Claude의 $ARGUMENTS 등 전용 설정을 복사하지 않습니다.

1. 수동으로 회의 A를 정리해 실행 3개·보류 1개를 먼저 확인합니다.
2. 프로젝트용 SKILL.md를 올바른 제품 경로에 만들고 name·description·입출력·미정·보류 규칙을 확인합니다.
3. 실제 호출이 확인된 경우에만 스킬 사용으로 기록합니다. 목록에 없으면 절차 파일 첨부로 A·B를 처리하고 수행 경로를 적습니다.

**완료 확인**

- 회의 A: 실행 3 / 담당 미정 1 / 기한 미정 1 / 보류 1
- 회의 B: 실행 2 / 담당 미정 0 / 기한 미정 1 / 보류 1
- 항목ID·근거ID 모두 M01~M04 / N01~N03 원문 그대로 유지

**막혔을 때:** 스킬만 실행해서 원문을 못 찾으면 회의 A·B를 명시해 전달합니다. 항목ID와 근거ID도 대조하고 A01/B01처럼 새로 번호를 붙였으면 고칩니다. 스킬 파일 저장·발견·실제 사용·결과 검수는 각각 기록합니다.

### 실제 예약 실행에서 발견한 오류

원문의 `M01`을 결과의 항목ID에서 `A01`로, `N01`을 `B01`로 바꾸는 문제가 있었습니다. 근거ID가 맞아도 항목ID 변경을 놓치면 안 됩니다. 스킬에 **항목ID와 근거ID 모두 원문 ID를 그대로 유지**한다는 규칙을 추가했습니다.

원래 예약 출력과 수동 재검수 파일을 따로 보존했습니다. 예약이 실행됐다는 사실과 수정된 스킬의 재실행 검증은 구분합니다. 일반 ChatGPT의 절차 첨부와 이번 Codex 로컬 스킬 발견·읽기도 다른 경로입니다.
