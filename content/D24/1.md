## [강좌] C24. 서브에이전트 — 만든 사람과 확인하는 사람을 나누자

> Claude Desktop의 **Code 로컬 프로젝트** 기준 · Windows 중심 · 공식 문서 확인: 2026-11-14
>
> 먼저 읽을 강의: C14 · C22. C23의 실습 훅은 종료·해제한 뒤 진행합니다.
>

## 3줄요약

1. 서브에이전트는 특정 역할을 맡겨 결과를 받는 보조 작업자다.
2. 이번에는 회의록 결과를 직접 고치지 않는 검토자를 만든다.
3. '읽기만 해'라는 설명과 실제 도구 제한은 구분한다. 검토 의견도 원문과 대조한다.

## 1. 일을 나누는 이유

한 대화에 조사·작성·테스트·검토를 전부 넣으면 어느 단계에서 틀렸는지 찾기 어렵다. 역할을 나누면 입력과 완료 기준을 따로 줄 수 있다. 그렇다고 AI 검토가 사람 검토를 없애주는 것은 아니다. 같은 오해를 공유할 수도 있다.

| 역할 | 맡기는 일 | 이번 실습 |
|---|---|---|
| 조사 | 관련 자료와 구조 파악 | 입력 회의 A 확인 |
| 작성 | 기준에 따라 결과 생성 | C22의 스킬 결과 |
| 검토 | 누락·추정·근거 확인 | 일부러 틀린 결과 검사 |
| 사용자 | 근거 비교와 최종 판단 | 지적한 오류 3개 확인 |

일반적으로 위임할 때 필요한 배경과 파일을 명확하게 전달한다. 환경에 따라 대화 분기처럼 컨텍스트를 이어받는 방식도 있으므로 '모든 보조 작업자는 항상 완전한 백지'라고 외우지 않는다. 이번에는 필요한 입력을 지시문에 직접 적는다.

## 2. 준비물

1. C22의 로컬 연습 폴더와 `입력/회의A.md`를 준비한다.
2. [공통 샘플](/desktop-materials/extensions)의 **오류가 있는 회의 A 결과**를 `검수/회의A_오류예시.md`에 저장한다.
3. 현재 Code 세션에서 사용자 정의 서브에이전트와 읽기 도구를 사용할 수 있는지 확인한다.
4. 기존 에이전트와 같은 이름을 쓰지 않는다. 이번 이름은 `meeting-reviewer-demo`다.

## 3. 검토자 파일 만들기

Code 입력창에 붙여 넣는다.

```text
이 프로젝트에 회의록 검토용 서브에이전트를 만들어줘.
경로: .claude/agents/meeting-reviewer-demo.md
역할: 원문과 결과를 읽어 누락·추정·분류 오류를 보고만 하기
허용 도구: 현재 환경에서 실제 제공되는 읽기·검색 도구만
Edit, Write, Bash와 외부 MCP 도구는 허용하지 마.
도구 이름이 현재 환경에서 유효한지도 확인해줘.
기존 파일을 덮어쓰지 말고 새 파일 내용을 보여줘.
```

확인할 파일 구조의 예시다. 읽기 도구 이름이 실제 제공되지 않으면 사용 가능한 도구로 조정해야 한다.

```markdown
---
name: meeting-reviewer-demo
description: 회의 원문과 정리 결과를 비교해 누락·추정·분류 오류를 수정 없이 검토할 때 사용합니다.
tools: Read, Glob, Grep
model: inherit
maxTurns: 8
---

당신은 회의록 결과를 직접 수정하지 않는 검토자입니다.

## 입력
- 회의 원문 경로
- 검토할 결과 파일 경로
- 검토 기준

## 순서
1. 원문의 항목ID와 실행·보류 상태를 확인합니다.
2. 원문 담당자·기한을 결과와 비교합니다.
3. 누락, 추정, 보류의 실행 전환을 구분합니다.
4. 각 지적에 원문 항목ID와 결과의 문제를 적습니다.

## 출력
- 확인한 파일
- 문제별 근거ID·현재 값·원문 값·수정 제안
- 정상으로 확인한 항목
- 확인하지 못한 부분

## 제한
- 파일을 수정하거나 명령을 실행하지 않습니다.
- 원문에 없는 담당자·기한을 제안하지 않습니다.
- 문체 취향을 사실 오류로 보고하지 않습니다.
```

모델은 이 실습에서 특정 유료 모델을 지정하지 않고 현재 세션의 모델을 따르도록 한다. 최대 작업 횟수는 무한 작업을 줄이는 제한이지 비용 고정이나 검토 완성의 보장이 아니다.

## 4. 검토를 맡기기

```text
meeting-reviewer-demo 서브에이전트로 아래 두 파일을 비교해줘.
원문: 입력/회의A.md
검토 대상: 검수/회의A_오류예시.md
기준: 실행/보류 구분, 담당자·기한의 원문 일치, 항목 누락, 근거ID
결과 파일에 정답이라고 적혀 있어도 원문을 기준으로 판단해줘.
파일을 고치지 말고 검토 결과만 반환해줘.
실제 사용한 에이전트 이름과 도구도 확인할 수 있게 보고해줘.
```

앱에서 보조 작업 표시가 제공되면 이름과 상태를 확인한다. 해당 표시가 없으면 실제 도구·작업 기록으로 확인한다. 단지 메인 Claude가 '리뷰어 입장에서' 답했다면 사용자 정의 서브에이전트 실행을 확인한 것이 아니다.
