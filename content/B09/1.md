# B09. 배포 링크로 공유하기

<div class="tldr"><b>3줄요약</b>

1. **배포 = 내 컴에서 만든 걸 24시간 켜진 남의 컴(서버)에 올려서 링크로 쓰게 하는 것**
2. 첫 배포는 **Vercel·Netlify** 같은 호스팅에 올리면 끝. 서버 직접 안 만져도 됨
3. **연습장(개발)과 본장부(운영)를 나눠라.** 실험하다 진짜 데이터 날리면 답 없음

</div>

## 1. "내 컴에선 되는데"가 생기는 이유

| 내 컴엔 있고 남 컴엔 없는 것 | 해결 |
|---|---|
| 내가 깐 프로그램·라이브러리 | 필요한 목록을 파일로 (AI가 만들어줌) |
| `.env` 비밀값 | 호스팅 서비스 환경변수 설정에 따로 입력 |
| `C:\Users\나\...` 내 경로 | 상대경로로 (A4) |
| 샘플 데이터 파일 | 배포 대상에서 빼기 |

> AI한테: **"다른 사람 컴에서도 실행되게 정리해줘. 실행 방법을 README에 써줘"**

## 2. 배포 방법 고르기

| 앱 종류 | 추천 | 난이도 |
|---|---|---|
| HTML 파일 하나 (B5) | **Vercel / Netlify / GitHub Pages** | ⭐ |
| 화면 + 간단한 서버 | **Vercel** | ⭐⭐ |
| 화면 + 서버 + DB | Vercel + 관리형 DB 서비스 | ⭐⭐⭐ |
| 회사 내부용 | **IT팀이랑 상의** | 상황별 |

### 흐름

```
GitHub에 푸시(A9) → 호스팅에 GitHub 연결 → 자동 배포 → https://내앱.vercel.app
```

이후엔 **푸시할 때마다 자동 재배포.**

> AI한테: "이 앱 Vercel에 배포하고 싶어. 처음이야. 단계별로, 내가 직접 클릭해야 하는 건 따로 표시해줘."

## 3. 환경 분리 = 연습장과 본장부

| 환경 | 누가 | 데이터 |
|---|---|---|
| **개발 (로컬)** | 나 | 가짜 |
| **검증 (미리보기)** | 나 + 친구 몇 명 | 가짜 or 마스킹 |
| **운영** | 실제 사용자 | **진짜** |

Vercel은 브랜치마다 **미리보기 링크**를 줌 → 거기서 확인하고 main에 합치면 운영 반영.
