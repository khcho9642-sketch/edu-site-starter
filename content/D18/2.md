## 4. 주의 사항

- main에 직접 푸시하는 습관을 들이지 않는다. 작은 변경이라도 PR로 연습한다.
- PR 설명에 개인정보·비밀값을 쓰지 않는다. PR은 저장소 접근자 모두가 본다.
- 머지는 되돌리기 번거롭다. **변경 파일을 읽은 뒤** 누른다.
- 자동으로 머지되게 하는 설정은 연습 단계에서 켜지 않는다.

## 5. 이렇게는 쓰지 말자

| ❌ 이렇게 하지 말자 | ✅ 대신 이렇게 | 이유 |
|---|---|---|
| "main에 바로 올려" | "새 브랜치에서 하고 PR 만들어줘" | 실수가 바로 본편에 들어간다 |
| PR을 열자마자 머지 | Files changed를 끝까지 읽고 머지 | 안 시킨 변경이 섞일 수 있다 |
| 충돌 나면 "내 거로 다 덮어" | 양쪽 비교 설명 → 내가 선택 | 다른 사람(또는 다른 세션)의 작업이 사라진다 |
| PR 설명 비우기 | 무엇을·왜·어떻게 확인했는지 | 나중에 왜 바꿨는지 아무도 모른다 |

## 6. 확인 방법과 막혔을 때

- 머지 후 main의 README에 합계 표가 보이는지 GitHub 웹에서 확인한다.
- T004가 0원으로 바뀌지 않았는지 확인한다.
- PR 만들기가 막히면 어떤 문구가 떴는지 Claude에게 전달하고, 공식 PR 안내를 따른다.
