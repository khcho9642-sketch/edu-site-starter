## 5. 주의 사항

- 실제 비밀키·실제 카드내역·회사 자료로 사고 연습을 하지 않는다.
- 사고 화면을 캡처할 때 키 값·계정명·다른 저장소 이름을 가린다.
- Claude가 강제 푸시나 기록 덮어쓰기를 제안하면 **이유와 영향 범위를 먼저 묻고**, 실행은 내가 판단한다.
- 회사 저장소라면 기술적으로 가능해도 **회사 보안 규정이 먼저**다.

## 6. 이렇게는 쓰지 말자

| ❌ 이렇게 하지 말자 | ✅ 대신 이렇게 | 이유 |
|---|---|---|
| 비밀키 커밋 → 파일만 지우고 끝 | 키 폐기·재발급부터 | 기록과 복사본에 남아 있다 |
| "깔끔하게 force push로 정리해" | 영향 범위 설명 → 내가 판단 | 다른 사람 작업이 사라질 수 있다 |
| 처음 보는 사람을 관리자 권한으로 초대 | 최소 권한, 끝나면 정리 | 저장소 삭제·설정 변경까지 가능해진다 |
| 오래된 Private 저장소를 점검 없이 Public 전환 | 기록의 비밀값·개인정보 점검 후 결정 | 과거 커밋까지 전부 공개된다 |
| 보안 알림 메일 무시 | 알림 내용 확인 → 위 2절 순서 | 이미 노출된 상태일 수 있다 |

## 7. 확인 방법과 막혔을 때

아래 점검표를 내 연습 저장소에 대해 채운다.

```
[ ] 공개 범위가 Private이다
[ ] .gitignore에 .env와 개인 자료 폴더가 있다
[ ] GitHub 웹에서 .env가 보이지 않는다
[ ] 협업자 목록에 모르는 사람이 없다
[ ] 협업자 권한이 필요한 만큼만이다
[ ] 비밀키를 올렸을 때의 대응 순서를 말할 수 있다
```

판단이 어려운 사고(실제 키 노출, 회사 자료 노출)는 혼자 처리하지 말고 서비스 공식 안내와 담당자에게 알린다.

## 화면 보며 따라 하기

**준비:** 가짜 키 시나리오와 안전 점검표를 준비합니다.

[공통 실습 파일 ZIP 받기](/materials/walkthrough/cd-practice-starter.zip) · ZIP을 모두 푼 뒤 00_먼저읽기.md부터 확인합니다.

**내 화면에서:** 그림은 가짜 파일을 사용한 로컬 Git 점검 결과입니다. GitHub의 보안 설정 변경 화면이 아닙니다.

1. 실제 키를 쓰지 않고 노출 가정 → 폐기·재발급 → 보관·추적 점검 → 기록 대응 순서를 적습니다.
2. .gitignore에 적힌 것과 이미 추적 중인 것을 구분합니다. 아직 복제하지 않았다면 해당 항목은 미실습으로 남깁니다.
3. 개인 비공개 저장소의 협업자 권한과 조직 역할을 구분합니다. 실제 초대·공개 전환·강제 푸시는 하지 않아도 됩니다.

**완료 확인**

- 키 파일 삭제만으로 노출 대응이 끝나지 않음
- 커밋 예정 목록에 .env·개인자료가 없음

**막혔을 때:** 화면 캡처에 실제 키나 다른 저장소 이름이 보이면 공유하지 않습니다. 연습 점검표에 미실습이 있어도 사실대로 남기고 17강 뒤 다시 확인합니다.

![따라 하기 화면](/materials/walkthrough/screens/git-check.png)

**이번 검토에서 확인한 범위:** 격리된 가짜 Git 예제에서 제외 규칙·추적 목록을 시험했습니다. 실제 키 발급·폐기·협업자 권한 변경은 수행하지 않았습니다.
