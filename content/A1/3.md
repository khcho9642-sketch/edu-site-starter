## HTML·CSS·JavaScript의 역할

웹 화면의 구조와 모양과 동작은 서로 연결되지만 역할이 다릅니다. 같은 입력창을 두고 어떤 변경을 하려는지에 따라 수정할 부분이 달라집니다.

| 구성 | 하는 일 | 변경 예시 |
| --- | --- | --- |
| HTML | 내용의 의미와 구조를 표현 | 제목 입력창·설명·저장 버튼 추가 |
| CSS | 크기·색·간격·배치를 표현 | 입력창 너비 조절·오류 강조 |
| JavaScript | 이벤트 처리와 데이터 변경 | 빈 제목 검사·저장 요청·결과 표시 |
| DOM | 브라우저가 문서를 객체 구조로 다룸 | 스크립트가 화면 요소를 찾아 변경 |

간단한 HTML 구조 예시:

```html
<label for="title">Title</label>
<input id="title" name="title">
<button type="button">Save</button>
```

label은 입력 항목의 이름을 연결하고, input은 값을 받으며, button은 행동의 시작점을 제공합니다. 이 구조만으로 DB에 저장되지는 않습니다. 실제 저장 기능과 성공·실패 처리는 추가로 연결해야 합니다.

<div class="note"><b>화면에서 되는 것과 저장은 다르다</b>
<p>버튼을 눌렀을 때 글자가 바뀌어도 DB에 저장됐다는 증거는 아닙니다. 새로고침 후 다시 조회하거나 서버의 응답과 저장 기록을 함께 확인합니다.</p></div>

<div class="tryit"><b>직접 해보기</b>
<p>“버튼을 둥글게”, “제목 입력칸 추가”, “저장 요청 보내기”를 세 역할에 연결하세요.</p>
<details><summary>예시 답 · 판단 기준</summary><p>둥근 모양은 CSS, 입력칸의 구조는 HTML, 요청을 보내는 동작은 JavaScript가 담당할 수 있습니다.</p></details></div>

## 코드를 읽기 위한 최소 개념

처음부터 긴 코드를 작성할 필요는 없습니다. 입력값이 어디에 담기고, 어떤 조건으로 나뉘며, 무엇을 돌려주는지 읽을 수 있으면 AI의 설명을 검토하기 쉬워집니다.

| 개념 | 쉽게 읽는 방법 |
| --- | --- |
| 변수·자료형 | 값에 이름을 붙입니다. 문자열·숫자·참/거짓을 구분합니다. |
| 배열·객체 | 여러 값을 목록으로 담거나, 관련 항목을 이름과 값으로 묶습니다. |
| 조건문 | 조건이 참인지에 따라 실행할 일을 나눕니다. |
| 반복문 | 목록의 각 항목 등에 같은 처리를 반복합니다. |
| 함수·인자·반환값 | 처리를 이름으로 묶고 입력을 받아 결과를 돌려줍니다. |
| 오류 | 기대하지 않은 입력·상태·실행 조건으로 처리를 끝내지 못할 수 있습니다. |

JavaScript로 저장 가능 여부만 판단하는 예시:

```js
function canSave(title) {
  if (typeof title !== "string") return false;
  return title.trim().length > 0;
}
const titles = ["Draft", " "];
for (const title of titles) {
  console.log(canSave(title));
}
```

<div class="note"><b>코드의 범위</b>
<p>결과는 true, false 순서입니다. 공백만 있는 제목을 거르지만 권한 확인이나 DB 저장은 수행하지 않습니다. 함수 이름에 save가 있어도 실제로 무엇을 하는지 내용을 확인합니다.</p></div>

<div class="tryit"><b>직접 해보기</b>
<p>이 코드에 숫자 123을 입력하면 어떤 결과가 나오는지 설명하세요.</p>
<details><summary>예시 답 · 판단 기준</summary><p>문자열이 아니므로 false를 반환합니다. 잘못된 자료형에서 trim을 바로 호출하지 않도록 먼저 확인합니다.</p></details></div>

## 화면을 컴포넌트로 나누기

컴포넌트는 입력창이나 카드처럼 재사용할 수 있도록 나눈 화면 단위입니다. 무엇을 입력받고 어떤 행동을 알려줄지 정하면, 여러 화면에서 같은 규칙을 유지하기 쉽습니다.

| 컴포넌트 | 받는 정보·책임 |
| --- | --- |
| 상단 메뉴 | 현재 메뉴·사용자 표시. 사용자가 선택한 메뉴를 알립니다. |
| 제목 입력 | 현재 제목·필수 여부·오류 문구를 받아 입력을 표시합니다. |
| 본문 편집 | 본문 값과 변경 내용을 다룹니다. |
| 저장 버튼 | 저장 가능 여부·처리 중 여부를 받아 클릭을 알립니다. |
| 저장 결과 | 저장 시각·결과·오류 내용을 표시합니다. |
| 게시글 카드 | 글 제목·상태·수정 시각을 목록에서 반복 표시합니다. |

### 입력과 행동의 계약

컴포넌트에 전달하는 값을 흔히 props라고 부릅니다. 같은 버튼이라도 글자와 사용 가능 여부를 전달해 다르게 표시할 수 있습니다. 입력 내용이 바뀌면 상위 화면에 변경 사실을 전달하고, 어디에서 값을 관리할지도 정합니다.

<div class="note"><b>나누는 기준</b>
<p>모든 문장을 별도 컴포넌트로 만들 필요는 없습니다. 반복되는 기능, 독립적인 책임, 함께 바뀌는 요소를 기준으로 나눕니다. 여러 곳에 복사한 입력 검증이 서로 달라지는 문제부터 줄여 봅니다.</p></div>

<div class="tryit"><b>직접 해보기</b>
<p>자료 제출 화면의 반복 요소 세 가지를 고르고, 각 요소에 전달할 값을 적으세요.</p>
<details><summary>예시 답 · 판단 기준</summary><p>예: 파일 항목(파일명·크기·상태), 기한 표시(기한·시간대), 제출 버튼(권한·처리 중 여부).</p></details></div>

## 상태와 이벤트로 화면의 변화를 읽기

상태는 화면이 현재 기억하는 값이고, 이벤트는 상태를 바꾸게 하는 사건입니다. 버튼이 있다는 사실보다 어떤 사건에 어떤 값이 바뀌는지 정하는 것이 중요합니다.

| 현재 상태 | 발생한 사건 | 바뀌는 내용 |
| --- | --- | --- |
| 입력 전 | 제목 입력 | 제목 값과 미저장 여부가 바뀜 |
| 입력 중 | 저장 클릭 | 입력을 확인하고 저장 중 상태로 전환 |
| 저장 중 | 성공 응답 | 저장 시각·글 ID 갱신, 성공 표시 |
| 저장 중 | 오류 응답 | 오류 문구 표시, 입력 내용은 유지 |
| 저장 완료 | 본문 수정 | 미저장 변경이 있다는 표시 |
| 미저장 변경 있음 | 다른 화면으로 이동 | 변경을 잃을 수 있음을 알려 선택하게 함 |

### 값의 주인을 정하기

제목을 두 컴포넌트가 따로 저장하면 한쪽만 바뀔 수 있습니다. 같은 사실은 기준이 되는 상태를 정하고 필요한 화면에 전달합니다. 글자 수처럼 제목에서 계산할 수 있는 값은 별도로 중복 보관할 필요가 있는지 먼저 검토합니다.

<div class="note"><b>화면 상태와 업무 상태 구분</b>
<p>저장 중·오류 표시 등은 화면 처리 상태입니다. 초안·승인·발행 완료 등은 업무 상태입니다. 화면에서 “완료”라고 표시했다고 업무 기록도 완료로 확정되는 것은 아닙니다.</p></div>

<div class="tryit"><b>직접 해보기</b>
<p>저장 실패 후 제목과 본문을 지워 버리는 화면에 어떤 문제가 있는지 적으세요.</p>
<details><summary>예시 답 · 판단 기준</summary><p>사용자가 작성한 내용을 잃습니다. 입력은 유지하고 실패 이유와 재시도 또는 상태 확인 방법을 알려야 합니다.</p></details></div>

## 폼과 입력 규칙 설계하기

폼은 여러 입력 항목을 묶어 한 가지 작업을 완료하게 하는 구조입니다. 필수값을 검사하는 것뿐 아니라 안내·오류 위치·입력 유지·서버 재검증까지 함께 설계합니다.

| 항목 | 규칙 | 화면 반응 |
| --- | --- | --- |
| 제목 | 공백만 있는 값 금지. 예제 최대 100자 | 항목 아래에 이유 표시 |
| 본문 | 작성 중인 값을 유지 | 저장 실패해도 입력 보존 |
| 예약 시각 | 선택한 시간대를 함께 표시 | 과거 시각이면 수정 안내 |
| 작성자 | 인증된 사용자와 서버에서 연결 | 임의 사용자 번호 입력칸은 두지 않음 |
| 저장 행동 | 처리 중에는 중복 클릭을 줄임 | 처리 중 표시와 완료 결과 제공 |

### 입력 검증의 세 층

**형식 검사**는 문자·날짜 등 자료형과 형태를 확인합니다. **범위 검사**는 길이·시각 등의 허용 범위를 확인합니다. **업무 규칙 검사**는 이 사용자가 이 상태에서 저장하거나 예약해도 되는지 판단합니다. 화면의 빠른 안내와 서버의 최종 검증이 함께 필요합니다.

<div class="note"><b>오류 문구를 구체적으로</b>
<p>“오류입니다”보다 “제목을 입력해 주세요. 공백만으로는 저장할 수 없습니다”가 다음 행동을 알려줍니다. 입력값을 자동으로 바꾼다면 바뀐 내용과 규칙도 사용자가 알 수 있어야 합니다.</p></div>
