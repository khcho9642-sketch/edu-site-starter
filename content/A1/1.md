## 버튼 뒤의 구조를 이해하기

이 강의는 개발을 처음 배우는 사람도 **화면에서 입력한 내용이 어디서 처리되고 저장되는지** 설명할 수 있도록 돕습니다. 프론트엔드·백엔드·클라이언트·서버를 구분하고, 작은 화면 하나를 설계해 봅니다.

설명을 읽고 채워진 예시를 살펴본 뒤, 종이나 문서에 자신의 화면을 그려 보세요. 지금은 특정 도구를 설치하지 않아도 됩니다. 모르는 단어는 기능 이름보다 그 **역할**을 먼저 확인합니다.

<div class="note"><b>이 강의에서 완성할 것</b>
<p>① 화면·처리·저장 역할표 ② 화면 초안과 입력 규칙 ③ 로딩·실패를 포함한 화면 상태표 ④ 내 업무에 적용한 작은 화면 설계</p></div>

### 시리즈에서의 위치

기존 개발 01~09권(이 사이트의 B과정)은 일을 진행하는 과정이고, 기초편은 그 과정에서 만나는 구성요소를 이해하는 보충 교재입니다. 이어지는 A2에서는 데이터와 ERD, A3에서는 API와 자동화를 다룹니다. 예제는 가상 자료와 모의 발행만 사용합니다.

## 한 가지 앱으로 끝까지 연결하기

우리는 게시글을 작성하고 저장한 뒤, 정한 시각에 모의 발행하는 작은 앱을 생각합니다. 화면만 예쁘게 만드는 데서 끝내지 않고 **입력·처리·저장·결과 확인**을 하나로 연결합니다.

| 항목 | 교육용 설정 |
| --- | --- |
| 사용자 | 가상 사용자 1과 2. 각자 자기 글을 관리합니다. |
| 기본 행동 | 글 작성 → 초안 저장 → 다시 열기 → 수정 → 예약 |
| 다룰 정보 | 제목·본문·예약 시각. 초안 저장과 예약 확정의 필수 항목은 단계별로 구분합니다. 작성자는 인증된 사용자와 연결합니다. |
| 교육 범위 | 외부 서비스에 실제 게시하지 않고 모의 발행 결과만 기록합니다. |
| 핵심 규칙 | 빈 제목은 저장할 수 없고, 글 하나의 활성 예약은 동시에 최대 한 개입니다. |
| 완료 확인 | 저장 후 목록에서 같은 글을 다시 열어 제목과 본문이 유지되는지 확인합니다. |

### 학습의 기준

코드를 외워야 다음으로 갈 수 있는 것은 아닙니다. 사용자의 행동, 프로그램의 처리, 보관할 데이터, 확인할 결과를 자신의 말로 설명하면 됩니다. 확정되지 않은 항목은 가정이라고 표시합니다.
