## [강좌] D18. 브랜치와 PR — 본편 안 건드리고 실험하기

> Codex 앱 선택 심화 · Windows 중심 · 공식 확인: 2026-11-14
> 먼저 읽을 강의: D17.

## 3줄요약

1. 실험은 **새 브랜치**에서 하고, main(본편)에는 **PR로 검토한 뒤** 합친다.
2. PR은 "이렇게 바꿀게요" 제안서다. **변경 내역(Files changed)을 읽고** 머지한다.
3. 충돌이 나면 한쪽을 통째로 덮지 말고 **양쪽을 비교한 설명**부터 받는다.

## 1. 준비와 오늘의 결과

D17에서 푸시한 `my-gagyebu-practice`를 쓴다. 오늘 결과는 **연습 PR 1개를 만들고, 변경 내역을 읽은 뒤 머지한 기록**이다.

## 2. 브랜치에서 작업하고 PR 만들기

1. Codex 앱에서 복제한 연습 프로젝트를 연다. Worktree를 선택했다면 현재 브랜치와 실제 작업 경로를 확인한다. 브랜치 생성과 변경 검수는 아래 공통 순서를 따른다.
2. 새 브랜치에서 작은 변경을 요청한다.

> main은 그대로 두고 새 브랜치 add-category-total을 만들어줘. 거기서 지출샘플.csv의 카테고리별 합계를 README에 표로 추가해줘. T004는 미확정으로 표시하고 0원으로 바꾸지 마.

3. 커밋과 푸시 후 PR을 요청한다.

> 이 브랜치를 푸시하고 main으로 가는 PR을 만들어줘. PR 설명에는 무엇을 바꿨는지, 어떻게 확인했는지, 미확정 항목을 적어줘.

4. GitHub 웹 → **Pull requests** 탭에서 방금 만든 PR을 연다.

## 3. PR 읽는 법과 머지

| PR 화면 영역(이름은 바뀔 수 있음) | 볼 것 |
|---|---|
| 설명(Conversation) | 무엇을, 왜, 어떻게 확인했는지 |
| 변경 파일(Files changed) | 빨간 줄 = 삭제, 초록 줄 = 추가. 안 시킨 파일이 바뀌었는지 |
| 체크(Checks) | 자동 검사 결과(D19) |
| 머지 버튼 | 위를 다 본 뒤에 누른다 |

- 변경 파일에 **요청하지 않은 파일**이 있으면 머지하지 말고 이유를 묻는다.
- 합계 숫자는 `지출샘플.csv`로 직접 계산해 대조한다. 확정 5건(T001·T002·T003·T005·T006) 합계 **28,000원**, T004는 미확정이어야 한다(D06와 같은 기준).

**충돌이 났을 때**

> 충돌이 났어. 양쪽 내용을 나란히 비교해서 설명해주고, 어떻게 합칠지 추천만 해줘. 내가 OK하기 전엔 고치지 마.
