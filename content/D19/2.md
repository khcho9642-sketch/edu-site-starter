## 4. 주의 사항

- 체크 실패를 **우회(검사 끄기·필수 검사 해제)**하지 않는다.
- 로그에 비밀값이 찍혀 있으면 캡처·공유하지 말고 C16의 대응을 따른다.
- 이슈·PR 내용은 저장소 접근자가 모두 본다. 개인정보를 쓰지 않는다.
- 자동 수정 기능을 쓰더라도 **결과 PR의 변경 파일은 사람이 읽는다.**

## 5. 이렇게는 쓰지 말자

| ❌ 이렇게 하지 말자 | ✅ 대신 이렇게 | 이유 |
|---|---|---|
| "체크 끄고 머지해" | 실패 원인부터 확인 | 고장 난 코드가 본편에 들어간다 |
| 로그 안 읽고 "고쳐줘"만 반복 | 핵심 에러 줄 + 계획부터 | 같은 실패를 계속 돌린다 |
| 테스트를 지워서 통과 | "테스트는 고치지 마" (B07) | 검사가 의미 없어진다 |
| 이슈 제목 "안 됨" | 무엇이·어디서·기대 결과 | 나중에 아무도 이해 못 한다 |

## 6. 확인 방법과 막혔을 때

- 이슈 화면에 연결된 PR이 표시되는지 본다.
- 머지 후 이슈 상태(열림/닫힘)를 확인한다.
- 체크 로그가 너무 길면 "에러가 처음 나온 줄 위아래 10줄"만 골라 Claude에게 준다(비밀값은 가린다).
