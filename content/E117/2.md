## 4. 주의 사항

- 커밋 전에 **포함 파일 목록**을 반드시 받는다.
- 토큰·비밀번호를 채팅에 붙여넣지 않는다. 인증은 GitHub가 띄우는 로그인 창에서 직접 한다.
- 원격 저장소가 **Private인지** 푸시 전에 한 번 더 본다.
- AI가 "푸시했습니다"라고 해도 **GitHub 웹에서 파일 목록**을 확인해야 완료다.

## 5. 이렇게는 쓰지 말자

| ❌ 이렇게 하지 말자 | ✅ 대신 이렇게 | 이유 |
|---|---|---|
| "전부 올려줘" | "올라갈 목록 먼저 보여줘" | 비밀 파일이 섞여도 모른다 |
| 커밋 메시지 "수정", "ㅇㅇ" | "제외 규칙 추가"처럼 무엇을 바꿨는지 | 나중에 되돌릴 지점을 못 찾는다 |
| 인증 에러가 나서 토큰을 채팅에 붙여넣기 | 로그인 창에서 직접 인증 | 토큰이 대화 기록에 남는다 |
| `.gitignore` 만들었다는 말만 믿기 | GitHub 웹에서 `.env`가 없는지 확인 | 이미 커밋된 파일은 나중에 제외해도 기록에 남는다 |
| 넓은 접근 모드로 확인 없이 한 번에 끝내기 | 현재 권한과 변경·실행 범위를 확인 | 무엇이 실행됐는지 놓친다 |

## 6. 확인 방법과 막혔을 때

- GitHub 웹 저장소 화면에 `README.md`, `지출샘플.csv`, `메모.md`, `.gitignore`가 보이고 **`.env`와 `개인자료/`는 없어야** 한다.
- `.env`가 이미 올라갔다면 D16의 사고 대응을 따른다. 파일만 지우고 끝내지 않는다.
- 인증이 계속 실패하면 어떤 화면이 떴는지(문구만) AI에게 말하고, 공식 인증 안내를 따른다. 브라우저 로그인과 Codex가 실행하는 Git 인증은 별개일 수 있다.
- 원격 기록과 다르다는 이유로 푸시가 거부되면 원격 변경부터 확인한다. 새 로컬 기록으로 강제 덮어쓰지 않는다. D15에서 만든 README가 있으므로 처음부터 복제하는 흐름을 따른다.

## 화면 보며 따라 하기

**준비:** README가 있는 연습 저장소 주소와 가짜 파일을 준비합니다.

[공통 실습 파일 ZIP 받기](/materials/walkthrough/cd-practice-starter.zip) · ZIP을 모두 푼 뒤 00_먼저읽기.md부터 확인합니다.

**내 화면에서:** Codex의 Local/Worktree 위치를 확인합니다. 파일 목록과 실제 인증 방식은 따로 봅니다.

1. 빈 폴더를 임의로 같은 원격에 연결하지 말고 원격 저장소부터 복제합니다. 이미 폴더가 있으면 상태만 먼저 확인합니다.
2. .gitignore를 만든 뒤 .env·개인자료의 추적 여부와 커밋 예정 파일 목록을 받습니다.
3. 목록을 확인한 뒤 커밋·푸시합니다. 원격에서 파일과 최신 기록을 다시 확인하고 실제 GitHub 푸시인지 로컬 원격 시험인지 구분합니다.

**완료 확인**

- 포함할 파일과 제외할 파일이 분리됨
- 비밀 파일 미포함·원격 파일 목록 직접 확인

**막혔을 때:** 푸시가 거부되면 원격 README와 로컬 기록 차이를 확인합니다. 강제 푸시를 먼저 쓰지 않습니다. 브라우저 로그인만으로 Git 인증이 끝난다고 가정하지 마세요.
