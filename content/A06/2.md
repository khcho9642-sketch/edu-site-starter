## 3. 관계: 1 대 N

```
가게 1곳 ──────< 지출 여러 건
 (S01)            (E001, E003, ...)
```

- 가게 1곳에 지출 **0건~여러 건**
- 지출 1건의 가게는 **정확히 1곳**

이걸 그림으로 그린 게 **ERD**. AI한테 "ERD 그려줘" 하면 그려줌.

### 다른 관계 예시

| 관계 | 예 |
|---|---|
| 1:1 | 사람 ↔ 주민등록증 |
| 1:N | 가게 → 지출들 |
| N:M | 학생 ↔ 수업 (중간에 "수강" 테이블 하나 끼움) |

## 4. 제약조건: DB가 알아서 막게

| 규칙 | 막는 것 |
|---|---|
| **NOT NULL** | 날짜 없는 지출 |
| **UNIQUE** | 같은 가게ID 두 번 등록 |
| **CHECK (금액 ≥ 0)** | 마이너스 금액 (환불은 따로) |
| **FK** | 없는 가게(S99)로 지출 등록 |

<div class="danger"><b>이거 모르면 큰일남</b>

- **이름을 키로 쓰지 마라.** 바뀌고, 겹치고, 오타 남
- 가게 지우면 그 가게 지출은 어떡함? → **지우기 전에 규칙 정해야 함** (같이 지움 / 못 지우게 막음)

</div>
