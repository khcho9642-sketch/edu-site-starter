## [강좌] D23. 훅 — 실행 전 차단과 실행 후 검사를 구분하자

> Codex 앱 선택 심화 · Windows 중심 · 공식 확인: 2026-11-14
> 먼저 읽을 강의: D03 · D14 · D22.

## 3줄요약

1. 훅은 정해진 이벤트가 생길 때 실행하는 검사다. 말로 주의하라고 하는 것과 다르다.
2. 실행 전 검사는 앞으로 할 작업을 막을 수 있지만, 실행 후 검사는 이미 한 작업을 되돌리지 않는다.
3. 가짜 파일에서 허용·차단·오류를 시험하고 원래 설정으로 돌리는 데까지가 실습이다.

## 1. 오늘의 목표

가짜 `normal-demo.md` 수정은 허용하고 `protected-demo.md` 수정은 거절하는 교육용 검사를 설계한다. 이번 Codex 예시는 **apply_patch 호출의 패치 헤더**만 다룬다. Claude의 Edit·Write `file_path` 입력을 그대로 쓰지 않는다.

| 이벤트 | 이번 구분 |
|---|---|
| PreToolUse | 실행 전에 해당 도구 호출을 검사 |
| PostToolUse | 이미 실행한 결과를 검사하며 자동 복구와 다름 |

검사 스크립트는 차단할 때 `hookSpecificOutput.permissionDecision: deny` JSON을 반환한다. 종료 코드가 0이어도 JSON이 차단을 뜻할 수 있다. 스크립트 실행 실패·시간 초과 때의 동작은 별도로 확인한다. 이 예시는 다른 도구·링크·명령·외부 시스템까지 보호하는 보안 경계가 아니다.

## 2. 준비물

1. D22의 로컬 연습 프로젝트와 [가짜 보호 파일](/chatgpt-materials/extensions)을 준비한다.
2. 제공한 [검사 예시](/materials/chatgpt/examples/hook_guard.py)와 [설정 초안](/materials/chatgpt/examples/hooks.example.json)을 먼저 읽는다. 예시 폴더에 있는 파일은 설치된 훅이 아니다.
3. 현재 Codex의 `.codex/hooks.json` 또는 `.codex/config.toml`에 이미 훅이 있는지, 정책과 프로젝트 신뢰가 허용하는지 확인한다. 둘을 중복 등록하지 않는다.
4. 백업·추가 범위·사용할 Python 실행 파일·현재 도구 입력 구조를 확인한 계획부터 받는다. 아직 설정은 바꾸지 않는다.

```text
연습 프로젝트에서만 Codex 훅을 검토하자.
현재 버전의 apply_patch PreToolUse 입력과 훅 설정을 공식 문서로 확인해줘.
기존 설정 유무, 추가 위치, 백업 계획, Python 실행 경로를 먼저 보고해줘.
실제 훅 등록·신뢰 승인·전역 설정 변경은 아직 하지 마.
```

## 3. 검사 파일 만들기

제공한 hook_guard.py는 입력 JSON의 `tool_name`과 `tool_input.command`를 읽는다. 패치의 Add File·Update File·Delete File·Move to 헤더를 모두 검사하고 보호 파일명이 들어 있으면 차단 JSON을 출력한다. 여러 파일 패치 중 하나라도 보호 파일이면 거절한다.

잘못된 JSON·빠진 command·인식하지 못한 헤더 입력도 거절한다. 전체 입력이나 원문 비밀값을 로그로 출력하지 않는다. 이름 비교만 하는 예시라 링크·별칭·다른 경로 표현까지 보장하지 않는다.

```text
예시 검사 파일을 연습 프로젝트의 별도 경로에 복사할 계획을 보여줘.
파일 내용을 먼저 검토하고, 실제 도구 호출 전에 가짜 이벤트만 시험해줘.
기존 파일을 덮어쓰거나 훅에 연결하지 마.
```

## 4. 설정을 연결하기 전에 무해하게 시험하기

아래는 가짜 이벤트를 프로그램에 입력하는 시험이다. 실제 파일을 수정하는 것이 아니다.

| 가짜 입력 | 기대 판정 |
|---|---|
| apply_patch, normal-demo.md 수정 헤더 | 차단 없음 |
| apply_patch, protected-demo.md 수정 | deny |
| 여러 파일 중 하나가 보호 파일 | deny |
| Move to로 보호 이름 지정 | deny |
| command 없음·잘못된 JSON | deny |

```text
검사 예시에 가짜 이벤트만 넣어 반환 JSON과 종료 코드를 표로 적어줘.
실제 apply_patch로 파일을 바꾸지는 마.
종료0을 무조건 허용으로 보지 말고 permissionDecision도 읽어줘.
프로그램 시작 실패나 시간 초과를 아직 시험하지 않았다면 미확인으로 써줘.
```

이 교안 제작 단계에서는 오프라인 입력 검사를 수행할 수 있다. 실제 Codex 훅 호출을 검증한 기록과 혼동하지 않는다.
