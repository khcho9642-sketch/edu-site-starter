## 5. 기존 설정에 추가하고 실제 호출 확인하기

오프라인 결과가 맞고 실제 설치를 선택한 학습자만 진행한다. 공식 형식의 `PreToolUse`에 `matcher: ^apply_patch$`와 동기식 command 검사를 연결하는 계획을 검토한다. 예시 JSON의 실행 경로는 교체 전에는 사용할 수 없다.

현재 프로젝트의 절대 위치·공백 경로·실제 Python 실행 파일·기존 항목을 확인한다. 프로젝트 신뢰와 비관리 훅의 정확한 정의에 대한 검토·신뢰 상태도 확인한다. 새 버전의 미지원 설정을 추측해 넣지 않는다.

```text
검토한 연습 훅만 기존 항목을 유지하며 추가해줘.
현재 Codex의 공식 지원 형식으로 실제 경로를 넣어줘.
정의와 실행 범위를 먼저 보여주고 필요한 신뢰 검토는 내가 확인할게.
활성 상태·실제 호출 결과와 해제 방법을 확인할 수 있게 해줘.
```

일반 파일 수정과 보호 파일 수정 요청을 각각 한 번 한다. 보호 파일 요청에는 “훅이 차단하면 멈추고 다른 도구·이름 변경으로 우회하지 마”를 붙인다. 실제 도구 호출과 deny 응답, 보호 파일 내용 동일을 모두 확인한다. 자발적 거절만 있으면 훅 실증은 미수행이다.

## 6. 예상 결과와 검수

| 구분 | 증거 |
|---|---|
| 오프라인 허용·거부 | 입력별 반환 JSON과 종료 코드 |
| 실제 훅 허용 | 호출 기록과 일반 파일 수정 결과 |
| 실제 훅 거부 | 훅 실행·deny 표시와 보호 파일 내용 동일 |
| 설정 보존 | 이번 항목 외의 변경이 없는 diff |
| 실행 실패·시간 초과 | 실제 시험하지 않았으면 미확인 |

스크립트 내부 예외 처리는 Python 실행 파일을 찾지 못하는 문제까지 잡아주지 않는다. 이벤트·실행 환경·오류 처리에 따라 실제 효과를 검증한다. 제작 단계의 검수 기록에는 훅을 설치·활성화하지 않았다는 사실을 남긴다.

## 7. 해제와 복구

실제 등록한 경우에만 이번 훅 항목을 제거하고 차이를 확인한다. 다른 작업이 설정을 바꿨다면 과거 백업을 통째로 덮어쓰지 않는다. 해제 후의 무해한 동작을 확인한다.

기능이나 정책 때문에 설치하지 않았다면 설정 설계와 가짜 입력 시험까지만 완료한 것으로 기록한다. 실제 수정·차단·복구를 했다고 쓰지 않는다. 원래 원고의 허용/거부/오류/실행 실패 검수 목표는 유지한다.
