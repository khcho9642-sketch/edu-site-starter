## 5. 같은 자료와 다른 자료에 적용하기

Code의 입력창에 `/meeting-actions`를 입력해 목록에 나타나는지 확인한다. 보이면 입력 경로를 이어 쓴다.

```text
/meeting-actions 입력/회의A.md
```

이어서 회의 B에도 적용한다.

```text
/meeting-actions 입력/회의B.md
```

명령 목록이 보이지 않으면 폴더 선택·파일 이름·현재 세션의 스킬 지원을 확인한다. 필요하면 같은 폴더에서 새 세션을 시작한다. 여전히 호출할 수 없으면 SKILL.md를 첨부해서 절차대로 처리할 수 있지만, 결과 기록에는 **'절차 파일 첨부로 실행, 스킬 호출 미확인'**이라고 쓴다.

## 6. 예상 결과와 검수

| 검수 항목 | 회의 A | 회의 B |
|---|---:|---:|
| 실행할 일 | 3개 | 2개 |
| 실행할 일 중 담당자 미정 | 1개 | 0개 |
| 실행할 일 중 기한 미정 | 1개 | 1개 |
| 보류 | 1개 | 1개 |

`출력/스킬_검수.md`에 입력 경로, 스킬 경로, 호출 확인 여부, 예상값과 실제값을 적는다. 수동 결과와 스킬 결과의 문장이 달라도 괜찮다. 분류·건수·근거가 같아야 한다.

## 7. 막혔을 때

| 증상 | 먼저 확인할 것 |
|---|---|
| 스킬을 못 찾음 | Code에서 선택한 폴더 아래에 `.claude/skills/meeting-actions/SKILL.md`가 있는지 |
| 다른 회의 결과가 섞임 | 호출할 때 입력 경로를 정확히 줬는지 |
| 보류 업무를 실행 업무로 넣음 | 분류 규칙과 원문 항목ID를 다시 비교 |
| 기한을 임의로 채움 | '미정으로 표시' 규칙과 실패 사례를 스킬에 보완 |
| 저장했다고 하는데 파일이 없음 | 변경 목록과 탐색기에서 실제 파일 확인 |

반복이 확실해진 뒤 예시 파일과 변경 이력을 추가한다. 한 번 쓸 일을 억지로 스킬로 만들 필요는 없다. 프로젝트 설정을 GitHub에 공유할 때는 입력 자료와 비밀값이 섞이지 않았는지도 확인한다.

1. 수동으로 회의 A를 정리해 실행 3개·보류 1개를 먼저 확인합니다.

3. 실제 호출이 확인된 경우에만 스킬 사용으로 기록합니다. 목록에 없으면 절차 파일 첨부로 A·B를 처리하고 수행 경로를 적습니다.

- 회의 A: 실행 3 / 담당 미정 1 / 기한 미정 1 / 보류 1

### 실제로 막힌 지점과 해결

스킬만 선택해 보내면 회의 원문이 없다는 안내가 나왔습니다. 스킬은 절차를 담고 있으므로, 선택한 뒤 회의 A·B의 원문도 입력하거나 첨부해야 합니다. 여러 줄 입력은 붙여넣기로 하고 **메시지 보내기는 마지막에 한 번만** 누릅니다.

이번 교육용 회의 스킬 이름은 `edu-meeting-actions-demo`입니다. 화면은 회의 예제로 등록·선택·결과 검수를 보여주며, 지출 스킬 자체의 등록 결과라고 바꾸어 읽지 않습니다.
