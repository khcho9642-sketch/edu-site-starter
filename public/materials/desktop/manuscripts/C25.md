# [강좌] C25. MCP·커넥터 — 연결하고, 범위를 확인하고, 끊는 데까지

> Claude Desktop 앱의 연결 설정과 **Code 로컬 프로젝트** 비교 · Windows 중심  
> 공식 문서 확인: 2026-11-14  
> 먼저 읽을 강의: C08 · C12 · C14 · C24.  
> 원안: 사용자가 제공한 확장 기능 4부작의 MCP·커넥터 단원과 플러그인 부록을 보완했습니다.

## 3줄요약

1. 커넥터는 서비스를 연결해 쓰는 기능이고 MCP는 이런 연결에 쓰이는 표준이다. 서로 완전히 별개인 기술로 외우지 않는다.
2. 같은 앱이어도 Chat·Cowork·Code, 로컬·클라우드에 따라 연결과 설정 적용 범위가 다를 수 있다.
3. 조회·초안·등록·발송을 구분하고, 연결 해제와 제공자 측 인증 폐기도 확인한다.

## 1. 외부 연결이 필요한 순간

파일을 첨부하면 그 시점의 복사본을 읽는다. 외부 서비스 연결은 권한이 허용하는 실제 서비스의 데이터를 조회하거나 변경할 수 있다. 편한 만큼 **어떤 계정에서 무엇을 할 수 있는지**를 알아야 한다.

| 필요한 일 | 먼저 고를 방법 |
|---|---|
| 가짜 회의 메모 한 번 요약 | 파일 첨부 |
| 계정의 문서 검색 | 제공되는 커넥터의 검색 도구 |
| 사내 조회 도구 연동 | 조직이 허용한 MCP 서버 |
| 회의록 절차 재사용 | C22의 스킬 |
| 기능 묶음 설치·공유 | 출처·권한을 확인한 플러그인 |

연결 수를 늘리는 것이 목표가 아니다. 필요한 업무 하나가 정확하게 되는지 확인한다.

## 2. 계정 없이 가능한 기본 실습

외부 계정 연결은 선택이다. 먼저 [공통 샘플](실습자료/07_확장기능_공통샘플.md)의 **가짜 연결 목록과 문서 조회 결과**를 Code에 전달한다.

```text
첨부한 가짜 연결 목록으로 권한 설계 연습을 하자.
실제 서비스에 연결하거나 인증 창을 열지 마.
업무는 교육 일정 문서 한 건을 조회하고 요약하는 것뿐이야.
연결별로 필요한 도구와 필요하지 않은 도구를 구분해줘.
서비스 토큰이나 계정 비밀번호를 요청하지 마.
결과를 출력/연결_권한설계.md에 저장해줘.
```

예상 설계는 `docs.search`, `docs.read`만 사용하는 것이다. `mail.send`, `calendar.create`, `db.execute`는 오늘 업무에 필요하지 않다. 가짜 목록에서 사용하지 않기로 정한 것은 **설계 결과**다. 실제 서비스 권한을 변경한 것이 아니다.

## 3. 실제 연결 전 화면 확인

선택 실습을 하려면 개인 연습 계정과 가짜 자료를 사용한다. 현재 앱에 보이는 **Plugins 또는 이전 Customize / Connectors** 등 연결 관리 화면을 확인한다. 없는 메뉴를 따라 찾느라 시간을 쓰지 말고 공식 안내와 계정·조직 지원을 먼저 본다.

다음을 기록한다.

| 확인할 것 | 기록 예시 |
|---|---|
| 지금 작업하는 화면 | Desktop Code, 로컬 프로젝트 |
| 연결 대상·계정 | 개인 연습 문서 서비스·계정 일부 가림 |
| 인증 범위 | 문서 검색·읽기 등 실제 동의 화면 내용 |
| 제공 도구 | 검색·조회·작성·삭제 도구 존재 여부 |
| 승인 방식 | 읽기 요청과 쓰기 요청의 확인 방식 |
| 해제 위치 | 앱의 연결 관리 + 제공자 계정의 앱 접근 관리 |

인증 동의 화면의 범위가 필요한 것보다 넓으면 연결을 중단하고 기본 실습으로 돌아가도 된다. '읽기만 해'라는 요청은 토큰 자체를 읽기 전용으로 바꾸지 않는다.

## 4. 실제로 연결하는 선택 실습

1. 제공자와 조직이 안내하는 공식 연결 방법을 선택한다.
2. 지원되는 계정·연결 관리 화면에서 서비스를 추가한다.
3. 로그인 도메인, 계정, 권한 목록을 직접 확인한다. 비밀번호·인증 코드는 대화창에 붙여 넣지 않는다.
4. 현재 Code 세션에서 해당 연결을 사용할 수 있는지 실제 도구 목록이나 상태로 확인한다.
5. 가짜 문서 한 건을 검색·읽기만 한다.
6. 사용한 도구·접근한 문서·변경 유무를 기록한다.

```text
연결된 연습 문서 서비스에서 '교육 일정 연습' 문서 한 건만 찾아줘.
검색과 읽기만 사용해줘. 문서 작성·수정·공유·메일 발송은 하지 마.
문서 제목, 수업 수, 총 교육시간, 출처를 정리해줘.
실제 조회 도구가 없으면 추정하지 말고 연결 확인 불가라고 말해줘.
```

기본 실습의 가짜 문서 기준은 **수업 2개, 총 90분**이다. 실제 계정에서는 같은 샘플을 연습 문서로 준비한 경우에만 이 값을 기대한다. 다른 실제 문서를 읽었는데 90분을 정답으로 맞추면 안 된다.

## 5. MCP 설정 파일은 어떤 때 보는가

화면에서 연결할 수 없는 조직 승인 서버를 쓰는 경우 Code의 프로젝트 `.mcp.json` 같은 설정이 필요할 수 있다. 서버 주소·인증 방식·사용 범위는 제공자의 공식 안내로 확인한다. 임의 패키지를 자동 설치하는 명령을 복사해 실행하지 않는다.

```text
조직이 허용한 이 MCP 서버의 공식 설정 문서를 읽고,
현재 Desktop Code 로컬 프로젝트에 적용할 수 있는지 확인해줘.
프로젝트 공유 설정과 개인 인증을 구분한 계획을 먼저 보여줘.
기존 .mcp.json이 있으면 유지하고, 실제 비밀값은 파일에 넣지 마.
지금은 설치·연결·인증·명령 실행을 하지 말고 계획만 작성해줘.
```

확인한 범위에 따라 설정을 추가한다. 프로젝트 공유용 파일에는 실제 API 키를 저장하지 않는다. 환경 변수나 제공되는 인증 관리 수단을 사용하되, Desktop 프로세스가 해당 값을 실제로 받는지도 확인한다. 값을 출력해서 확인하지 않는다.

앱과 CLI가 공유하는 Code 설정이 있어도, 모든 연결이 모든 화면에서 똑같이 나타난다고 가정하면 안 된다. 로컬·클라우드·SSH의 적용 범위도 따로 기록한다. 이번 기본 실습에는 터미널 명령 입력이 없다.

## 6. 서브에이전트의 외부 도구 권한

C24의 검토자는 로컬 파일만 읽으면 충분하다. 따라서 도구 목록을 읽기 도구로 제한하고 외부 연결은 주지 않는다.

`mcpServers`는 전용 서버를 정의하거나 사용할 서버를 지정하는 설정이지만, 그 목록만 보고 모든 상속 도구가 차단됐다고 판단하지 않는다. 필요한 경우 현재 버전의 `tools` 허용 목록 또는 `disallowedTools` 차단 목록으로 실제 도구 범위를 확인한다.

| 확인 | 잘못된 판단 | 확인할 증거 |
|---|---|---|
| 로컬 검토자 | 서버를 안 적었으니 외부 접근 불가 | 실제 허용 도구 목록 |
| DB 조사자 | DB 서버 하나만 적었으니 메일 접근 불가 | 상속·차단된 도구와 실제 호출 |
| 쓰기 제한 | '읽기만'이라고 했으니 토큰도 읽기 전용 | 제공자 권한·DB 계정 권한 |

DB는 연습용 읽기 전용 계정에서 허용된 조회만 사용한다. 조회도 민감정보 노출이나 부하를 만들 수 있으므로 필요한 열·행·기간만 요청한다.

## 7. 연결 해제와 인증 폐기

1. 앱에서 연습 연결을 끄거나 제거한다.
2. 현재 세션에서 해당 도구를 더 사용할 수 없는지 확인한다. 필요하면 새 세션에서 확인한다.
3. 제공자 계정의 연결된 앱·OAuth 허용 목록에서도 접근을 해제한다.
4. 별도 토큰을 만들었다면 그 토큰을 제공자 측에서 폐기한다.
5. 연습 설정에 남은 참조와 환경 변수를 확인한다. 다른 앱과 공유하는 인증은 영향 범위를 먼저 확인한다.
6. `출력/연결_검수.md`에 해제한 것과 확인하지 못한 것을 나눠 기록한다.

**앱에서 연결을 지운 것과 제공자 인증을 폐기한 것은 별개의 확인 항목**이다. 실제로 연결하지 않았다면 '가짜 목록으로 권한 설계만 수행, 인증 해제 실습 미수행'으로 기록한다.

## 8. 플러그인은 마지막에

플러그인은 스킬·에이전트·훅·MCP 같은 구성을 묶어 배포하는 단위다. 개인 실험이 끝나고 여러 프로젝트에 같은 구성을 적용할 때 검토한다. 설치 전 출처·구성 파일·실행 스크립트·필요한 인증·쓰기 범위를 확인한다.

이번에는 설치 없이 **C22 스킬, C23 검사, C24 검토자, C25 연결 설계**의 목록을 만든다. 종합 흐름은 '자료 조회 → 스킬로 초안 → 검토자 확인 → 사람이 검수'다. 외부 쓰기나 발송이 필요한 업무는 그 시점의 승인 범위를 따로 확인한다.

**내 화면에서:** 사용자 지정 → 커넥터 → 내 항목에서 현재 상태를 읽습니다. 계정에 연결됨으로 보여도 현재 대화에 조회 도구나 저장소 자료가 있어야 실제로 읽을 수 있습니다.

1. 문서 한 건 검색·읽기에 필요한 도구와 필요 없는 쓰기 도구를 분리합니다.
2. 가짜 조회 결과의 수업 수·교육시간·경과시간을 계산합니다. 이 텍스트를 읽은 것을 실제 서비스 조회라고 적지 않습니다.
3. 실제 연결을 선택할 때만 공식 인증·계정·범위·현재 도구·해제·제공자 인증 폐기를 확인합니다. 기본 실습에는 토큰이 필요 없습니다.

**완료 확인**

- 필요: docs.search·docs.read / 불필요: mail.send·calendar.create·db.execute
- 수업 2개·교육 90분·휴식 포함 경과 100분

**막혔을 때:** 읽기만 요청해도 토큰의 쓰기 권한이 자동 제거되지는 않습니다. 앱 연결 제거와 제공자 인증 해제를 따로 확인하고, 실제 연결하지 않았다면 해제 완료라고 적지 않습니다.

### 실제 커넥터 실패를 진단하기

Claude의 기존 Vercel 커넥터에서 공개 교육 사이트 배포의 **상태·커밋·별칭만 읽기**를 요청했습니다. `get_deployment`와 `list_deployment_aliases`가 실제 호출됐으나 **403 forbidden**으로 실패했습니다. 답변은 값을 받지 못했다고 표시했으며 일반 웹 검색으로 대체하지 않았습니다.

이어 팀 승인 링크만 요청했지만 `authorize_team_access`도 **404 Team not found**로 실패해 링크가 만들어지지 않았습니다. 계정 불일치 가능성은 추정이며 확정 원인으로 단정하지 않습니다.

| 확인할 경계 | 이번 관찰 | 다음 조치 |
|---|---|---|
| 계정의 연결 표시 | 연결은 있음 | 현재 대화의 도구 가용성을 따로 확인 |
| 실제 조회 권한 | 팀 접근 403 | 연결에 사용한 계정과 대상 팀을 확인 |
| 승인 링크 발급 | 팀을 찾지 못해 404 | 계정·팀을 확인한 뒤 링크를 다시 요청 |
| 조회 결과 | 상태·커밋·별칭 확인 불가 | 권한 해결 후 같은 읽기 요청 재시험 |

연결이 실패했다고 환경변수·API 키를 대화에 붙이지 않습니다. 새 인증·팀 접근 승인·설정 변경은 사용자 확인 없이 진행하지 않습니다. 화면은 **실제 실패 사례**이며 성공한 설정 화면이 아닙니다. [Codex의 기존 GitHub 실제 조회 기록](/materials/walkthrough/verified-practice.zip)과 구분합니다.

### 같은 연결에서 공개 검색은 가능한가

새 인증 없이 기존 커넥터의 `search_vercel_documentation`을 **한 번 허용**해 실제 공개 문서 검색을 완료했습니다. 이 도구는 계정·프로젝트 조회와 별개인 공개 문서 색인을 사용합니다. “항상 허용”이나 팀 접근 승인을 한 것은 아닙니다.

검색 결과에는 `next/image` 사용 예시는 있었지만 요청한 종횡비 문제의 상세 근거는 없었습니다. **도구 실행 완료·필요한 근거 확보·팀 자료 접근 성공은 세 가지 다른 판정**입니다. 이번에는 공개 검색 실행만 확인됐고, 배포 조회 403과 승인 링크 404는 해결되지 않았습니다. 원하던 답을 받지 못했으면 기억으로 빈 근거를 채우지 말고 공식 원문을 따로 확인합니다.

**이번 검토에서 확인한 범위:** 기존 GitHub 연결의 현재 세션 조회 실패에 더해, Claude의 기존 Vercel 커넥터로 교육 사이트 배포 조회와 별칭 조회를 실제 호출했습니다. 두 조회는 팀 접근 권한 403으로 실패했습니다. 승인 링크 요청도 Team not found 404여서 링크가 발급되지 않았습니다. 조회 성공·인증 승인·해제는 확인하지 않았으며 권한을 바꾸지 않았습니다. 같은 기존 Vercel 커넥터의 공개 문서 검색 도구를 한 번 허용해 실제 검색 완료를 확인했습니다. 질문에 필요한 상세 근거는 결과에 없었으며, 공개 검색 성공으로 팀 자료 조회 403이 해결된 것은 아닙니다.

## 숙제

1. 연결 대상·업무·필요 도구·불필요 도구·실제 권한·해제 방법을 한 표로 만든다.
2. 가짜 문서에서 수업 수와 총 시간을 검수한다.
3. 실제 조회, 가짜 결과 분석, 연결 설계를 구분한 완료 기록을 쓴다.

## 확인 퀴즈

### Q1. 커넥터와 MCP의 관계를 올바르게 설명한 것은?
- A. 커넥터는 반드시 MCP와 무관하다
- B. MCP는 외부 연결에 쓰이는 표준이며 커넥터가 이를 사용할 수 있다
- C. MCP를 쓰면 모든 계정 접근이 자동 허용된다
- D. 커넥터를 추가하면 파일 첨부는 불가능하다

### Q2. 문서 한 건을 검색·읽는 이번 업무에 필요하지 않은 동작은?
- A. 문서 검색
- B. 찾은 문서 읽기
- C. 메일 발송
- D. 문서 검색 결과 확인

### Q3. '읽기만 해'라고 요청했다면?
- A. 실제 토큰의 쓰기 권한도 자동 제거된다
- B. 운영 DB 계정이 자동 변경된다
- C. 기존 발송 메일이 취소된다
- D. 지시와 별도로 제공자·도구 권한을 확인해야 한다

### Q4. 앱에서 서버 연결을 제거한 뒤에도 확인할 것은?
- A. 제공자 측 OAuth·토큰 접근 해제
- B. 다른 사람의 비밀번호
- C. 모든 저장소 삭제
- D. 모든 브라우저 기록 공개

### Q5. 가짜 연결 목록만 분석했다면 올바른 완료 기록은?
- A. 실제 서비스 인증 성공
- B. 가짜 목록으로 권한 설계 수행, 실제 연결 미수행
- C. 실제 메일 조회 완료
- D. 운영 권한 변경 완료

## 정답과 해설

1. **B** — 사용자 연결 기능과 그 연결에 쓰이는 표준을 구분한다.
2. **C** — 조회 업무에 메일 발송 권한은 필요하지 않다.
3. **D** — 대화 지시가 서비스의 인증 범위를 자동으로 바꾸지는 않는다.
4. **A** — 클라이언트 설정 삭제와 제공자 인증 폐기를 따로 확인한다.
5. **B** — 설계와 실제 실행을 구분해야 잘못된 완료 보고를 피할 수 있다.
