# [강좌] C22. 스킬 — 같은 설명 세 번 했다면 저장하자

> Claude Desktop의 **Code 로컬 프로젝트** 기준 · Windows 중심 · 공식 문서 확인: 2026-11-14  
> 먼저 읽을 강의: C05 · C12 · C14. 일반 업무 활용만 필요하면 선택해서 읽어도 됩니다.  
> 원안: 사용자가 제공한 「클로드코드_쉽게배우기_C09_확장기능_4부작.md」를 데스크톱 과정용으로 재구성했습니다.

## 3줄요약

1. 스킬은 반복 업무의 입력·순서·출력·금지·완료 기준을 저장한 절차다.
2. 이번에는 Code 화면에서 말로 `SKILL.md`를 만들고 같은 자료에 두 번 적용한다.
3. 스킬을 불렀다는 표시와 결과의 정확성을 따로 확인한다. 이름만 부르고 끝내면 실습 끝난 게 아님.

## 1. 오늘 만드는 것

매주 회의 메모에서 할 일을 뽑는다고 해보자. 매번 담당자·기한·미정 항목 표시까지 설명하면 귀찮다. 그 절차를 `meeting-actions`라는 스킬에 저장한다.

| 구분 | 적는 내용 |
|---|---|
| 프로젝트 지침·CLAUDE.md | 프로젝트에서 계속 참고할 공통 기준 |
| 스킬 | 특정 업무를 반복할 때 불러올 작업 절차 |
| 결과 검수 | 실제 입력과 출력이 맞는지 사람이 확인하는 일 |

일반 Chat·Cowork의 개인 스킬 등록과 Code의 프로젝트 폴더 설정은 구분한다. 이번 실습은 Code에서 선택한 로컬 프로젝트의 `.claude/skills/`를 사용한다. 앱 전체의 모든 화면에 설치됐다고 기록하지 않는다.

## 2. 준비물과 입력

1. 탐색기에 `Documents/Claude_연습/확장기능` 폴더를 만든다.
2. Desktop의 Code 화면에서 이 로컬 폴더를 선택한다. 클라우드 세션이나 회사 저장소를 선택하지 않는다.
3. [심화 공통 샘플](실습자료/07_확장기능_공통샘플.md)의 회의 A·B를 연습 폴더의 `입력/회의A.md`, `입력/회의B.md`로 각각 저장해 달라고 요청한다.
4. 파일 작업 권한이 나오면 폴더와 생성할 파일을 확인한다. 터미널을 직접 열 필요는 없다.

## 3. 먼저 한 번 수동으로 해보기

Code 입력창에 붙여 넣는다.

```text
입력/회의A.md에서 실행할 일만 표로 정리해줘.
열은 항목ID, 할 일, 담당자, 기한, 상태, 근거ID로 해줘.
담당자·기한이 없으면 '미정'으로 적고 추정하지 마.
논의만 한 내용과 보류한 내용은 실행할 일에 섞지 말고 별도 표로 적어줘.
출력/회의A_수동.md에 저장하고 원본은 수정하지 마.
```

예상 결과는 실행할 일 3개, 보류 1개다. **담당자가 미정인 M02에 수진·지민 등을 임의로 배정하면 오류**다. 반대로 M03의 장소 후보 비교 담당자는 원문에 지민으로 명시돼 있으므로 그대로 유지한다. AI가 만든 그럴듯한 표보다 원문 한 줄이 우선이다.

## 4. 절차를 스킬로 저장하기

다음처럼 요청한다.

```text
방금 회의록 정리 절차를 이 프로젝트의 스킬로 저장해줘.
파일 위치: .claude/skills/meeting-actions/SKILL.md
아래 예시를 기준으로 만들고, 요청한 스킬 파일 외의 기존 설정은 수정하지 마.
명령 실행이나 외부 연결은 필요 없어.
만든 뒤 실제 파일 경로와 내용을 보여줘.
```

파일 내용의 기준은 다음과 같다. 코드를 이해하고 직접 타이핑하는 시험이 아니다. 생성된 파일이 이 구조인지 확인하는 실습이다.

```markdown
---
name: meeting-actions
description: 회의 메모에서 실행할 일과 보류 항목을 구분하고 담당자·기한·근거를 정리할 때 사용합니다.
argument-hint: "<회의 메모 경로>"
disable-model-invocation: true
---

$ARGUMENTS 파일을 읽고 실행할 일을 정리합니다.

## 순서
1. 입력 파일과 문서 내 항목ID를 확인합니다. 항목ID·근거ID 모두 원문의 M01/N01 같은 ID를 유지하고 새 A01/B01 번호를 붙이지 않습니다.
2. 실행할 일, 보류, 단순 논의를 구분합니다.
3. 담당자와 기한은 원문에 있는 값만 사용합니다.
4. 없는 값은 '미정'으로 표시합니다.
5. 실행할 일은 항목ID·할 일·담당자·기한·상태·근거ID 표로 만듭니다.
6. 보류·단순 논의는 별도 표로 만듭니다.
7. 실행할 일 수, 담당자 미정 수, 기한 미정 수, 보류 수를 요약합니다.

## 금지
- 입력 파일을 수정하지 않습니다.
- 담당자·기한을 추정하지 않습니다.
- 메일 발송, 예약 등록, 외부 서비스 변경을 하지 않습니다.

## 완료 기준
- 모든 행에서 원문의 근거ID를 찾을 수 있어야 합니다.
- 원문에 없는 담당자·기한이 없어야 합니다.
- 결과를 이 프로젝트의 출력 폴더에 별도 MD로 저장합니다.
```

`disable-model-invocation: true`는 사용자가 직접 호출하도록 정하는 설정이다. 파일 수정 권한이나 결과의 정확성을 보장하는 설정은 아니다. 스킬의 지시와 도구 권한은 따로 봐야 한다.

## 5. 같은 자료와 다른 자료에 적용하기

Code의 입력창에 `/meeting-actions`를 입력해 목록에 나타나는지 확인한다. 보이면 입력 경로를 이어 쓴다.

```text
/meeting-actions 입력/회의A.md
```

이어서 회의 B에도 적용한다.

```text
/meeting-actions 입력/회의B.md
```

명령 목록이 보이지 않으면 폴더 선택·파일 이름·현재 세션의 스킬 지원을 확인한다. 필요하면 같은 폴더에서 새 세션을 시작한다. 여전히 호출할 수 없으면 SKILL.md를 첨부해서 절차대로 처리할 수 있지만, 결과 기록에는 **'절차 파일 첨부로 실행, 스킬 호출 미확인'**이라고 쓴다.

## 6. 예상 결과와 검수

| 검수 항목 | 회의 A | 회의 B |
|---|---:|---:|
| 실행할 일 | 3개 | 2개 |
| 실행할 일 중 담당자 미정 | 1개 | 0개 |
| 실행할 일 중 기한 미정 | 1개 | 1개 |
| 보류 | 1개 | 1개 |

`출력/스킬_검수.md`에 입력 경로, 스킬 경로, 호출 확인 여부, 예상값과 실제값을 적는다. 수동 결과와 스킬 결과의 문장이 달라도 괜찮다. 분류·건수·근거가 같아야 한다.

## 7. 막혔을 때

| 증상 | 먼저 확인할 것 |
|---|---|
| 스킬을 못 찾음 | Code에서 선택한 폴더 아래에 `.claude/skills/meeting-actions/SKILL.md`가 있는지 |
| 다른 회의 결과가 섞임 | 호출할 때 입력 경로를 정확히 줬는지 |
| 보류 업무를 실행 업무로 넣음 | 분류 규칙과 원문 항목ID를 다시 비교 |
| 기한을 임의로 채움 | '미정으로 표시' 규칙과 실패 사례를 스킬에 보완 |
| 저장했다고 하는데 파일이 없음 | 변경 목록과 탐색기에서 실제 파일 확인 |

반복이 확실해진 뒤 예시 파일과 변경 이력을 추가한다. 한 번 쓸 일을 억지로 스킬로 만들 필요는 없다. 프로젝트 설정을 GitHub에 공유할 때는 입력 자료와 비밀값이 섞이지 않았는지도 확인한다.

## 화면 보며 따라 하기

**준비:** ZIP의 회의A.md·회의B.md를 각각 준비합니다.

[공통 실습 파일 ZIP 받기](/materials/walkthrough/cd-practice-starter.zip) · ZIP을 모두 푼 뒤 00_먼저읽기.md부터 확인합니다.

**내 화면에서:** 이번 실제 캡처는 Claude 웹의 계정 스킬 화면입니다. 사용자 지정 → Skills → 추가 → Skill 만들기에서 이름·설명·절차를 입력합니다. 계정 스킬과 .claude/skills의 프로젝트 스킬은 구분합니다.

1. 수동으로 회의 A를 정리해 실행 3개·보류 1개를 먼저 확인합니다.
2. 프로젝트용 SKILL.md를 올바른 제품 경로에 만들고 name·description·입출력·미정·보류 규칙을 확인합니다.
3. 실제 호출이 확인된 경우에만 스킬 사용으로 기록합니다. 목록에 없으면 절차 파일 첨부로 A·B를 처리하고 수행 경로를 적습니다.

**완료 확인**

- 회의 A: 실행 3 / 담당 미정 1 / 기한 미정 1 / 보류 1
- 회의 B: 실행 2 / 담당 미정 0 / 기한 미정 1 / 보류 1
- 항목ID·근거ID 모두 M01~M04 / N01~N03 원문 그대로 유지

**막혔을 때:** 스킬만 실행해서 원문을 못 찾으면 회의 A·B를 명시해 전달합니다. 항목ID와 근거ID도 대조하고 A01/B01처럼 새로 번호를 붙였으면 고칩니다. 스킬 파일 저장·발견·실제 사용·결과 검수는 각각 기록합니다.

### 실제로 막힌 지점과 해결

스킬만 선택해 보내면 회의 원문이 없다는 안내가 나왔습니다. 스킬은 절차를 담고 있으므로, 선택한 뒤 회의 A·B의 원문도 입력하거나 첨부해야 합니다. 여러 줄 입력은 붙여넣기로 하고 **메시지 보내기는 마지막에 한 번만** 누릅니다.

이번 교육용 회의 스킬 이름은 `edu-meeting-actions-demo`입니다. 화면은 회의 예제로 등록·선택·결과 검수를 보여주며, 지출 스킬 자체의 등록 결과라고 바꾸어 읽지 않습니다.

## 숙제

1. 주간 보고 또는 파일 검토 중 하나를 골라 입력·순서·출력·금지·완료 기준을 적는다.
2. 서로 다른 샘플 두 개에서 확인할 예상 결과를 먼저 정한다.
3. 스킬 호출 여부와 결과 검수를 분리해 기록한다.

## 확인 퀴즈

### Q1. 스킬로 저장하기 가장 적합한 것은?
- A. 한 번만 하는 인사말 작성
- B. 반복하는 회의 메모 정리 절차
- C. 계정 비밀번호
- D. AI의 모든 답변을 정확하게 만드는 규칙

### Q2. 이번 Code 프로젝트 스킬의 필수 파일은?
- A. `.claude/skills/meeting-actions/SKILL.md`
- B. 아무 폴더의 `설명.txt`
- C. 운영 DB 비밀번호 파일
- D. 브라우저 방문 기록

### Q3. 스킬이 담당자를 임의로 채우거나 항목ID를 바꿨다면?
- A. 표가 예쁘면 통과
- B. 호출됐으므로 통과
- C. 원문과 대조해 실패를 기록하고 절차를 보완한다
- D. 담당자를 원문에 추가한다

### Q4. `disable-model-invocation: true`의 역할은?
- A. 모든 쓰기 작업을 기술적으로 차단
- B. 결과의 정답 보장
- C. 무료 사용 보장
- D. Claude의 자동 호출을 막고 사용자 직접 호출로 제한

### Q5. 목록에서 스킬을 찾지 못해 SKILL.md를 첨부했다면?
- A. 스킬 설치·호출 성공으로 기록
- B. 절차 파일 첨부로 실행했다고 기록
- C. 다른 계정의 스킬이 실행됐다고 추정
- D. 결과 검수 생략

## 정답과 해설

1. **B** — 반복해서 검증한 절차를 저장해야 재사용 효과가 있다.
2. **A** — 선택한 로컬 프로젝트 아래의 정확한 경로를 확인한다.
3. **C** — 스킬 실행과 결과의 정확성은 별개다.
4. **D** — 호출 주체를 제어하는 설정이며 모든 권한을 제한하는 장치는 아니다.
5. **B** — 실제 수행한 방법과 확인하지 못한 기능을 구분해 기록한다.
