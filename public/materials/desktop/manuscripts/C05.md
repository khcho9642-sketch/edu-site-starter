# [강좌] C05. 같은 설명 줄이기 — 프로젝트 지침과 CLAUDE.md 구분

> Claude Desktop 앱 전체 기준 · Windows 중심 · 공식 문서 확인: 2026-11-14
> 실습 화면: 업무 프로젝트의 지침·파일 설정, Code는 별도 선택 절
> CLAUDE.md가 Desktop 모든 화면에서 똑같이 적용된다고 설명하지 않습니다.

> 먼저 읽을 강의: C03 · C04.

## 3줄요약

1. 앱의 개인 지침, 프로젝트 지침, Code용 CLAUDE.md를 구분한다.
2. 규칙은 짧고 검증 가능하게 쓰고, 실제 결과에서 적용 여부를 확인한다.
3. 프로젝트 지침은 비밀값 저장소나 강제 보안 장치가 아니다.

## 1. 준비와 오늘의 결과

[보고서 견본](실습자료/03_보고서견본.md)과 지출 샘플을 준비한다. 목표는 `지출연습` 프로젝트에 짧은 지침을 넣고 두 대화에서 결과를 비교하는 것.

## 2. 업무 프로젝트에 지침 넣기

1. 왼쪽 **Projects**에서 새 프로젝트를 만든다. 새로 시작하는 항목을 선택하고 이름을 `지출연습`으로 정한다.
2. 프로젝트의 지침·Instructions 항목을 열어 아래 내용을 넣는다. 계정에 프로젝트 기능이 없으면 `작업지침.md`로 저장해 매번 첨부하는 대체 실습을 한다.

> 답변은 한국어로 쉽게 쓴다. 금액은 원 단위로 표시한다. 확정 금액과 미확정 금액을 구분한다. 금액이 빈 거래는 0원으로 바꾸지 않는다. 원본은 보존하고 결과를 새 파일로 만든다. 보고서 수치는 제공 자료에서 확인한 것만 사용한다.

3. 프로젝트에 샘플을 추가하고 “T004의 금액을 어떻게 처리할지 설명해줘”라고 묻는다.
4. 같은 프로젝트의 새 대화에서도 같은 질문을 한다. **미확정으로 유지**하는지 확인한다.
5. 개인 전체 지침은 설정의 **Your Claude / Instructions for Claude**, 또는 이전 Account 화면에서 찾는다. 특정 프로젝트만의 규칙을 전역에 넣지 않는다.

## 3. Code를 사용할 때의 CLAUDE.md

Code의 로컬 프로젝트 규칙은 `CLAUDE.md`로 관리할 수 있다. Code에서 실제 연습 폴더를 선택하고 “이 프로젝트의 CLAUDE.md에 아래 규칙을 작성해줘”라고 요청한 뒤, 생성 경로와 내용을 확인한다.

업무 프로젝트의 지침과 로컬 Code 프로젝트의 CLAUDE.md가 자동으로 같은 내용이라고 가정하지 않는다. 새 Code 세션에서 로드된 지침과 실제 결과를 확인한다. 다른 프로젝트에서도 쓰는 사용자 지침과 현재 프로젝트 전용 지침도 구분한다. 이 절은 Code를 사용하지 않으면 읽기만 해도 된다. 실제 Code 조작은 C14에서 배우므로 지금은 프로젝트 지침과의 차이만 이해하면 된다.

## 4. 좋은 요청의 세 요소

| 요소 | 이번 실습 |
|---|---|
| 어디 | 첨부한 지출 샘플의 금액 열 |
| 무엇 | 빈 값과 환불을 분리 |
| 결과 | 거래 ID와 처리 이유를 표로 표시 |

“알아서 깔끔하게”보다 “T004는 미확정, T005는 음수 유지, 근거 표를 보여줘”가 검증하기 쉽다.

## 5. 확인 방법과 막혔을 때

지침을 넣어도 누락이 생길 수 있다. 결과의 거래 수·합계·미확정 표시를 다시 확인한다. 자동 메모리는 유용한 정보를 기억할 수 있지만, 현재 입력 자료와 결과 검증을 대신하지 않는다. 기억에 남기면 안 되는 비밀값은 지침이나 메모리에 넣지 않는다. 지침을 작성했다고 폴더·네트워크 접근이 기술적으로 차단된 것은 아니다.

## 화면 보며 따라 하기

**준비:** 지출 샘플과 짧은 지침을 준비합니다.

[공통 실습 파일 ZIP 받기](/materials/walkthrough/cd-practice-starter.zip) · ZIP을 모두 푼 뒤 00_먼저읽기.md부터 확인합니다.

**내 화면에서:** Claude 업무 프로젝트 지침과 Code 로컬 프로젝트의 CLAUDE.md는 별도입니다.

1. 프로젝트를 쓴다면 새 연습 프로젝트를 만들고 이름을 지출연습으로 정합니다. 기존 회사 프로젝트는 수정하지 않습니다.
2. 프로젝트 지침에는 빈 금액 미확정, 환불 음수 유지, 원본 보존을 넣습니다. 로컬 개발 지침 파일과 계정의 프로젝트 지침을 구분합니다.
3. 같은 프로젝트의 두 대화에서 T004 처리 방법을 묻고 실제 답을 비교합니다. 기능이 없으면 작업지침.md를 매번 첨부합니다.

**완료 확인**

- T004를 0원으로 채우지 않음
- 지침의 저장 위치와 적용 범위를 설명할 수 있음

**막혔을 때:** 지침을 넣는 칸을 못 찾으면 프로젝트 상세의 Instructions·지침을 먼저 찾습니다. 개인화 설정에 이번 샘플의 합계까지 고정하지 마세요. 파일이 저장됐다고 적용까지 확인된 것은 아닙니다.

![따라 하기 화면](/materials/walkthrough/screens/instructions-file.png)

**이번 검토에서 확인한 범위:** 그림은 연습 지침 파일의 확인 예시입니다. 두 제품 계정의 프로젝트 지침 저장·새 대화 적용은 검증하지 않았습니다.

## 숙제

1. 업무 프로젝트 지침을 6줄 이내로 작성한다.
2. 같은 프로젝트의 두 대화에서 T004 처리 결과를 비교한다.
3. 프로젝트 기능이 없으면 지침 파일을 직접 첨부해 같은 검증을 하고 대체 경로 사용을 기록한다.

## 확인 퀴즈

4지선다 5문항입니다. 먼저 답을 고른 뒤 아래 해설을 확인하세요.

### Q1. 프로젝트 지침에 넣기 적절한 내용은?

- A. 개인 카드 비밀번호
- B. 빈 금액을 0으로 바꾸지 않는 처리 규칙
- C. 실제 API 비밀키
- D. 매일 변하는 결과 숫자 전부

### Q2. CLAUDE.md의 적용에 대한 올바른 설명은?

- A. Code 프로젝트의 지침으로 확인하며 앱의 프로젝트 지침과 구분한다
- B. 모든 화면에서 무조건 동일하게 적용된다
- C. 메일 발송 권한을 자동으로 부여한다
- D. 파일 접근을 완전히 격리한다

### Q3. 프로젝트 기능이 없으면?

- A. 비밀키를 채팅에 넣는다
- B. 실습을 위해 조직 정책을 우회한다
- C. 다른 회원의 프로젝트를 복사한다
- D. 지침 MD를 작업마다 첨부해 대체 실습한다

### Q4. 지침이 제대로 적용됐는지 확인하려면?

- A. 규칙을 길게 늘리기만 한다
- B. AI가 기억한다고 말하면 모두 맞다고 본다
- C. 같은 기준의 질문과 실제 출력 결과를 대조한다
- D. 저장 버튼을 눌렀으니 끝낸다

### Q5. T004 금액의 올바른 처리는?

- A. 행을 숨겨 없앤다
- B. 미확정으로 남기고 별도로 표시한다
- C. 0원으로 채운다
- D. 다른 거래 평균으로 확정한다

## 정답과 해설

1. **B** — 반복 적용할 업무 규칙을 지침으로 남긴다. 비밀값은 넣지 않는다.

2. **A** — 표면별 지침 체계와 적용 범위를 구분해야 한다.

3. **D** — 필요한 맥락을 파일로 전달하는 방식으로도 기본 원리를 연습할 수 있다.

4. **C** — 설정 존재와 실제 행동 일치는 별도로 확인한다.

5. **B** — 근거 없는 보정은 집계 오류를 만든다.

## 념글 박제

지침은 짧게, 적용 범위는 분명하게, 결과는 직접 확인.
