# [강좌] C03. 계획과 권한 — 승인 버튼 읽는 법

> Claude Desktop 앱 전체 기준 · Windows 중심 · 공식 문서 확인: 2026-11-14
> 실습 화면: 일반 업무 작업의 권한 요청과 Code 화면의 모드 선택을 구분
> Code의 모드 이름을 앱 전체에 적용하지 않습니다. 실제 보이는 선택지와 관리자 정책을 확인합니다.

> 먼저 읽을 강의: C01 · C02.

## 3줄요약

1. 큰 작업은 먼저 분석·계획을 받고 범위를 정한다.
2. 통합 일반 업무 화면에도 수동·자동 메뉴가 보일 수 있다. Code의 Plan 등과 구분하고 현재 화면의 권한 안내를 읽는다.
3. 폴더·파일·계정·외부 전송 권한을 따로 확인한다. 자동 승인은 안전 인증이 아니다.

## 1. 준비와 오늘의 결과

[지출 샘플](실습자료/01_지출샘플.md)을 첨부한다. 오늘 결과는 **실행 전 계획표와 승인 판단표**다. 실제 삭제·메일 발송·설정 변경은 실습하지 않는다.

## 2. 일반 업무 화면에서 계획부터

1. 새 대화 또는 Cowork 작업에 샘플을 첨부한다.
2. 다음처럼 범위를 제한한다.

> 이 자료를 정리할 계획만 작성해줘. 읽을 자료, 만들 결과물, 수정할 파일, 외부 연결 필요 여부, 검증 방법을 표로 적어줘. 지금은 파일을 옮기거나 외부로 보내지 마.

3. 계획에 없는 외부 서비스나 원본 덮어쓰기가 보이면 이유를 묻고 범위를 수정한다.
4. 정제 결과를 만들 때도 원본은 두고 별도 파일을 만들도록 요청한다. 자연어 지시는 작업 의도이며, 기술적인 접근 차단을 설정한 것과는 다르다.

## 3. Code 화면에서는 모드 선택 메뉴 확인

Code를 사용하는 사람만 이 절을 따라 한다. 입력창 주변의 모드 선택기를 연다.

| 표시될 수 있는 모드 | 뜻과 확인 |
|---|---|
| Plan | 분석과 계획 중심. 구현 전 계획 검토에 사용 |
| Manual / 이전 Ask permissions | 수정·실행 요청을 확인하면서 진행 |
| Accept edits / 이전 Auto accept edits | 파일 편집 승인 범위를 넓힘. 모든 실행이 안전하다는 뜻은 아님 |
| Auto | 지원 계정·모델·정책에 따라 제공. 자동 판단도 오류 가능 |
| Bypass permissions | 별도 설정이나 조직 정책에 따라 노출. 초보 실습에서 켜지 않음 |

**다섯 개가 모두 보여야 정상인 게 아니다.** 이 강의의 숙제는 자신에게 보이는 메뉴를 기록하고 Plan/Manual의 뜻을 이해하는 것이다. 현재 공식 Desktop 안내에서 `/permissions`는 터미널 대화상자 명령으로 지원되지 않는다. 모드 선택은 화면 메뉴를 사용한다.

## 4. 승인 판단 실습

아래는 가짜 요청이다. 실제로 실행하지 말고 판단 이유를 적는다.

| 요청 | 판단 기준 |
|---|---|
| 첨부한 지출 샘플 읽기 | 내가 준 자료와 작업 목적에 맞는가 |
| 원본 CSV 덮어쓰기 | 새 파일로 만들도록 변경 요청 |
| 회사 전체 공유 폴더 연결 | 필요한 최소 범위와 회사 정책 확인 |
| 답장 초안 만들기 | 실제 발송 여부와 별개로 검토 |
| 파일을 외부 주소에 전송 | 수신자·내용·목적이 명시적으로 승인됐는가 |

## 5. 확인 방법과 막혔을 때

차단 규칙을 만들었다면 **어느 파일·어느 도구에 적용됐는지와 거부 결과**를 확인한다. “막아줘”라는 대답만으로 차단 완료로 판정하지 않는다. 테스트는 가짜 비밀 파일로 한다. 폴더 접근과 외부 커넥터 권한은 별개이며, 권한 문제를 해결하려고 무조건 전체 허용하지 않는다.

## 화면 보며 따라 하기

**준비:** 지출 샘플과 승인 판단표를 준비합니다.

[공통 실습 파일 ZIP 받기](/materials/walkthrough/cd-practice-starter.zip) · ZIP을 모두 푼 뒤 00_먼저읽기.md부터 확인합니다.

**내 화면에서:** 현재 통합 Claude 업무 화면에는 수동·자동 메뉴가 보였습니다. 그림은 일반 업무 화면이며 Code의 모든 모드를 나열한 그림이 아닙니다.

1. 정리 요청 앞에 지금은 계획만, 파일 수정·외부 전송 금지를 붙입니다.
2. 계획표에서 읽을 파일, 만들 파일, 원본 보존, 외부 연결, 검증 방법 다섯 칸을 찾습니다.
3. 권한 메뉴는 열어 현재 상태만 읽습니다. 넓은 권한을 켜서 오류를 해결하지 않습니다. Code·Codex의 모드와 일반 업무의 권한 메뉴를 구분합니다.

**완료 확인**

- 계획표가 입력·출력·원본·연결·검증을 구분
- 자연어 계획 요청을 기술적 읽기 전용 설정으로 기록하지 않음

**막혔을 때:** Plan이 안 보인다면 먼저 현재 화면이 일반 업무인지 개발 화면인지 확인합니다. 계획 문서 요청은 모드 이름과 무관하게 할 수 있지만 권한 경계가 자동으로 바뀌지는 않습니다.

**이번 검토에서 확인한 범위:** 두 제품의 실행 전 계획표와 클로드 통합 화면의 권한 메뉴를 확인했습니다. 권한 설정은 변경하지 않았습니다.

## 숙제

1. 샘플 정리 계획에서 원본 보존·외부 연결·검증 방법을 찾는다.
2. 승인 판단표의 다섯 요청에 허용/수정요청/보류와 이유를 적는다.
3. Code를 쓴다면 실제 표시된 모드만 기록한다. Code를 쓰지 않으면 그 절은 읽기만 한다.

## 확인 퀴즈

4지선다 5문항입니다. 먼저 답을 고른 뒤 아래 해설을 확인하세요.

### Q1. Code 모드가 네 개 또는 다섯 개로 다르게 보이면?

- A. 항상 고장이다
- B. Bypass를 반드시 켠다
- C. 다른 사람 계정으로 로그인한다
- D. 계정·모델·버전·정책에 따른 표시를 확인한다

### Q2. Desktop Code에서 권한 모드를 바꾸는 기본 방법은?

- A. 파일명을 바꾼다
- B. 로그인 비밀번호를 채팅에 쓴다
- C. 입력창 주변의 모드 선택 메뉴
- D. 터미널 전용 /permissions 창을 반드시 연다

### Q3. 계획 요청만으로 파일 접근이 기술적으로 차단될까?

- A. 연결한 계정이 자동 해지된다
- B. 자연어 지시와 실제 권한 차단은 별개다
- C. 모든 도구가 자동 차단된다
- D. 관리자 권한이 사라진다

### Q4. 원본 덮어쓰기 요청이 나오면?

- A. 별도 결과 파일로 바꾸도록 요청한다
- B. 확인 없이 승인한다
- C. 원본을 먼저 삭제한다
- D. 보안을 위해 메일로 원본을 보낸다

### Q5. 자동 승인 모드에 대한 올바른 설명은?

- A. 모든 결과가 정확하다
- B. 개인정보 유출이 불가능하다
- C. 검토가 필요 없어지는 기능이다
- D. 승인 절차를 줄일 수 있지만 안전을 보장하지 않는다

## 정답과 해설

1. **D** — 모든 모드가 모든 환경에 나타나는 것은 아니다.

2. **C** — 현재 공식 안내에 맞춰 화면의 모드 선택기를 사용한다.

3. **B** — 의도 전달과 도구·시스템의 접근 통제는 구분한다.

4. **A** — 원본 보존은 검토와 복구의 기준을 남긴다.

5. **D** — 자동 판단과 결과 검수는 다른 문제다.
