# [강좌] C19. 이슈와 체크(CI) — 빨간 X 읽는 법

> Claude Desktop 앱 전체 기준 · Windows 중심 · 공식 문서 확인: 2026-11-14
> 실습 화면: GitHub 웹의 Issues 탭, PR의 Checks 영역
> 자동 검사(GitHub Actions)를 새로 설정하는 것은 이 강의 범위가 아닙니다. 이미 있는 체크를 읽고 대응하는 법을 다룹니다.

> 먼저 읽을 강의: C18.

## 3줄요약

1. **이슈** = 할 일·버그 메모장. PR과 연결하면 "무엇 때문에 바꿨는지"가 남는다.
2. PR의 **체크(✅/❌)**는 자동 검사 결과다. ❌면 **로그를 읽고** 원인부터 확인한다.
3. 체크를 끄거나 테스트를 지워서 통과시키지 않는다.

## 1. 준비와 오늘의 결과

연습 저장소를 쓴다. 오늘 결과는 **이슈 1개 → 그 이슈를 해결하는 PR 1개 → 체크 결과 해석 메모 1장**이다. 연습 저장소에 체크가 없다면 [가짜 CI 실패 로그](실습자료/08_CI_실패로그.md)로 읽기 실습을 한다. 공개 저장소의 체크 화면은 선택 참고이며 새 CI를 설치할 필요는 없다.

## 2. 이슈 만들고 PR과 연결하기

1. GitHub 웹 → **Issues** 탭 → 새 이슈
2. 제목: `README에 샘플 검수 체크리스트 추가`
3. 본문: C18에서 만든 합계 표 아래에 거래 수·미확정·환불 검수 체크리스트를 추가하자는 요청과 기대 결과를 쓴다. C18에서 이미 넣은 T004 미확정 표시를 없는 문제로 꾸미지 않는다.
4. Code 화면에서 요청한다.

> 이슈 "README에 샘플 검수 체크리스트 추가"를 위한 브랜치를 만들고 PR을 올려줘. 기존 합계 표와 T004 미확정 표시는 유지해. PR 설명에 이 이슈를 닫는다고 연결해줘. 이슈 번호는 내가 알려줄게: (번호)

5. PR이 머지되면 이슈가 자동으로 닫히는지 확인한다(연결 방식에 따라 다름).

## 3. 체크(CI) 결과 읽기

| 표시 | 뜻 | 할 일 |
|---|---|---|
| 노란 점 / 진행 중 | 검사 중 | 기다린다 |
| ✅ 초록 체크 | 통과 | 그래도 Files changed는 읽는다 |
| ❌ 빨간 X | 실패 | **Details(자세히)**를 눌러 로그 확인 |
| No checks / 체크 없음 | 자동 검사가 설정되지 않았거나 실행 기록이 없음 | 통과라고 쓰지 말고 가짜 로그 읽기 실습으로 대체 |
| Skipped / Cancelled | 건너뛰거나 취소됨 | 통과와 구분하고 실제 수행한 검사를 확인 |

**계정 없이 하는 실패 로그 실습:** [공통 로그](실습자료/08_CI_실패로그.md)의 세 사례를 읽고 `상태 / 첫 오류 줄 / 원인 후보 / 다음 확인 / 실제 재실행 여부` 다섯 칸을 채운다. 사례 A는 32,000원과 28,000원의 차이를 T005 환불 부호로 설명하고, 사례 B는 파일 경로·복사 여부를 확인한다. 사례 C는 검사가 없으므로 통과로 표시하지 않는다. 해설은 먼저 답을 적은 뒤 비교한다. 로그를 읽은 것만으로 실제 CI를 실행·복구했다고 기록하지 않는다.

❌일 때 Claude에게 이렇게 맡긴다.

> PR 체크가 실패했어. 실패 로그의 핵심 에러 줄을 찾아서 원인을 쉽게 설명해줘. 고치기 전에 무엇을 바꿀지 계획부터 보여줘. 테스트를 지우거나 약하게 만들지 마.

Desktop 앱에는 PR 상태를 보여주거나 체크 실패를 고치는 것을 돕는 기능이 있을 수 있다. 표시와 이름은 버전·계정마다 다르므로 보이는 대로 기록한다.

## 4. 주의 사항

- 체크 실패를 **우회(검사 끄기·필수 검사 해제)**하지 않는다.
- 로그에 비밀값이 찍혀 있으면 캡처·공유하지 말고 C16의 대응을 따른다.
- 이슈·PR 내용은 저장소 접근자가 모두 본다. 개인정보를 쓰지 않는다.
- 자동 수정 기능을 쓰더라도 **결과 PR의 변경 파일은 사람이 읽는다.**

## 5. 이렇게는 쓰지 말자

| ❌ 이렇게 하지 말자 | ✅ 대신 이렇게 | 이유 |
|---|---|---|
| "체크 끄고 머지해" | 실패 원인부터 확인 | 고장 난 코드가 본편에 들어간다 |
| 로그 안 읽고 "고쳐줘"만 반복 | 핵심 에러 줄 + 계획부터 | 같은 실패를 계속 돌린다 |
| 테스트를 지워서 통과 | "테스트는 고치지 마" (B07) | 검사가 의미 없어진다 |
| 이슈 제목 "안 됨" | 무엇이·어디서·기대 결과 | 나중에 아무도 이해 못 한다 |

## 6. 확인 방법과 막혔을 때

- 이슈 화면에 연결된 PR이 표시되는지 본다.
- 머지 후 이슈 상태(열림/닫힘)를 확인한다.
- 체크 로그가 너무 길면 "에러가 처음 나온 줄 위아래 10줄"만 골라 Claude에게 준다(비밀값은 가린다).

## 화면 보며 따라 하기

**준비:** 08_CI_실패로그.md와 이슈·PR 연결 양식을 준비합니다.

[공통 실습 파일 ZIP 받기](/materials/walkthrough/cd-practice-starter.zip) · ZIP을 모두 푼 뒤 00_먼저읽기.md부터 확인합니다.

**내 화면에서:** GitHub Issues·Pull requests·Checks를 구분해 읽습니다. 자동 수정 후에도 diff를 확인합니다.

1. 이슈에는 재현 위치·기대 결과·실제 결과를 씁니다. 아직 생성하지 않았다면 이슈 초안으로 기록합니다.
2. PR에 실제 이슈 번호를 연결하고 대상 브랜치와 체크 상태를 봅니다.
3. CI가 없으면 가짜 로그 A·B·C를 읽습니다. 첫 오류 줄·원인 후보·다음 확인·재실행 여부를 표로 남깁니다.

**완료 확인**

- 32,000원: 환불 부호 / ENOENT: 파일 경로
- No checks·Skipped·Cancelled를 통과와 구분

**막혔을 때:** 체크 없음은 통과가 아닙니다. 테스트를 삭제하거나 기준을 낮추지 않고 원인을 설명한 뒤 코드를 수정합니다.

![따라 하기 화면](/materials/walkthrough/screens/ci-result.png)

**이번 검토에서 확인한 범위:** 가짜 실패 로그의 원인·기대값을 검사했습니다. 새 GitHub 이슈 생성·연결·원격 CI 재실행은 별도 미검증입니다.

## 숙제

1. 이슈 1개를 만든다(무엇이·기대 결과 포함).
2. 그 이슈를 해결하는 PR을 만들고 연결 여부를 확인한다.
3. 체크가 있다면 실제 결과를, 없다면 가짜 실패 로그 세 사례의 "표시 → 뜻 → 할 일"을 메모한다. 실제 CI를 재실행했는지 별도로 기록한다.

## 확인 퀴즈

4지선다 5문항입니다. 먼저 답을 고른 뒤 아래 해설을 확인하세요.

### Q1. 이슈의 역할로 맞는 것은?

- A. 저장소 삭제
- B. 비밀번호 저장소
- C. 요금 결제 내역
- D. 할 일·버그를 기록하고 PR과 연결하는 메모장

### Q2. PR 체크에 빨간 X가 떴다. 먼저 할 일은?

- A. Details를 눌러 실패 로그를 확인한다
- B. 체크를 끈다
- C. 바로 머지한다
- D. 저장소를 새로 만든다

### Q3. 테스트 실패를 "해결"하는 잘못된 방법은?

- A. 원인을 찾아 코드를 고친다
- B. 테스트를 지운다
- C. 로그를 읽는다
- D. 계획을 먼저 받는다

### Q4. 체크가 초록 ✅이면?

- A. 아무것도 볼 필요 없다
- B. 저장소를 Public으로 바꾼다
- C. 그래도 변경 파일은 읽는다
- D. 이슈를 삭제한다

### Q5. 연습 저장소에 체크가 없다면 올바른 학습 기록은?

- A. 초록 체크가 없으니 자동 검사 통과라고 쓴다
- B. 가짜 로그로 읽기 연습을 하고 실제 CI 실행은 미수행으로 적는다
- C. 원인을 보지 않고 필수 검사를 끈다
- D. 다른 저장소의 통과 결과를 내 결과로 쓴다

## 정답과 해설

1. **D** — 이슈는 "왜 바꾸는지"의 기록이다.

2. **A** — 원인을 모르고 고치면 같은 실패를 반복한다.

3. **B** — 검사를 없애면 통과가 아니라 눈 가리기다.

4. **C** — 자동 검사가 모든 문제를 잡지는 않는다.

5. **B** — 검사 없음·로그 읽기·실제 CI 실행은 서로 다른 상태다.
