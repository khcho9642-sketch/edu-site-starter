# [강좌] C12. 스킬·플러그인·연결 — 반복 업무를 저장하는 법

> Claude Desktop 앱 전체 기준 · Windows 중심 · 공식 문서 확인: 2026-11-14
> 실습 화면: Desktop의 Plugins 또는 이전 Customize, Code 심화는 참고 절
> 훅·서브에이전트의 개념은 남기되, 앱 전체에서 같은 설정창이 있다고 가정하지 않습니다.

> 먼저 읽을 강의: C05 · C06.

## 3줄요약

1. 처음에는 화면에서 제공하는 스킬·플러그인을 찾아 작은 자료로 시험한다.
2. 내 절차를 스킬로 저장해도 결과의 정확성과 접근 권한은 따로 확인한다.
3. 훅의 차단 효과는 이벤트·구현·오류 처리에 달려 있다. 모든 위험을 막는 장치가 아니다.

## 1. 기능의 역할 구분

| 필요한 것 | 사용할 수단 |
|---|---|
| 계속 참고할 업무 기준 | 앱의 프로젝트 지침, Code라면 CLAUDE.md |
| 반복할 작업 순서 | 스킬 |
| 계정·서비스 데이터 연결 | 커넥터, 지원되는 MCP 연결 |
| 여러 기능 묶음 | 플러그인 |
| 도구 이벤트에 맞춘 검사 | Code용 훅, 별도 동작 검증 필요 |
| 역할을 나눠 검토 | 별도 검토 작업, 지원되는 Code 서브에이전트 |

## 2. 화면에서 찾아 시험하기

1. 현재 확인한 계정 화면은 **사용자 지정 → Skills / 커넥터 / 플러그인**이다. Plugins 통합 화면 등 다른 배치라면 실제 메뉴를 먼저 확인한다.
2. 상세 설명에서 제공 기능·필요 연결·실행 권한·출처를 읽는다. 조직이 허용하지 않으면 우회 설치하지 않는다.
3. 문서·표 관련 기능이 제공되면 가짜 지출 자료로 한 번만 시험한다.
4. 결과의 거래 수와 합계를 확인한 뒤 계속 사용할지 결정한다.

## 3. 내 지출 정리 스킬을 UI로 등록하기

이미 완성한 [SKILL.md](실습자료/expense-cleanup/SKILL.md)를 제공한다. 이 파일은 교육용 절차이며 프로그램 설치 스크립트나 실제 비밀키를 포함하지 않는다.

1. 사이트에서는 위 링크의 **SKILL.md 파일을 내려받는다.** 탐색기에서 새 `expense-cleanup` 폴더를 만들고 그 안에 파일을 `SKILL.md`라는 이름으로 저장한다. 통합 ZIP을 받은 경우에는 압축을 풀어 `실습자료/expense-cleanup` 폴더를 사용한다.
2. 폴더를 우클릭해 ZIP으로 압축한다. Windows 버전에 따라 **ZIP 파일로 압축**, 또는 **추가 옵션 → 보내기 → 압축(ZIP) 폴더**를 사용한다.
3. ZIP을 열어 `expense-cleanup/SKILL.md`가 들어 있는지 확인한다. 확장자가 `SKILL.md.txt`이면 수정한다.
4. 현재 화면에서는 **사용자 지정 → Skills → 추가**에서 **Skill 업로드 / Skill 만들기 / Claude로 만들기** 중 맞는 경로를 고른다. 직접 만들기는 이름·설명·SKILL.md 절차를 입력하고 만들기를 누른다. 이번 실제 검증은 회의 예제를 직접 만든 경로이며 ZIP 업로드 성공을 확인한 것은 아니다. 업로드를 선택한다면 앞서 만든 ZIP 구조를 확인하고 해당 화면 안내를 따른다.
5. 등록 후 목록에서 활성 상태와 설명을 확인한다.
6. 새 작업에 지출 샘플을 첨부하고 해당 스킬을 선택하거나 “지출 정리 절차로 샘플부터 처리해줘”라고 요청한다.
7. T004 미확정·T005 환불·전체 확정 합계 28,000원을 검수한다. 원하는 스킬이 실제 사용됐는지도 도구·스킬 표시로 확인한다.

업로드 기능이 없으면 SKILL.md 자체를 첨부해 “첨부한 절차에 따라 처리해줘”라고 요청한다. 이 경우 **절차 첨부 실습**이며 스킬 설치 성공이라고 기록하지 않는다.

## 4. 훅과 서브에이전트는 Code 심화로 구분

이 절은 개념 참고다. 실제 Code 작업을 배우는 C14 이후에 다시 읽어도 된다.

훅은 설정된 이벤트에 반응한다. 실행 전 차단 가능한 검사와 실행 후 관찰은 다르다. 일부 오류·시간 초과에서는 동작이 계속될 수 있다. “위험 명령을 막아줘”라는 요청만으로 모든 위험이 차단됐다고 말하면 안 된다.

심화 검증은 가짜 파일과 무해한 시험 동작으로 한다. 설정 위치·이벤트·실행 로그·허용/거부 결과·오류 시 동작을 확인한다. 실제 삭제·송금·비밀 파일로 차단 시험을 하지 않는다.

서브에이전트에 “읽기만”이라고 말하는 것과 수정 도구를 실제로 제한한 것은 다르다. 사용 중인 Code 환경에서 설정을 확인해야 한다. 해당 기능의 설정이 없으면 별도 대화에 자료와 검토 기준을 전달하는 방식으로 검토 연습을 한다.

## 화면 보며 따라 하기

**준비:** expense-cleanup/SKILL.md와 지출 샘플을 준비합니다.

[공통 실습 파일 ZIP 받기](/materials/walkthrough/cd-practice-starter.zip) · ZIP을 모두 푼 뒤 00_먼저읽기.md부터 확인합니다.

**내 화면에서:** 이번 실제 캡처는 Claude 웹의 계정 스킬 화면입니다. 사용자 지정 → Skills → 추가 → Skill 만들기에서 이름·설명·절차를 입력합니다. 계정 스킬과 .claude/skills의 프로젝트 스킬은 구분합니다.

1. SKILL.md의 name·description과 미확정·환불·원본 보존 규칙을 읽습니다.
2. 먼저 절차 파일과 샘플을 함께 전달해 결과를 확인합니다. 실제 등록 UI가 있다면 등록 형식과 활성 상태를 따로 확인합니다.
3. 등록·활성·호출 표시와 28,000원 결과 검수를 각각 기록합니다. 파일을 첨부한 것만으로 설치 성공이라고 적지 않습니다.

**완료 확인**

- T004 미확정·T005 -2,000원·확정 합계 28,000원
- 실제 경로가 절차 첨부인지 스킬 등록인지 구분

**막혔을 때:** 스킬만 실행해서 원문을 못 찾으면 회의 A·B를 명시해 전달합니다. 항목ID와 근거ID도 대조하고 A01/B01처럼 새로 번호를 붙였으면 고칩니다. 스킬 파일 저장·발견·실제 사용·결과 검수는 각각 기록합니다.

### 실제로 막힌 지점과 해결

스킬만 선택해 보내면 회의 원문이 없다는 안내가 나왔습니다. 스킬은 절차를 담고 있으므로, 선택한 뒤 회의 A·B의 원문도 입력하거나 첨부해야 합니다. 여러 줄 입력은 붙여넣기로 하고 **메시지 보내기는 마지막에 한 번만** 누릅니다.

이번 교육용 회의 스킬 이름은 `edu-meeting-actions-demo`입니다. 화면은 회의 예제로 등록·선택·결과 검수를 보여주며, 지출 스킬 자체의 등록 결과라고 바꾸어 읽지 않습니다.

## 숙제

1. 스킬 폴더와 파일명을 확인하고 ZIP에 들어갈 구조를 적는다.
2. 스킬 등록 또는 절차 파일 첨부 중 가능한 경로로 샘플을 처리한다.
3. 훅이 실패했을 때 작업이 계속될 수 있다는 점과 확인해야 할 증거 두 가지를 적는다.

## 확인 퀴즈

4지선다 5문항입니다. 먼저 답을 고른 뒤 아래 해설을 확인하세요.

### Q1. 스킬이 입력 규칙대로 작동했는지 확인하는 기준은?

- A. 미확정·환불·건수·합계를 원본과 대조한다
- B. 스킬 이름이 멋있는지 본다
- C. 완료라는 문구만 본다
- D. 자동 호출됐다고 항상 정확하다고 본다

### Q2. 사용자 지정 스킬의 제공 파일명은?

- A. 아무 폴더의 설명.txt
- B. 계정 비밀번호.txt
- C. 프로젝트 전체 압축만 가능
- D. expense-cleanup 폴더 안의 SKILL.md

### Q3. 업로드 기능이 없을 때의 대체 실습은?

- A. 업로드했다고 말한다
- B. 관계없는 모든 플러그인을 설치한다
- C. 절차 MD를 첨부해 실행하고 설치와 구분해 기록한다
- D. 정책을 우회한다

### Q4. 훅에 대한 올바른 설명은?

- A. 실행 후 훅은 과거 동작을 언제나 취소한다
- B. 이벤트·설정·오류 처리에 따라 차단 여부를 검증해야 한다
- C. 항상 모든 위험을 막는다
- D. 말로 요청하면 설정 검증이 필요 없다

### Q5. 읽기 전용 검토자를 만들었다고 판정하려면?

- A. 실제 사용 도구와 권한 제한도 확인한다
- B. 이름에 리뷰어를 넣으면 끝이다
- C. 읽기만 하라고 한 문장만 있으면 된다
- D. 수정 도구를 전부 자동 허용한다

## 정답과 해설

1. **A** — 절차 재사용과 결과 검증은 별개다.

2. **D** — 제공한 실습용 구조를 그대로 확인하고 확장자도 점검한다.

3. **C** — 학습 목표는 절차 재사용이며 실제 등록 여부는 정확히 보고해야 한다.

4. **B** — 관찰·차단·오류 시 동작을 구분해야 한다.

5. **A** — 역할 지시와 기술적 권한 제한은 다르다.
