# [강좌] C20. 문제 해결 — 안 되는 위치부터 나눠보자

> Claude Desktop 앱 전체 기준 · Windows 중심 · 공식 문서 확인: 2026-11-14
> 실습 화면: 일반 대화·파일 작업·연결 설정·Code 화면별 진단
> 터미널 전용 명령을 기본 해결책으로 제시하지 않습니다.

> 먼저 읽을 강의: 선행 강의 없음. 막히면 순서와 관계없이 수시로 참고합니다.

## 3줄요약

1. 화면·입력·권한·실행·결과 저장 중 어느 단계가 실패했는지 먼저 나눈다.
2. 메뉴가 없으면 버전·플랜·조직 정책·화면 개편을 확인한다.
3. 복구는 파일·대화·외부 동작을 구분하고, 원본과 백업을 기준으로 한다.

## 1. 응급처치 표

| 증상 | 먼저 확인할 것 |
|---|---|
| 메뉴가 안 보임 | 앱 버전, 현재 화면, 계정 지원, Plugins/Customize 개편 여부 |
| 첨부를 읽지 못함 | 파일이 실제 첨부됐는지, 암호·형식·읽기 오류 |
| 로컬 폴더를 못 읽음 | 실제 연결된 폴더·권한·Desktop 실행/연결 상태 |
| 파일을 만들었다는데 안 보임 | 결과 카드·다운로드 여부·실제 저장 경로 |
| 숫자가 다름 | 원본 행 수, 미확정, 환불 부호, 중복, 숫자 형식 |
| 문맥을 잃음 | 기존 대화 또는 C04의 작업 인수인계 메모 |
| 커넥터 조회 실패 | 연결 계정·권한·서비스 상태·조직 정책 |
| 예약이 안 돎 | 실행 위치, 시간대, 실행 기록, 권한·사용량, 로컬 자원 필요 여부 |
| Code 명령이 안 됨 | Desktop에서 지원하는 기능인지 공식 안내와 대조 |
| 파일 변경을 취소하고 싶음 | 변경 내용·복구 범위·원본·Git/별도 백업 확인 |

## 2. 오류를 설명하는 다섯 칸

[지출 샘플](실습자료/01_지출샘플.md)을 사용해 아래 양식을 채운다.

> 사용 화면: 일반 대화 / Cowork / Code 중 실제 화면  
> 하려던 일: 샘플 6건의 집계 파일 만들기  
> 입력 자료: 파일명과 첨부 여부  
> 기대 결과: 확정 합계 28,000원, 미확정 1건  
> 실제 결과: 보인 오류 원문 또는 틀린 결과, 발생 시각

화면 캡처를 보낼 때 이름·메일·키·개인 문서 내용을 가린다. AI가 현재 앱 화면을 자동으로 보고 있다고 가정하지 않는다. 직접 화면 접근은 별도의 기능 지원·설정·허용이 필요하다.

## 3. 잘못된 진단을 피하는 연습

- **오답 A: 32,000원** — T005의 -2,000원을 +2,000원으로 바꾸면 생긴다. 행별 부호를 확인한다.
- **오답 B: 전체 지출 28,000원 확정** — 숫자 자체는 알려진 합계와 같지만 미확정 T004를 숨겼다. 문장과 범위도 고쳐야 한다.
- **오답 C: 예약 실패 = PC 꺼짐** — 클라우드 예약 자체는 PC 없이 실행될 수 있다. 로컬 파일·앱 사용 단계가 실패했는지 실행 기록을 본다.

## 4. 화면별 치트시트

| 목적 | 일반 업무 화면 | Code 화면 |
|---|---|---|
| 새 작업 | 새 대화/새 작업 | 새 세션 |
| 파일 전달 | 첨부 버튼·끌어놓기 | 첨부, 지원되는 @ 선택 |
| 규칙 | 프로젝트 지침·첨부 지침 | 프로젝트 CLAUDE.md 적용 확인 |
| 권한 | 해당 요청의 계정·도구 범위 | 모드 선택기와 실제 권한 설정 |
| 연결 | Plugins 또는 Customize의 연결 관리 | 제공 커넥터와 Code MCP 설정 구분 |
| 결과 검토 | 미리보기·다운로드·실제 파일 열기 | 변경 목록·diff·실행 결과·실제 경로 |

Code의 `/permissions`가 창을 열어준다고 가르치지 않는다. 기본 모드 조작은 화면의 선택기를 사용한다.

## 5. 복구와 확인

되감기·체크포인트가 제공되는 Code 환경에서도 복구 범위를 먼저 확인한다. 파일 내용 변경, 셸 명령으로 한 이동·삭제, DB 변경, 메일 발송은 같은 복구 대상이 아니다. 복구 후 파일을 열고 상태를 확인한다. 비밀키가 노출됐다면 파일을 지우는 것으로 끝내지 말고 해당 서비스에서 키를 폐기·재발급하고 노출 범위를 점검한다.

## 화면 보며 따라 하기

**준비:** 실패 사례 한 개와 원본 자료를 준비합니다.

[공통 실습 파일 ZIP 받기](/materials/walkthrough/cd-practice-starter.zip) · ZIP을 모두 푼 뒤 00_먼저읽기.md부터 확인합니다.

**내 화면에서:** 새 앱 화면·일반 업무·Code 중 어디서 실패했는지 먼저 적습니다.

1. 사용 화면·하려던 일·입력·기대 결과·실제 오류 다섯 칸을 씁니다.
2. 32,000원은 T005 부호, 30,000원은 환불 누락, 28,000원 전체 확정 문장은 T004 누락부터 대조합니다.
3. 고친 뒤 정상 입력과 빈 자료·형식 오류 복사본을 다시 확인하고 실제 실행 범위만 기록합니다.

**완료 확인**

- 32,000→28,000의 원인 설명
- 미확정 1건을 숨기지 않음·원본 보존

**막혔을 때:** 예상 숫자에 맞추려고 원본을 바꾸지 않습니다. 재설치·전체 권한 허용 전에 실패한 위치와 오류 원문부터 좁힙니다.

## 숙제

1. 오류 설명 다섯 칸을 가짜 사례로 채운다.
2. 오답 A·B·C의 원인과 올바른 결과를 적는다.
3. 결과 파일 하나를 실제로 열어 확인하고 미리보기만 본 결과와 구분한다.

## 확인 퀴즈

4지선다 5문항입니다. 먼저 답을 고른 뒤 아래 해설을 확인하세요.

### Q1. 샘플 합계가 32,000원일 때 우선 확인할 것은?

- A. 항상 서버 고장인지
- B. 앱을 먼저 삭제할지
- C. 모델 이름만 바꿀지
- D. T005 환불의 부호가 +로 바뀌었는지

### Q2. 28,000원이 맞아도 보고가 틀릴 수 있는 이유는?

- A. 파일이 예쁘지 않아서
- B. 마이너스 금액은 무조건 오류라서
- C. 미확정 1건을 숨기고 전체 확정이라고 쓸 수 있어서
- D. 합계는 언제나 의미가 없어서

### Q3. 예약 실패의 진단 순서로 적절한 것은?

- A. 결과 없이 성공 처리한다
- B. 실행 위치와 기록, 자료 접근 조건을 나눠 확인한다
- C. 무조건 PC 전원을 켜고 끝낸다
- D. 모든 권한을 무제한 허용한다

### Q4. 화면 위치를 AI에게 물을 때 주의할 것은?

- A. 필요한 화면 정보를 가려서 제공하고 접근 여부를 확인한다
- B. AI가 항상 화면을 보고 있다고 믿는다
- C. 전체 비밀키가 보이도록 보낸다
- D. 다른 계정으로 바꾼다

### Q5. 비밀키가 노출되면?

- A. 파일 이름만 바꾼다
- B. 채팅에서 지우면 끝이다
- C. 다음 달까지 기다린다
- D. 서비스에서 폐기·재발급하고 노출 범위를 점검한다

## 정답과 해설

1. **D** — 환불 -2,000원을 +2,000원으로 바꾸면 4,000원이 늘어 32,000원이 된다.

2. **C** — 수치뿐 아니라 집계 범위와 불확실성도 정확히 표시해야 한다.

3. **B** — 클라우드·로컬·권한·사용량 등 실패 지점을 구분해야 한다.

4. **A** — 실제로 제공된 맥락과 화면 접근 기능을 구분한다.

5. **D** — 복사된 비밀값은 로컬 파일 삭제만으로 회수할 수 없다.
