# [강좌] C14. Code 화면에서 첫 앱 만들기 — 변경 목록과 실행 결과 보기

> Claude Desktop 앱 전체 기준 · Windows 중심 · 공식 문서 확인: 2026-11-14
> 실습 화면: Desktop의 Code, 로컬 연습 폴더
> Code를 사용하는 앱 개발 선택 실습입니다. 사용자에게 터미널 명령 입력을 요구하지 않습니다.

> 먼저 읽을 강의: C02 · C03 · C05 · C06.

## 3줄요약

1. 앱 개발은 Code 화면에서 프로젝트와 실행 환경을 확인하고 시작한다.
2. 계획 → 변경 검토 → 실제 실행 → 오류 입력 검증 순서로 진행한다.
3. Code가 수정한 파일 위치와 실제 브라우저 동작을 함께 확인한다.

## 1. 준비와 오늘의 앱

탐색기로 빈 `Claude_연습/앱연습` 폴더를 만든다. [지출 샘플](실습자료/01_지출샘플.md)을 복사한다. 목표는 외부 서버·계정·DB 없이 가짜 지출 자료를 보여주는 **index.html 한 개**다.

Code가 계정이나 조직 환경에서 제공되지 않으면 이 강의는 설계·검수 기준 작성까지만 진행하고 실행 미검증으로 기록한다. 일반 대화에서 코드 글을 받았다고 Code에서 실행한 것처럼 쓰지 않는다.

## 2. 폴더를 선택하고 계획 받기

1. Desktop의 **Code**를 연다.
2. 새 세션에서 로컬 연습 폴더를 선택한다. 클라우드·SSH 등 다른 환경을 선택한 것은 아닌지 확인한다.
3. 빈 연습 폴더에서는 Worktree를 사용하지 않는 기본 경로로 진행한다. 기존 Git 프로젝트라면 실제 작업 폴더가 어디인지 확인한다.
4. 모드 선택기에서 **Plan**을 고르고 요청한다.

> 첨부 샘플 6건을 보여주는 HTML 파일 하나를 만들 계획을 세워줘. 기능은 거래 표, 확정 합계, 미확정 건수, 카테고리 필터다. 빈 금액을 0으로 확정하지 말고 환불은 음수로 유지해. 외부 라이브러리·서버·로그인·실제 데이터 연결은 사용하지 마. 검증 기준도 적어줘.

5. 계획의 입력·출력·검증이 맞으면 Manual 등 확인하면서 진행하는 모드로 바꿔 구현을 요청한다. 명령 실행 승인이 나오면 목적과 내용을 확인한다.

## 3. 변경 검토와 화면 열기

1. 생성된 `index.html`과 실제 저장 경로를 확인한다.
2. 변경 목록/diff에서 샘플과 관계없는 파일·비밀값·외부 전송 코드가 추가되지 않았는지 검토를 요청하고 설명을 읽는다.
3. 내장 미리보기가 제공되면 화면을 연다. 제공되지 않으면 탐색기에서 index.html을 브라우저로 연다.
4. 미리보기 설정에 실행 명령이 필요하면 Code가 그 목적과 실행 결과를 설명하게 한다. 사용자가 터미널에 명령을 복사하는 것을 필수 단계로 두지 않는다.
5. “작동한다”는 답변뿐 아니라 **직접 화면에서 표·필터·합계**를 확인한다.

## 4. 예상 결과

- 전체: 6행, 확정 합계 **28,000원**, 금액 미확정 **1건**.
- 식비 필터: T001·T005 두 행, 합계 **10,000원**.
- 기타 필터: T004 한 행, 금액 **미확정**. 총액이 확정 0원이라고 오해하게 표시하지 않는다.
- 환불 T005는 -2,000원, 빈 값은 미확정으로 표시.
- 외부 서비스 없이 연습 자료로 동작.

**선택 추가 검수 — 빈 자료와 형식 오류**

정상 `index.html`은 그대로 둔다. 별도 검수용 복사본에서만 아래 입력을 시험해 달라고 요청하고 직접 화면을 연다. 원본 CSV와 정상 앱의 데이터를 덮어쓰지 않는다.

| 검수용 복사본 | 바꿀 입력 | 기대 결과 |
|---|---|---|
| `검수/빈자료.html` | 거래 목록을 빈 목록으로 제공 | 자료 없음·거래 0건 표시. 정상 샘플 28,000원을 그대로 재사용하지 않음 |
| `검수/형식오류.html` | T004의 빈 금액을 교육용 문자열 `확인중`으로 바꾼 복사본 | T004는 형식 확인필요·미확정. 임의의 0원으로 확정하지 않고 나머지 5건의 확인 합계는 28,000원 |

```text
정상 index.html과 입력 원본은 보존해줘.
검수 폴더의 복사본 두 개에만 위 시험 입력을 적용해줘.
입력별 예상 상태와 실제 화면 결과를 비교하고, 못 실행했으면 미검증으로 써줘.
마지막에 정상 앱의 6행·28,000원·미확정 1건도 다시 확인해줘.
```

## 5. 작은 수정과 재검증

제목만 바꾸도록 요청하고 변경 목록을 본다. 제목 외의 계산 코드까지 바뀌면 이유를 확인한다. 수정 뒤에도 전체·식비·기타 필터를 다시 시험한다. 되감기 기능이 제공돼도 파일 이동·삭제·DB 변경·외부 발송까지 복구해준다고 가정하지 않는다.

## 화면 보며 따라 하기

**준비:** 빈 앱연습 폴더와 지출 샘플을 준비합니다.

[공통 실습 파일 ZIP 받기](/materials/walkthrough/cd-practice-starter.zip) · ZIP을 모두 푼 뒤 00_먼저읽기.md부터 확인합니다.

**내 화면에서:** Code에서 만든 파일의 경로와 브라우저 화면을 함께 확인합니다.

1. 개발 화면에서 로컬 연습 폴더를 선택하고 index.html 한 개를 만들 계획부터 읽습니다.
2. 변경 파일과 실제 경로를 확인한 뒤 index.html을 브라우저로 엽니다. 참고 예제를 쓴 경우 직접 생성한 앱과 구분해 기록합니다.
3. 전체 → 식비 → 기타 필터를 하나씩 누르고 숫자를 확인합니다. 검수용 복사본에서 빈 자료와 확인중 문자열도 시험합니다.

**완료 확인**

- 전체 6행·28,000원·미확정 1건
- 식비 2행·10,000원 / 기타 T004·미확정
- 빈 자료: 0건·자료 없음 / 형식 오류: T004 미확정 유지

**막혔을 때:** 파일이 index.html.txt이면 확장자부터 확인합니다. 단일 HTML 예제에 npm·DB·서버 설치를 추가할 필요는 없습니다. 참고 예제의 검수 입력 선택은 화면 복사본만 바꾸며 실제 CSV를 덮어쓰지 않습니다.

## 숙제

1. index.html의 실제 경로와 화면을 확인한다.
2. 전체·식비·기타 필터의 결과를 기대값과 대조한다.
3. 제목 변경 뒤 계산 결과가 유지되는지 재검증한다. 실행하지 못했다면 그 이유를 적는다.

## 확인 퀴즈

4지선다 5문항입니다. 먼저 답을 고른 뒤 아래 해설을 확인하세요.

### Q1. 이번 앱의 기본 구조는?

- A. 메일 자동 발송 서버 필수
- B. 유료 외부 API 필수
- C. 외부 연결 없는 index.html 한 개
- D. 운영 DB와 실제 카드 계정 필수

### Q2. 식비 필터의 기대 결과는?

- A. 6행, 28,000원
- B. 2행, 확정 합계 10,000원
- C. 1행, 12,000원
- D. 2행, 14,000원

### Q3. 기타 필터의 T004 금액은?

- A. 미확정으로 표시한다
- B. 0원 확정으로 표시한다
- C. 임의 평균으로 표시한다
- D. 항상 숨긴다

### Q4. 제목만 수정한 뒤에도 확인할 것은?

- A. 제목 색만
- B. 파일명 길이만
- C. 모델을 바꿨는지만
- D. 기존 합계와 필터 동작이 유지되는지

### Q5. 일반 대화에서 HTML 코드를 받기만 했다면?

- A. Code 세션이 자동 생성됐다
- B. 운영 배포가 완료됐다
- C. 실제 저장·실행 여부는 별도로 확인해야 한다
- D. 앱 테스트까지 모두 끝난 것이다

## 정답과 해설

1. **C** — 실습 범위를 줄여 화면과 검증에 집중한다.

2. **B** — T001의 12,000원과 T005의 환불 -2,000원을 합친다.

3. **A** — 빈 금액은 알려진 0원과 다르다.

4. **D** — 작은 수정도 기존 기능에 영향을 주지 않았는지 확인한다.

5. **C** — 코드 응답·파일 저장·실행·배포는 각각 다른 단계다.
