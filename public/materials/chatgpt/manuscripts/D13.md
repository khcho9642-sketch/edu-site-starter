# [강좌] D13. 예약 작업 — 어디서 돌고 무엇을 읽는지 확인하기

> ChatGPT 일반 업무 · 앱/웹 · Windows 중심 · 공식 확인: 2026-11-14
> 먼저 읽을 강의: D03 · D06 · D09.

## 3줄요약

1. 수동 결과를 검증한 후 같은 기준으로 예약한다.
2. 클라우드 실행과 내 PC 파일·앱 접근의 조건을 따로 확인한다.
3. 실행 위치·시간대·입력 자료·결과·중지 방법까지 확인해야 예약을 이해한 것이다.

## 1. 예약 전에 수동 결과 확인

[지출 샘플](/chatgpt-materials/expenses)만 사용한다. 다음 요청을 세 번 수동으로 실행하고 결과가 일치하는지 확인한다.

> 이 연습 자료의 거래 수, 확정 금액 합계, 미확정 거래 ID, 환불 거래 ID를 표로 정리해줘. 새 메일 조회나 외부 발송은 하지 마. 원본을 수정하지 말고 보고 초안만 만들어줘.

세 번 모두 **6건 / 확정 5건 28,000원 / T004 / T005**가 나오는지 기록한다. 한 번이라도 틀리면 예약 전에 요청과 자료를 고친다.

## 2. 실행 위치와 입력 자료 확인

| 종류 | 먼저 확인 |
|---|---|
| ChatGPT 웹 예약 | 저장된 작업의 입력·업로드 자료·연결 도구가 실제 접근 가능한가 |
| 데스크톱 로컬 예약 | 프로젝트 위치, PC·앱 실행 상태, 입력 파일 접근이 가능한가 |
| Worktree 작업 | 원래 폴더가 아닌 분리한 Git 작업 복사본의 입력인가 |
| 클라우드 작업에서 로컬 자원 사용 | 해당 기능의 로컬 접근 지원·연결 조건을 따로 확인했는가 |

현재 대화에 첨부한 자료가 다음 예약에 자동 전달된다고 가정하지 않는다. 복사본과 실제 로컬 파일의 갱신 방식도 확인한다. 지원 범위가 불분명하면 명세 작성까지만 한다.

## 3. 화면에서 등록해보기

1. ChatGPT 웹 또는 데스크톱에서 현재 제공되는 **Scheduled / 예약 작업**을 확인한다. 기능이 없으면 명세 작성 대체 실습을 선택한다.
2. 새 작업에서 지시문, 사용할 자료, 반복 주기, 시간대를 확인한다. UI 대신 자연어로 생성했다면 저장된 작업 상세를 다시 연다.
3. 연습 주기는 **매주 금요일 16:00, Asia/Seoul**로 설정하고 다음 실행 시각이 기대와 맞는지 읽는다.
4. 샘플이 예약 작업에서 읽을 수 있는 입력으로 실제 지정됐는지 확인한다. 로컬 파일을 쓰지 않는 연습으로 먼저 시작한다.
5. 즉시 실행/Run now가 제공되면 한 번 시험한다. 없다면 수동 결과만 확인했다고 기록하고 다음 실제 실행은 미검증으로 남긴다.
6. 실행 기록과 결과를 열어 자료의 이름·합계·미확정 표시가 맞는지 확인한다.
7. 실습 후 **일시중지·비활성화 또는 삭제**해서 의도하지 않은 반복 실행을 남기지 않는다. 실제 중지 상태를 확인한다.

예약 기능이 없거나 사용하지 않으려면 `예약작업_명세.md`에 위 필드를 작성하는 대체 실습으로 진행한다. 이 경우 예약을 등록하거나 실행한 것으로 표시하지 않는다.

## 4. 예상 결과와 실패 진단

기록에는 작업 이름, 실행 위치, 입력, 시간대, 다음 실행, 실제 실행 결과, 종료/중지 상태가 있어야 한다. 실패했으면 PC 전원만 확인하지 말고 작업 기록의 오류, 파일 가용성, 인증, 사용량, 조직 정책을 구분한다. 원본 파일 내용이 바뀐 경우 예약이 어느 버전의 자료를 읽었는지도 확인한다.

다음 표를 `예약작업_명세.md`에 복사해 빈칸을 채운다. 실제 등록하지 않은 항목은 `미등록`, 시험하지 않은 항목은 `미검증`으로 남긴다.

| 항목 | 내 기록 |
|---|---|
| 작업 이름·실행 위치 | 직접 입력 / 화면에서 확인 또는 미검증 |
| 입력 자료·버전·접근 방법 | 가짜 지출 샘플 6건 / 첨부·계정 파일 등 실제 방법 |
| 반복·시간대 | 매주 금요일 16:00 / Asia/Seoul |
| 다음 실행 시각 | 작업 상세에서 확인 또는 미등록 |
| 기대 결과 | 6건 / 확정 5건 28,000원 / T004 미확정 / T005 환불 |
| 수동 검수 1·2·3회 | 각 결과와 기준 일치 여부 |
| 실제 예약 실행·기록 위치 | 실행 결과와 기록 위치 또는 미수행 |
| 중지·삭제 상태 | 실제 확인한 상태 또는 등록 안 함 |

## 화면 보며 따라 하기

**준비:** 지출 샘플과 예약작업_명세.md를 준비합니다.

[공통 실습 파일 ZIP 받기](/materials/walkthrough/cd-practice-starter.zip) · ZIP을 모두 푼 뒤 00_먼저읽기.md부터 확인합니다.

**내 화면에서:** 웹 예약은 PC 폴더를 직접 쓰는 로컬 예약과 다릅니다. 로컬 예약에는 PC·앱 실행 상태도 필요합니다.

1. 같은 입력으로 수동 결과를 세 번 확인하고 각 실제 결과를 적습니다. 한 번만 했다면 세 번 성공이라고 적지 않습니다.
2. 예약 명세에 실행 위치·입력 버전·금요일 16:00·Asia/Seoul·결과 위치·중지 방법을 씁니다.
3. 등록을 선택한 경우에만 저장된 상세와 다음 실행 시각을 읽고 실행 기록을 확인합니다. 기본 실습은 명세 작성으로 끝낼 수 있습니다.

**완료 확인**

- 6건·확정 5건 28,000원·T004·T005
- 미등록·미실행·미검증을 구분한 명세

**막혔을 때:** 현재 대화의 첨부가 예약에도 자동 전달된다고 생각하지 마세요. 클라우드 실행과 내 PC 파일 접근 조건을 따로 확인합니다.

## 숙제

1. 수동 결과 세 번과 정답 기준을 대조한다.
2. 예약 등록 또는 명세 작성 중 수행한 경로를 정확히 기록한다.
3. 등록했다면 중지 상태를 확인하고, 다음 실제 실행을 관찰했는지 구분한다.

## 확인 퀴즈

4지선다 5문항입니다. 먼저 답을 고른 뒤 아래 해설을 확인하세요.

### Q1. 클라우드 예약에 대한 올바른 설명은?

- A. PC가 꺼지면 모든 클라우드 예약이 실패한다
- B. 내 PC 모든 파일을 언제나 읽는다
- C. 권한·자료 확인이 필요 없다
- D. PC 없이 실행될 수 있지만 로컬 자원 접근에는 별도 조건이 있다

### Q2. 한국 시각 금요일 오후 4시를 설정할 때 함께 볼 것은?

- A. 파일 색상
- B. 브라우저 배경
- C. Asia/Seoul 시간대와 다음 실행 시각
- D. 모델 이름만

### Q3. 예약 전에 수동 결과가 틀렸다면?

- A. 오류를 숨긴다
- B. 자료와 지시문을 고쳐 재검증한다
- C. 자동화하면 저절로 정확해진다
- D. 먼저 모든 승인을 없앤다

### Q4. 작업 명세만 작성했을 때 올바른 기록은?

- A. 예약 등록·실행은 하지 않았다고 적는다
- B. 예약 실행 성공이라고 적는다
- C. 반복 작업이 이미 켜졌다고 적는다
- D. 외부 발송 완료라고 적는다

### Q5. 연습용 예약을 시험한 뒤에는?

- A. 무조건 계속 켜둔다
- B. 계정 연결을 더 늘린다
- C. 실행 기록을 보지 않는다
- D. 일시중지·삭제 등 실제 종료 상태를 확인한다

## 정답과 해설

1. **D** — 실행 위치와 로컬 파일·앱의 가용성은 구분해야 한다.

2. **C** — 시간대가 다르면 같은 시각 표시라도 실행 시간이 달라진다.

3. **B** — 틀린 작업을 반복 예약하면 오류도 반복된다.

4. **A** — 계획 문서와 실제 등록·실행은 다른 상태다.

5. **D** — 의도하지 않은 반복 실행과 사용량 소비를 남기지 않는다.
