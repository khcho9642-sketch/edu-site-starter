# [강좌] D22. 스킬 — 같은 설명 세 번 했다면 저장하자

> Codex 앱 선택 심화 · Windows 중심 · 공식 확인: 2026-11-14
> 먼저 읽을 강의: D05 · D12 · D14. 일반 업무 활용만 필요하면 선택해서 읽어도 됩니다.

## 3줄요약

1. 스킬은 반복 업무의 입력·순서·출력·금지·완료 기준을 담는다.
2. 이번 Codex 프로젝트에서는 .agents/skills 아래 SKILL.md로 만든다.
3. 명시적으로 선택한 스킬과 실제 사용 흔적, 결과 검수를 구분한다.

## 1. 오늘 만드는 것

회의 메모의 실행·보류·담당·기한을 정리하는 `meeting-actions` 절차를 쓴다. 입력과 정답은 클로드 C22의 회의 A·B를 그대로 재사용한다.

| 구분 | 이번 경로 |
|---|---|
| 프로젝트 공통 기준 | Codex의 AGENTS.md |
| 반복할 작업 절차 | meeting-actions/SKILL.md |
| 결과 검수 | 원문의 근거ID와 실제 출력 대조 |

Claude의 `.claude/skills` 위치와 호출용 슬래시 명령을 복사하지 않는다. 일반 ChatGPT에서 절차 파일을 첨부하는 것은 Codex 프로젝트 스킬 등록과 구분한다.

## 2. 준비물과 입력

1. 탐색기로 `Documents/AI_연습/확장기능` 연습 폴더를 준비한다.
2. Codex 앱에서 로컬 프로젝트로 선택하고 실제 작업 위치를 확인한다.
3. [공통 샘플](/chatgpt-materials/extensions)의 회의 A·B를 `입력/회의A.md`, `입력/회의B.md`로 각각 저장한다.
4. 파일 생성 권한을 확인한다. 개인 전역 스킬이나 회사 프로젝트는 변경하지 않는다. 기본 흐름은 앱에 말로 요청하며 터미널 입력은 필수가 아니다.

## 3. 먼저 한 번 수동으로 해보기

Codex 앱에서 연습 프로젝트를 선택한 뒤 입력창에 붙여 넣는다.

```text
입력/회의A.md에서 실행할 일만 표로 정리해줘.
열은 항목ID, 할 일, 담당자, 기한, 상태, 근거ID로 해줘.
담당자·기한이 없으면 '미정'으로 적고 추정하지 마.
논의만 한 내용과 보류한 내용은 실행할 일에 섞지 말고 별도 표로 적어줘.
출력/회의A_수동.md에 저장하고 원본은 수정하지 마.
```

예상 결과는 실행할 일 3개, 보류 1개다. **담당자가 미정인 M02에 수진·지민 등을 임의로 배정하면 오류**다. 반대로 M03의 장소 후보 비교 담당자는 원문에 지민으로 명시돼 있으므로 그대로 유지한다. AI가 만든 그럴듯한 표보다 원문 한 줄이 우선이다.

## 4. 절차를 스킬로 저장하기

먼저 [제품 중립 절차](/materials/chatgpt/examples/meeting-actions/SKILL.md)를 읽는다. 다음을 Codex에 요청한다.

```text
이 연습 프로젝트에 회의 메모 정리 스킬 초안을 만들어줘.
위치는 .agents/skills/meeting-actions/SKILL.md로 해줘.
참고한 절차의 입력·출력·미정·보류 규칙을 유지해줘.
기존 같은 이름 파일이 있으면 먼저 내용을 비교하고 덮어쓰지 마.
name과 description, 실제 파일 경로와 전체 내용을 보여줘.
외부 연결이나 개인 전역 설정은 바꾸지 마.
```

SKILL.md에는 name·description과 작업 절차를 둔다. 이번 예시에는 Claude 전용 `argument-hint`, `$ARGUMENTS`, `disable-model-invocation`을 넣지 않는다. 입력 경로는 실제 요청에 명시한다. 스킬 생성과 현재 세션의 인식은 따로 확인한다.

공유 절차의 핵심은 원문 근거ID, 실행/보류 구분, 담당·기한 미정 유지, 결과 별도 저장이다. 설치했다는 말만으로 적용 완료로 판정하지 않는다.

## 5. 같은 자료와 다른 자료에 적용하기

현재 앱의 Skills 목록이나 제공되는 선택 UI에서 `meeting-actions`가 있는지 확인한다. 명시 선택이 가능하면 선택하고 입력 경로를 적는다.

```text
meeting-actions 스킬을 사용해 입력/회의A.md를 정리해줘.
어떤 스킬을 실제 사용했는지 표시하고, 출력/회의A_스킬.md에 결과를 저장해줘.
원본은 변경하지 마.
```

회의 B에도 같은 요청을 하되 경로와 결과 파일명을 바꾼다. A의 담당자·기한을 B에 복사하지 않는다.

목록에 없으면 폴더·파일명과 현재 세션의 스킬 발견 상태를 확인한다. 여전히 안 되면 SKILL.md를 직접 첨부해 실행하되 **절차 첨부, 스킬 호출 미확인**으로 기록한다. Codex CLI 전용 `/skills` 또는 `$` 입력을 앱의 필수 조작이라고 가르치지 않는다.

## 6. 예상 결과와 검수

| 검수 항목 | 회의 A | 회의 B |
|---|---:|---:|
| 실행할 일 | 3개 | 2개 |
| 실행할 일 중 담당자 미정 | 1개 | 0개 |
| 실행할 일 중 기한 미정 | 1개 | 1개 |
| 보류 | 1개 | 1개 |

`출력/스킬_검수.md`에 입력 경로, 스킬 경로, 호출 확인 여부, 예상값과 실제값을 적는다. 수동 결과와 스킬 결과의 문장이 달라도 괜찮다. 분류·건수·근거가 같아야 한다.

## 7. 막혔을 때

| 증상 | 확인 |
|---|---|
| 스킬을 못 찾음 | 선택한 프로젝트 아래 .agents/skills/meeting-actions/SKILL.md와 메타데이터 |
| 다른 회의가 섞임 | 요청한 입력 경로와 실제 읽은 파일 |
| 담당·기한을 채움 | 원문 항목ID와 미정 유지 규칙 |
| 호출 표시가 없음 | 실제 사용 증거가 없으면 미확인으로 기록 |
| 저장 결과가 없음 | 실제 파일 경로와 출력 내용 |

사용자 지침으로 자동 호출을 확실히 차단했다고 주장하지 않는다. 한 번 쓰는 요청을 모두 스킬로 만들 필요는 없다.

## 화면 보며 따라 하기

**준비:** ZIP의 회의A.md·회의B.md를 각각 준비합니다.

[공통 실습 파일 ZIP 받기](/materials/walkthrough/cd-practice-starter.zip) · ZIP을 모두 푼 뒤 00_먼저읽기.md부터 확인합니다.

**내 화면에서:** Codex 프로젝트 위치는 .agents/skills/meeting-actions/SKILL.md입니다. Claude의 $ARGUMENTS 등 전용 설정을 복사하지 않습니다.

1. 수동으로 회의 A를 정리해 실행 3개·보류 1개를 먼저 확인합니다.
2. 프로젝트용 SKILL.md를 올바른 제품 경로에 만들고 name·description·입출력·미정·보류 규칙을 확인합니다.
3. 실제 호출이 확인된 경우에만 스킬 사용으로 기록합니다. 목록에 없으면 절차 파일 첨부로 A·B를 처리하고 수행 경로를 적습니다.

**완료 확인**

- 회의 A: 실행 3 / 담당 미정 1 / 기한 미정 1 / 보류 1
- 회의 B: 실행 2 / 담당 미정 0 / 기한 미정 1 / 보류 1
- 항목ID·근거ID 모두 M01~M04 / N01~N03 원문 그대로 유지

**막혔을 때:** 스킬만 실행해서 원문을 못 찾으면 회의 A·B를 명시해 전달합니다. 항목ID와 근거ID도 대조하고 A01/B01처럼 새로 번호를 붙였으면 고칩니다. 스킬 파일 저장·발견·실제 사용·결과 검수는 각각 기록합니다.

### 실제 예약 실행에서 발견한 오류

원문의 `M01`을 결과의 항목ID에서 `A01`로, `N01`을 `B01`로 바꾸는 문제가 있었습니다. 근거ID가 맞아도 항목ID 변경을 놓치면 안 됩니다. 스킬에 **항목ID와 근거ID 모두 원문 ID를 그대로 유지**한다는 규칙을 추가했습니다.

원래 예약 출력과 수동 재검수 파일을 따로 보존했습니다. 예약이 실행됐다는 사실과 수정된 스킬의 재실행 검증은 구분합니다. 일반 ChatGPT의 절차 첨부와 이번 Codex 로컬 스킬 발견·읽기도 다른 경로입니다.

## 숙제

1. 주간 보고 또는 파일 검토 중 하나를 골라 입력·순서·출력·금지·완료 기준을 적는다.
2. 서로 다른 샘플 두 개에서 확인할 예상 결과를 먼저 정한다.
3. 스킬 호출 여부와 결과 검수를 분리해 기록한다.

## 확인 퀴즈

4지선다 5문항입니다. 먼저 답을 고른 뒤 아래 해설을 확인하세요.

### Q1. 스킬로 저장하기 가장 적합한 것은?

- A. 한 번만 하는 인사말 작성
- B. 반복하는 회의 메모 정리 절차
- C. 계정 비밀번호
- D. AI의 모든 답변을 정확하게 만드는 규칙

### Q2. 이번 Codex 프로젝트 스킬 파일 위치는?

- A. .agents/skills/meeting-actions/SKILL.md
- B. 아무 폴더의 설명.txt
- C. 운영 DB 비밀번호 파일
- D. 브라우저 방문 기록

### Q3. 스킬이 담당자를 임의로 채우거나 항목ID를 바꿨다면?

- A. 표가 예쁘면 통과
- B. 호출됐으므로 통과
- C. 원문과 대조해 실패를 기록하고 절차를 보완한다
- D. 담당자를 원문에 추가한다

### Q4. 이 교재의 Codex 스킬로 옮길 때 적절한 방법은?

- A. Claude의 모든 설정 필드를 그대로 복사
- B. 파일 수정 권한이 자동 차단됐다고 선언
- C. 무료 사용을 보장
- D. name·description과 절차를 확인하고 제품 전용 호출 필드는 따로 검토

### Q5. 목록에서 스킬을 찾지 못해 SKILL.md를 첨부했다면?

- A. 스킬 설치·호출 성공으로 기록
- B. 절차 파일 첨부로 실행했다고 기록
- C. 다른 계정의 스킬이 실행됐다고 추정
- D. 결과 검수 생략

## 정답과 해설

1. **B** — 반복해서 검증한 절차를 저장해야 재사용 효과가 있다.

2. **A** — 현재 선택한 프로젝트 아래의 공식 스킬 발견 경로를 확인한다.

3. **C** — 스킬 실행과 결과의 정확성은 별개다.

4. **D** — 제품 공통 절차와 제품별 등록·호출 설정을 구분한다.

5. **B** — 실제 수행한 방법과 확인하지 못한 기능을 구분해 기록한다.
