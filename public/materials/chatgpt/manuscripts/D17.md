# [강좌] D17. 말로 커밋·푸시 — 올리기 전에 목록부터

> Codex 앱 선택 심화 · Windows 중심 · 공식 확인: 2026-11-14
> 먼저 읽을 강의: D14 · D15 · D16.

## 3줄요약

1. 올리기 전에 **"무엇이 올라가는지 목록부터"** 받는다.
2. `.env`·개인 자료는 **`.gitignore`로 제외**하고, 제외됐는지 직접 확인한다.
3. 푸시 완료 증거는 **GitHub 웹에 파일이 보이는 것**이다.

## 1. 준비와 오늘의 결과

[GitHub 연습 안내](/chatgpt-materials/github)를 확인한다. D15에서 README를 넣어 만든 원격 저장소는 **먼저 복제(clone)한 뒤** 가짜 실습 파일을 추가한다. 오늘 결과는 **확인한 연습 저장소로 푸시 1회 + `.gitignore`**다.

## 2. Codex 앱에서 복제한 프로젝트 열기

1. GitHub 웹의 본인 비공개 연습 저장소에서 **Code → HTTPS 주소 복사**로 저장소 주소를 확인한다. 이 Code는 GitHub의 버튼 이름이다.
2. Codex 앱에서 상위 연습 폴더를 로컬 작업으로 열고 해당 주소를 `my-gagyebu-practice`에 복제하도록 요청한다. 이미 폴더가 있으면 덮어쓰지 말고 Git 연결 상태부터 확인한다.
3. 복제한 폴더를 작업 프로젝트로 열어 원격 README가 로컬에 있는지 확인한 다음 가짜 파일을 추가한다.
4. 현재 대화의 권한 상태와 실제 변경 범위를 확인한다. 인증은 공식 창에서 사용자가 직접 한다.
5. 먼저 상태만 묻는다.

> 이 폴더가 Git 저장소인지, 연결된 GitHub 저장소가 있는지 확인만 해줘. 아직 아무것도 바꾸지 마.

## 3. 제외 목록 → 커밋 → 푸시

1. 제외 규칙부터 만든다.

> `.gitignore`를 만들어서 `.env`와 `개인자료/` 폴더를 제외해줘. 만든 뒤 내용 보여줘.

2. 올라갈 목록을 받는다.

> 지금 커밋하면 포함될 파일 목록과 `.env`·`개인자료/`의 기존 Git 추적 여부를 확인해줘. 둘 중 하나가 커밋 예정 목록에 있거나 이미 추적 중이면 멈추고 상태만 설명해줘. 아직 커밋·푸시하지 마.

`.gitignore`는 새로 추적하지 않을 파일을 정하는 규칙이다. 이미 추적 중인 파일이나 과거 커밋의 비밀값은 이 파일을 작성하는 것만으로 사라지지 않는다. 실제 비밀값을 이미 올렸다면 D16의 폐기·재발급 대응부터 하고, 이번 수업의 가짜 파일과 구분한다.

3. 목록이 맞으면 커밋한다. 메시지는 내용이 드러나게 쓴다.

> 이 목록으로 커밋해줘. 메시지는 "가계부 연습 첫 파일과 제외 규칙 추가".

4. GitHub의 `my-gagyebu-practice`(Private)에 연결하고 푸시해 달라고 한다. **로그인·인증 창이 뜨면 내가 직접** 처리한다.

> 이 폴더를 GitHub의 my-gagyebu-practice 비공개 저장소에 연결하고 푸시해줘. 인증이 필요하면 멈추고 나한테 알려줘.

| 참고: 터미널로 하면 | |
|---|---|
| 상태 보기 · 커밋 · 올리기 | `git status` · `git commit` · `git push` |

## 4. 주의 사항

- 커밋 전에 **포함 파일 목록**을 반드시 받는다.
- 토큰·비밀번호를 채팅에 붙여넣지 않는다. 인증은 GitHub가 띄우는 로그인 창에서 직접 한다.
- 원격 저장소가 **Private인지** 푸시 전에 한 번 더 본다.
- AI가 "푸시했습니다"라고 해도 **GitHub 웹에서 파일 목록**을 확인해야 완료다.

## 5. 이렇게는 쓰지 말자

| ❌ 이렇게 하지 말자 | ✅ 대신 이렇게 | 이유 |
|---|---|---|
| "전부 올려줘" | "올라갈 목록 먼저 보여줘" | 비밀 파일이 섞여도 모른다 |
| 커밋 메시지 "수정", "ㅇㅇ" | "제외 규칙 추가"처럼 무엇을 바꿨는지 | 나중에 되돌릴 지점을 못 찾는다 |
| 인증 에러가 나서 토큰을 채팅에 붙여넣기 | 로그인 창에서 직접 인증 | 토큰이 대화 기록에 남는다 |
| `.gitignore` 만들었다는 말만 믿기 | GitHub 웹에서 `.env`가 없는지 확인 | 이미 커밋된 파일은 나중에 제외해도 기록에 남는다 |
| 넓은 접근 모드로 확인 없이 한 번에 끝내기 | 현재 권한과 변경·실행 범위를 확인 | 무엇이 실행됐는지 놓친다 |

## 6. 확인 방법과 막혔을 때

- GitHub 웹 저장소 화면에 `README.md`, `지출샘플.csv`, `메모.md`, `.gitignore`가 보이고 **`.env`와 `개인자료/`는 없어야** 한다.
- `.env`가 이미 올라갔다면 D16의 사고 대응을 따른다. 파일만 지우고 끝내지 않는다.
- 인증이 계속 실패하면 어떤 화면이 떴는지(문구만) AI에게 말하고, 공식 인증 안내를 따른다. 브라우저 로그인과 Codex가 실행하는 Git 인증은 별개일 수 있다.
- 원격 기록과 다르다는 이유로 푸시가 거부되면 원격 변경부터 확인한다. 새 로컬 기록으로 강제 덮어쓰지 않는다. D15에서 만든 README가 있으므로 처음부터 복제하는 흐름을 따른다.

## 화면 보며 따라 하기

**준비:** README가 있는 연습 저장소 주소와 가짜 파일을 준비합니다.

[공통 실습 파일 ZIP 받기](/materials/walkthrough/cd-practice-starter.zip) · ZIP을 모두 푼 뒤 00_먼저읽기.md부터 확인합니다.

**내 화면에서:** Codex의 Local/Worktree 위치를 확인합니다. 파일 목록과 실제 인증 방식은 따로 봅니다.

1. 빈 폴더를 임의로 같은 원격에 연결하지 말고 원격 저장소부터 복제합니다. 이미 폴더가 있으면 상태만 먼저 확인합니다.
2. .gitignore를 만든 뒤 .env·개인자료의 추적 여부와 커밋 예정 파일 목록을 받습니다.
3. 목록을 확인한 뒤 커밋·푸시합니다. 원격에서 파일과 최신 기록을 다시 확인하고 실제 GitHub 푸시인지 로컬 원격 시험인지 구분합니다.

**완료 확인**

- 포함할 파일과 제외할 파일이 분리됨
- 비밀 파일 미포함·원격 파일 목록 직접 확인

**막혔을 때:** 푸시가 거부되면 원격 README와 로컬 기록 차이를 확인합니다. 강제 푸시를 먼저 쓰지 않습니다. 브라우저 로그인만으로 Git 인증이 끝난다고 가정하지 마세요.

![따라 하기 화면](/materials/walkthrough/screens/git-check.png)

**이번 검토에서 확인한 범위:** 그림은 가짜 로컬 저장소와 로컬 bare 원격을 사용한 Git 시험입니다. GitHub 인증·푸시 성공 화면과 구분합니다.

## 숙제

1. `.gitignore` 작성 후 포함 파일 목록을 받는다.
2. 내용이 드러나는 메시지로 첫 커밋 후 푸시한다.
3. GitHub 웹에서 `.env`와 `개인자료/`가 없는지 확인하고 결과를 메모한다.

## 확인 퀴즈

4지선다 5문항입니다. 먼저 답을 고른 뒤 아래 해설을 확인하세요.

### Q1. 커밋 전에 꼭 받을 것은?

- A. 칭찬
- B. 요금표
- C. 포함될 파일 목록
- D. 다른 저장소 이름

### Q2. `.env`를 GitHub에 올리지 않으려면?

- A. 파일 이름을 바꾼다
- B. `.gitignore`에 넣고 커밋 전 추적 여부·포함 목록을 확인한 뒤 웹에서도 대조한다
- C. 저장소를 Public으로 바꾼다
- D. 커밋 메시지에 "올리지 마"라고 쓴다

### Q3. 인증 에러가 났을 때 올바른 행동은?

- A. 로그인 창에서 직접 인증한다
- B. 토큰을 채팅에 붙여넣는다
- C. 비밀번호를 커밋 메시지에 쓴다
- D. 다른 사람 계정을 빌린다

### Q4. 좋은 커밋 메시지는?

- A. "수정"
- B. "ㅇㅇ"
- C. 빈 메시지
- D. "가계부 연습 첫 파일과 제외 규칙 추가"

### Q5. 푸시 완료의 증거는?

- A. AI가 완료라고 말함
- B. GitHub 웹에서 파일 목록을 직접 확인함
- C. 앱을 닫음
- D. 폴더 이름을 바꿈

## 정답과 해설

1. **C** — 무엇이 올라가는지 모르면 사고가 나도 모른다.

2. **B** — 이미 추적 중인 파일은 제외 규칙만으로 빠지지 않는다. 커밋 전에 멈춰 확인하고, 실제 비밀값이 과거에 올라갔다면 D16의 사고 대응을 따른다.

3. **A** — 인증 정보는 대화에 남기지 않는다.

4. **D** — 무엇을 바꿨는지 드러나야 나중에 찾을 수 있다.

5. **B** — 결과를 직접 보는 것이 완료 증거다.
