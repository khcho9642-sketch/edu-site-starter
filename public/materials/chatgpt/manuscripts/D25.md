# [강좌] D25. MCP·커넥터 — 연결하고, 범위를 확인하고, 끊는 데까지

> Codex 앱 선택 심화 · Windows 중심 · 공식 확인: 2026-11-14
> 먼저 읽을 강의: D08 · D12 · D14 · D24.

## 3줄요약

1. 커넥터는 외부 서비스 연결 기능이고 MCP는 이런 도구 연결에 쓰이는 표준이다.
2. ChatGPT 웹·앱과 Codex 로컬·클라우드의 연결·인증 범위를 구분한다.
3. 조회·변경·발송과 연결 해제·제공자 인증 폐기를 각각 확인한다.

## 1. 외부 연결이 필요한 순간

파일을 첨부하면 그 시점의 복사본을 읽는다. 외부 서비스 연결은 권한이 허용하는 실제 서비스의 데이터를 조회하거나 변경할 수 있다. 편한 만큼 **어떤 계정에서 무엇을 할 수 있는지**를 알아야 한다.

| 필요한 일 | 먼저 고를 방법 |
|---|---|
| 가짜 회의 메모 한 번 요약 | 파일 첨부 |
| 계정의 문서 검색 | 제공되는 커넥터의 검색 도구 |
| 사내 조회 도구 연동 | 조직이 허용한 MCP 서버 |
| 회의록 절차 재사용 | D22의 스킬 |
| 기능 묶음 설치·공유 | 출처·권한을 확인한 플러그인 |

연결 수를 늘리는 것이 목표가 아니다. 필요한 업무 하나가 정확하게 되는지 확인한다.

## 2. 계정 없이 가능한 기본 실습

외부 계정 연결은 선택이다. 먼저 [공통 샘플](/chatgpt-materials/extensions)의 **가짜 연결 목록과 문서 조회 결과**를 ChatGPT 또는 Codex에 첨부한다.

```text
첨부한 가짜 연결 목록으로 권한 설계 연습을 하자.
실제 서비스에 연결하거나 인증 창을 열지 마.
업무는 교육 일정 문서 한 건을 조회하고 요약하는 것뿐이야.
연결별로 필요한 도구와 필요하지 않은 도구를 구분해줘.
서비스 토큰이나 계정 비밀번호를 요청하지 마.
결과를 출력/연결_권한설계.md에 저장해줘.
```

예상 설계는 `docs.search`, `docs.read`만 사용하는 것이다. `mail.send`, `calendar.create`, `db.execute`는 오늘 업무에 필요하지 않다. 가짜 목록에서 사용하지 않기로 정한 것은 **설계 결과**다. 실제 서비스 권한을 변경한 것이 아니다.

## 3. 실제 연결 전 화면 확인

선택 실습을 하려면 개인 연습 계정과 가짜 자료를 사용한다. ChatGPT에서는 현재 제공되는 **Plugins / 연결 관리**, Codex에서는 **Integrations / MCP** 등 실제 표시를 공식 안내와 대조한다. 없는 메뉴를 따라 찾느라 시간을 쓰지 말고 공식 안내와 계정·조직 지원을 먼저 본다.

다음을 기록한다.

| 확인할 것 | 기록 예시 |
|---|---|
| 지금 작업하는 화면 | ChatGPT 웹·앱 또는 Codex 로컬·클라우드 |
| 연결 대상·계정 | 개인 연습 문서 서비스·계정 일부 가림 |
| 인증 범위 | 문서 검색·읽기 등 실제 동의 화면 내용 |
| 제공 도구 | 검색·조회·작성·삭제 도구 존재 여부 |
| 승인 방식 | 읽기 요청과 쓰기 요청의 확인 방식 |
| 해제 위치 | 앱의 연결 관리 + 제공자 계정의 앱 접근 관리 |

인증 동의 화면의 범위가 필요한 것보다 넓으면 연결을 중단하고 기본 실습으로 돌아가도 된다. '읽기만 해'라는 요청은 토큰 자체를 읽기 전용으로 바꾸지 않는다.

## 4. 실제로 연결하는 선택 실습

1. 제공자와 조직이 안내하는 공식 연결 방법을 선택한다.
2. 지원되는 계정·연결 관리 화면에서 서비스를 추가한다.
3. 로그인 도메인, 계정, 권한 목록을 직접 확인한다. 비밀번호·인증 코드는 대화창에 붙여 넣지 않는다.
4. 현재 ChatGPT 또는 Codex 작업에서 해당 연결을 사용할 수 있는지 실제 도구 목록과 연결 계정을 확인한다.
5. 가짜 문서 한 건을 검색·읽기만 한다.
6. 사용한 도구·접근한 문서·변경 유무를 기록한다.

```text
연결된 연습 문서 서비스에서 '교육 일정 연습' 문서 한 건만 찾아줘.
검색과 읽기만 사용해줘. 문서 작성·수정·공유·메일 발송은 하지 마.
문서 제목, 수업 수, 총 교육시간, 출처를 정리해줘.
실제 조회 도구가 없으면 추정하지 말고 연결 확인 불가라고 말해줘.
```

기본 실습의 가짜 문서 기준은 **수업 2개, 총 90분**이다. 실제 계정에서는 같은 샘플을 연습 문서로 준비한 경우에만 이 값을 기대한다. 다른 실제 문서를 읽었는데 90분을 정답으로 맞추면 안 된다.

## 5. MCP 설정 파일은 어떤 때 보는가

ChatGPT 웹에서 플러그인으로 제공되는 연결과 Codex 로컬 설정을 구분한다. 웹 작업이 PC의 Codex 설정을 자동으로 읽는 것은 아니다.

Codex는 `config.toml`의 `[mcp_servers.<이름>]` 설정을 사용한다. 사용자 설정과 신뢰한 프로젝트의 `.codex/config.toml` 적용 범위가 다르다. Claude의 `.mcp.json`을 그대로 복사하지 않는다.

```text
조직이 허용한 서버의 공식 안내를 읽고 Codex 적용 계획만 작성해줘.
개인 config.toml과 프로젝트 .codex/config.toml 범위를 구분해줘.
기존 설정을 유지할 추가안과 인증·해제 위치를 보여줘.
비밀값을 파일이나 답변에 쓰지 말고 실제 설치·연결·인증은 하지 마.
```

이번 기본 실습에는 서버 주소·패키지 설치·실제 토큰이 필요 없다. 실제 연결이 필요할 때만 제공자가 정한 인증과 현재 제품의 지원 형식을 확인한다.

## 6. 서브에이전트의 외부 도구 권한

D24의 검토는 로컬 파일 두 개면 충분하다. 외부 문서·메일·DB 연결을 추가할 이유가 없다. Codex 서브에이전트는 부모 설정과 권한을 상속하므로 에이전트 TOML에 서버 이름을 하나 적었다고 독립된 접근 제한이 생긴다고 설명하지 않는다.

| 잘못된 판단 | 확인할 증거 |
|---|---|
| 읽기만 요청했으니 토큰도 읽기 전용 | 제공자 인증·실제 서비스 권한 |
| 검토자 이름이니 외부 쓰기 불가 | 부모 연결·현재 도구 범위·호출 기록 |
| 설정에 서버 하나만 보이니 다른 연결 없음 | 계정 연결·프로젝트/사용자 설정의 적용 범위 |

기술적 제한이 확인되지 않으면 그 한계를 적고 가짜 자료 기반 설계 실습으로 끝낸다. DB를 다루는 선택 실습은 별도 연습용 읽기 전용 계정과 허용된 조회 범위에서만 한다.

## 7. 연결 해제와 인증 폐기

1. 앱에서 연습 연결을 끄거나 제거한다.
2. 현재 세션에서 해당 도구를 더 사용할 수 없는지 확인한다. 필요하면 새 세션에서 확인한다.
3. 제공자 계정의 연결된 앱·OAuth 허용 목록에서도 접근을 해제한다.
4. 별도 토큰을 만들었다면 그 토큰을 제공자 측에서 폐기한다.
5. 연습 설정에 남은 참조와 환경 변수를 확인한다. 다른 앱과 공유하는 인증은 영향 범위를 먼저 확인한다.
6. `출력/연결_검수.md`에 해제한 것과 확인하지 못한 것을 나눠 기록한다.

**앱에서 연결을 지운 것과 제공자 인증을 폐기한 것은 별개의 확인 항목**이다. 실제로 연결하지 않았다면 '가짜 목록으로 권한 설계만 수행, 인증 해제 실습 미수행'으로 기록한다.

## 8. 플러그인은 마지막에

ChatGPT·Codex 플러그인은 재사용 절차와 연결 기능을 묶어 제공할 수 있다. 스킬·MCP·훅 등 어떤 구성이 현재 제품에서 지원되는지 실제 패키지와 공식 형식을 확인한다. 개인 실험이 끝나고 여러 프로젝트에 같은 구성을 적용할 때 검토한다. 설치 전 출처·구성 파일·실행 스크립트·필요한 인증·쓰기 범위를 확인한다.

이번에는 설치 없이 **D22 스킬, D23 검사, D24 검토자, D25 연결 설계**의 목록을 만든다. 종합 흐름은 '자료 조회 → 스킬로 초안 → 검토자 확인 → 사람이 검수'다. 외부 쓰기나 발송이 필요한 업무는 그 시점의 승인 범위를 따로 확인한다.

- B. 운영 DB 계정이 자동 변경된다

- B. 다른 사람의 비밀번호

- D. 모든 브라우저 기록 공개

- A. 실제 서비스 인증 성공
- B. 가짜 목록으로 권한 설계 수행, 실제 연결 미수행
- C. 실제 메일 조회 완료

## 정답과 해설

1. **B** — 사용자 연결 기능과 그 연결에 쓰이는 표준을 구분한다.

2. **C** — 조회 업무에 메일 발송 권한은 필요하지 않다.

3. **D** — 대화 지시가 서비스의 인증 범위를 자동으로 바꾸지는 않는다.

4. **A** — 클라이언트 설정 삭제와 제공자 인증 폐기를 따로 확인한다.

5. **B** — 설계와 실제 실행을 구분해야 잘못된 완료 보고를 피할 수 있다.
