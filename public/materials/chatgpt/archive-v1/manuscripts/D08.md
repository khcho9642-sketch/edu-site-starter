# [강좌] D08. 매번 같은 설명 안 하는 법

> ChatGPT 웹 대화 중심 · 가짜 자료 실습 · 예상 25~40분
> 별도 터미널·API 키 없이 시작합니다. 기능이 없는 계정의 대체 실습도 포함합니다.

## 3줄요약

1. 맞춤 지침·프로젝트·메모리를 용도별로 나눕니다.

2. 가짜 자료로 직접 실행하고 원문·기대 결과를 대조합니다.

3. 기능이 없으면 제공된 대체 실습으로 같은 검수 기준을 확인합니다.

## 1. 세 가지를 같은 저장소로 생각하지 않기

맞춤 지침은 "한국어로 간결하게, 미정은 구분" 같은 공통 응답 선호를 전달하는 데 유용합니다. 프로젝트는 특정 업무의 대화·파일·지침을 모으는 공간입니다. 메모리는 계정에서 허용한 과거 맥락을 활용하는 기능이며 항상 정확한 업무 원장처럼 쓰면 안 됩니다.

오늘은 ChatGPT 웹을 기준으로 합니다. 데스크톱·다른 도구의 로컬 메모리 설정과 혼동하지 마세요. 설정 이름이나 제공 여부는 계정에 따라 다를 수 있으므로 개인화 화면에서 실제 보이는 항목을 확인합니다.

## 2. 공통 선호와 업무 사실 분리

맞춤 지침에 행사 날짜와 정원을 영구 규칙처럼 넣으면 다음 업무에도 섞일 수 있습니다. 공통 지침에는 말투·형식·불확실성 표시 정도만 둡니다. 특정 행사 일정은 프로젝트의 안내문에 둡니다.

웹 프로젝트에 이름을 붙였다고 PC 폴더 전체가 자동 연결되지는 않습니다. 사용할 파일은 직접 업로드하거나 지원되는 연결을 명시적으로 설정해야 합니다. 어떤 자료를 추가했고 누구에게 공유했는지 확인하세요.

## 3. 설정한 뒤 작은 테스트를 한다

가짜 교육 프로젝트를 만들 수 있다면 안내문과 메모를 넣고 짧은 지침을 추가합니다. 새 대화를 프로젝트 안에서 열어 교육일과 미정 사항을 질문하세요. 원문과 일치하는지 확인하고, 프로젝트 밖의 대화에도 같은 자료가 있다고 가정하지 않습니다.

프로젝트를 쓸 수 없으면 자료와 지침을 묶은 인계 MD를 매번 첨부합니다. 이는 프로젝트를 설치한 것이 아니라 수동으로 맥락을 전달하는 대체 실습입니다. 무엇을 했는지 이름을 정확히 붙여야 다음 사람이 혼동하지 않습니다.

## 4. 메모리는 검수와 삭제 통제를 함께

메모리 사용 가능 여부와 관리 항목은 설정에서 확인하세요. 중요한 날짜·합계·승인 규칙은 별도 원문으로 관리합니다. 기억해 달라는 말 한 번으로 모든 향후 대화가 정확히 따를 것이라 기대하지 않습니다.

공유 자료의 범위도 확인합니다. 비공개와 팀 공유를 구분하고, 가짜 데이터로 테스트를 마친 뒤 실제 업무의 입력·보관 규칙에 맞는지 판단합니다. 이 강의에서는 실제 회사 자료나 비밀값을 추가하지 않습니다.

## 5. 직접 해 보기

예상 15~25분. 먼저 [실습 자료실](/chatgpt-materials)에서 필요한 자료를 열어 보세요. 원문이 필요한 요청의 대괄호 부분은 실제 자료 전체로 바꿉니다.

1. 새 대화에서 원자료를 확인합니다.
2. 아래 요청을 붙이고 답을 받습니다.
3. 이어지는 수정 요청을 보냅니다.
4. 기대 결과와 대조하고 결과를 별도 MD·CSV로 저장합니다.

```text
다음 공통 응답 선호를 짧은 맞춤 지침 후보로 정리해 줘.
한국어로 간결하게. 사실/추정/미확인을 구분. 원문 숫자 유지.
특정 행사 날짜나 개인 정보는 공통 지침에 넣지 않음.
별도로 새싹팀 프로젝트 지침 후보를 만들어 줘:
제공된 안내문과 회의 메모만 근거로 하고, 없는 정보는 미정.
실제 발송·공유는 이번 연습에서 하지 않음.
후보 작성만 하고 설정을 바꿨다고 말하지 마.
```

### 이어서 보낼 요청

```text
가능하면 내가 웹 설정과 가짜 교육 프로젝트에 지침을 직접 넣고 새 대화에서 시험할게. 프로젝트가 없으면 지침+원자료를 인계 MD로 묶어 줘. 설정·업로드·테스트 중 실제로 완료한 것과 아직 안 한 것을 구분해 줘.
```

## 6. 기대 결과와 직접 검수

- [ ] 공통 지침에는 교육일·이름 같은 이번 업무의 사실이 없습니다.
- [ ] 프로젝트용 지침에는 자료 범위와 미정 처리 기준이 있습니다.
- [ ] 새 대화의 교육일·정원 답이 원문과 맞는지 확인합니다.
- [ ] 직접 한 설정과 후보 문서만 작성한 상태를 구분해 기록합니다.

AI가 스스로 맞다고 평가한 문장만으로 통과 처리하지 마세요. 원자료를 열어 값과 근거를 확인합니다. 실제 지원 기능이 없는 경우 표·MD 본문으로 검수하고 기능을 실행한 것처럼 기록하지 않습니다.

## 7. 막혔을 때

| 증상 | 확인과 수정 |
| --- | --- |
| 다음 업무에 옛 날짜가 섞임 | 공통 지침에서 업무 사실을 빼고 최신 원문을 명시합니다. |
| 프로젝트가 파일을 못 찾음 | 실제 업로드·연결 여부를 확인합니다. |
| 메모리 메뉴가 없음 | 계정 설정을 확인하고 중요한 규칙은 인계 MD로 전달합니다. |

## 숙제

공통 선호 3줄, 업무 지침 3줄, 새 대화 테스트 결과를 각각 저장하세요. 실제 변경한 설정도 기록하세요.

제출용 메모에는 사용 자료, 처음 생긴 문제, 수정 요청, 최종 확인 근거를 함께 적으세요.

## 확인 퀴즈

### Q1. 공통 맞춤 지침에 적절한 것은?

- A. 이번 행사 날짜를 영구 고정
- B. 회사 API 키
- C. 한국어로 간결하게, 미확인 구분
- D. 모든 업무 금액은 4만원

### Q2. 웹 프로젝트를 만들면?

- A. PC 폴더 전체가 자동 공개
- B. 쓸 파일을 직접 추가하거나 연결해야 함
- C. 모든 조직 문서 권한 획득
- D. 파일 검수 불필요

### Q3. 메모리는 중요한 원문을?

- A. 항상 대체한다
- B. 무조건 정확히 복제한다
- C. 외부에 자동 공개한다
- D. 대신하는 유일한 원장으로 삼지 않는다

### Q4. 설정 후보를 글로 만들었다면?

- A. 아직 실제 설정 변경과 구분해야 함
- B. 설치 완료임
- C. 모든 계정에 적용됨
- D. 프로젝트 생성 완료임

### Q5. 프로젝트 기능이 없을 때 대체는?

- A. 권한 공유 요청
- B. 기억한다고 가정
- C. 지침과 원자료를 인계 MD로 전달
- D. 이전 자료 삭제

## 정답과 해설

1. **C** — 반복 응답 선호와 특정 업무 사실을 분리합니다.
2. **B** — 프로젝트 이름만으로 로컬 자료에 접근하지 않습니다.
3. **D** — 필수 사실과 규칙은 별도 자료로 관리합니다.
4. **A** — 초안 작성과 실제 적용은 다릅니다.
5. **C** — 같은 맥락 전달을 문서 첨부로 연습합니다.
