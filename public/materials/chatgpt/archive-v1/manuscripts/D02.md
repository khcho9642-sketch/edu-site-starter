# [강좌] D02. 질문을 잘해야 답도 잘 나옴

> ChatGPT 웹 대화 중심 · 가짜 자료 실습 · 예상 25~40분
> 별도 터미널·API 키 없이 시작합니다. 기능이 없는 계정의 대체 실습도 포함합니다.

## 3줄요약

1. 목적·배경·조건·형식으로 모호한 요청을 고칩니다.

2. 가짜 자료로 직접 실행하고 원문·기대 결과를 대조합니다.

3. 기능이 없으면 제공된 대체 실습으로 같은 검수 기준을 확인합니다.

## 1. 잘 써 줘의 빈칸

AI는 내가 속으로 생각한 독자와 기준을 자동으로 알지 못합니다. "안내문 잘 써 줘"에는 무엇을 안내하는지, 누구에게 보낼지, 얼마나 길게 쓸지가 빠져 있습니다. 역할 이름을 거창하게 붙이는 것보다 이 빈칸을 채우는 편이 유용합니다.

목적은 동료의 교육 신청, 독자는 처음 듣는 사무직 동료, 배경은 제공된 가짜 안내문, 조건은 사실 유지와 미정 표시, 형식은 일정표와 짧은 안내로 정합니다. 모든 질문에 긴 양식이 필요한 것은 아닙니다. 결과를 바꾸는 항목만 적으세요.

## 2. 좋은 제약은 검수할 수 있다

"최고로 멋지게"보다 "핵심 일정 표 1개와 안내 3문장"이 확인하기 쉽습니다. 길이·대상·유지할 사실·추측 금지 같은 조건은 완성 여부를 판단하게 해 줍니다. 조건을 너무 많이 쌓으면 서로 충돌할 수 있으니 우선순위도 생각하세요.

예를 들어 "모든 세부 사항을 담되 10자 이내"는 실현하기 어렵습니다. 충돌하면 어느 조건을 우선할지 질문하도록 요청합니다. 빠진 정보를 질문하는 답도 좋은 결과입니다.

## 3. 예시를 줄 때 답까지 베끼게 하지 않기

원하는 표의 열 이름을 알려 주면 형식이 안정됩니다. 다만 예시의 날짜나 이름이 새 작업에 섞이지 않도록 "형식만 참고"라고 명시하세요. 교육 안내 실습에는 예전 행사의 녹화 링크나 인원을 가져오면 안 됩니다.

출력 형식은 일정·내용·확인 상태 세 열이면 충분합니다. 원문에 없는 항목은 미정으로 쓰도록 합니다. 실제 전송이나 신청 처리까지 요청할 필요는 없습니다.

## 4. 질문 전후를 비교해야 배운다

먼저 모호한 질문으로 받은 답을 저장하고, 같은 자료를 넣어 개선된 질문으로 다시 답을 받아 보세요. 두 답의 차이를 길이가 아니라 사실 보존·미정 표시·읽기 쉬움으로 평가합니다.

이후에는 잘 작동한 요청을 템플릿으로 남깁니다. 템플릿에 실제 개인정보를 박아 넣지 말고 독자·목적·자료를 바꿀 수 있게 만드세요. 질문을 다듬는 실력은 단어 암기가 아니라 결과를 비교하는 데서 늘어납니다.

## 5. 직접 해 보기

예상 15~25분. 먼저 [실습 자료실](/chatgpt-materials)에서 필요한 자료를 열어 보세요. 원문이 필요한 요청의 대괄호 부분은 실제 자료 전체로 바꿉니다.

1. 새 대화에서 원자료를 확인합니다.
2. 아래 요청을 붙이고 답을 받습니다.
3. 이어지는 수정 요청을 보냅니다.
4. 기대 결과와 대조하고 결과를 별도 MD·CSV로 저장합니다.

```text
목적: 새싹팀 동료가 교육 일정을 확인하고 신청하도록 안내.
독자: 처음 참가하는 동료. 자료: 실습 자료실의 교육 안내문 전체를 아래에 붙임.
형식: 항목/내용/확인 상태 표와 안내 세 문장.
조건: 자료의 날짜·시간·정원을 유지. 없는 정보는 미정. 실제 발송은 하지 않음.
작업에 꼭 필요한 정보가 빠졌으면 먼저 질문해 줘.
[여기에 교육 안내문 전체를 붙여 넣기]
```

### 이어서 보낼 요청

```text
내 요청 중 서로 충돌하거나 모호한 조건이 있는지 짚어 줘. 완성한 안내의 각 사실이 원문의 어느 문장에 근거하는지도 표시해 줘.
```

## 6. 기대 결과와 직접 검수

- [ ] 교육일·신청 기한·정원·접속 링크 상태가 별도 행으로 나옵니다.
- [ ] 표와 세 문장 안내가 있으며 미정 사항을 사실처럼 확정하지 않습니다.
- [ ] 비교 기록에는 개선 전 답의 문제 2개와 개선한 조건 2개를 적습니다.

AI가 스스로 맞다고 평가한 문장만으로 통과 처리하지 마세요. 원자료를 열어 값과 근거를 확인합니다. 실제 지원 기능이 없는 경우 표·MD 본문으로 검수하고 기능을 실행한 것처럼 기록하지 않습니다.

## 7. 막혔을 때

| 증상 | 확인과 수정 |
| --- | --- |
| 자료 없이 훌륭한 안내가 나옴 | 그럴듯하게 보완한 것일 수 있습니다. 원자료를 붙이고 재작성합니다. |
| 예시의 이름이 섞임 | 형식만 참고하라는 조건을 주고 고유명사를 대조합니다. |
| 조건이 너무 많아 누락됨 | 핵심 사실 유지부터 우선하고 형식 수정을 다음 요청으로 나눕니다. |

## 숙제

자주 쓰는 요청 하나를 목적·독자·배경·조건·형식으로 고쳐 두 버전을 비교하세요. 가짜 사례를 사용하고 성공 기준 3개를 남기세요.

제출용 메모에는 사용 자료, 처음 생긴 문제, 수정 요청, 최종 확인 근거를 함께 적으세요.

## 확인 퀴즈

### Q1. 질문을 개선할 때 가장 유용한 정보는?

- A. 멋진 수식어만 추가
- B. 아무 분야의 전문가 역할
- C. 목적과 독자, 필요한 사실
- D. 토큰을 무조건 많이 쓰기

### Q2. 검수하기 쉬운 조건은?

- A. 세상에서 가장 잘
- B. 무조건 완벽하게
- C. 센스 있게
- D. 일정 표 1개와 안내 3문장

### Q3. 형식 예시를 줄 때는?

- A. 예시의 사실도 모두 복사하게 한다
- B. 형식만 참고하고 현재 자료의 사실을 사용하게 한다
- C. 예시 날짜를 항상 우선한다
- D. 이름을 지우지 않는다

### Q4. 자료가 부족할 때 좋은 응답은?

- A. 필요한 정보를 먼저 질문한다
- B. 임의로 채운다
- C. 확신 있게 단정한다
- D. 관련 없는 글을 길게 쓴다

### Q5. 요청 두 개가 충돌하면?

- A. 둘 다 지켰다고 쓰게 한다
- B. 조건을 모두 삭제한다
- C. 우선할 조건을 정한다
- D. 출처를 숨긴다

## 정답과 해설

1. **C** — 결과에 영향을 주는 맥락을 알려 주어야 합니다.
2. **D** — 관찰 가능한 형식과 수량은 결과 확인에 도움이 됩니다.
3. **B** — 예시와 이번 작업의 사실을 구분해야 합니다.
4. **A** — 빠진 정보를 드러내면 잘못된 완성을 줄입니다.
5. **C** — 충돌을 확인하고 우선순위를 정해야 합니다.

## 념글 박제

> 목적·배경·조건·형식으로 모호한 요청을 고칩니다. 답의 완성도는 직접 확인한 근거로 판단합니다.
