# [강좌] D01. GPT 처음 써본 썰

> ChatGPT 웹 대화 중심 · 가짜 자료 실습 · 예상 25~40분
> 별도 터미널·API 키 없이 시작합니다. 기능이 없는 계정의 대체 실습도 포함합니다.

## 3줄요약

1. 브라우저에서 첫 대화를 하고 답을 직접 확인합니다.

2. 가짜 자료로 직접 실행하고 원문·기대 결과를 대조합니다.

3. 기능이 없으면 제공된 대체 실습으로 같은 검수 기준을 확인합니다.

## 1. 앱 설치보다 첫 대화가 먼저

이 과정은 ChatGPT 웹의 대화를 기준으로 합니다. 공식 주소 https://chatgpt.com 에서 시작하세요. 별도 터미널이나 API 키는 필요하지 않습니다. 데스크톱 앱을 이미 쓰고 있다면 같은 질문 실습을 할 수 있지만 메뉴 위치는 다를 수 있습니다. 화면이 교재와 다르다고 잘못 설치한 것은 아닙니다.

로그인 계정과 개인·조직 작업 공간부터 확인하세요. 기능과 사용량은 플랜·지역·조직 설정에 따라 다릅니다. 이 강의 때문에 바로 결제할 필요는 없습니다. 현재 화면에서 가능한 대화로 시작하고, 기능이 없으면 각 강의의 대체 실습을 하세요.

## 2. 대화 상대이지 사실 확인 도장은 아님

질문을 입력하면 답을 이어 주지만, 자연스러운 문장이 사실이라는 뜻은 아닙니다. 모르면서 그럴듯하게 말하는 경우도 있습니다. 오늘은 답을 잘 받는 것과 답을 검수하는 것을 한 묶음으로 연습합니다.

입력창은 요청을 쓰는 곳, 대화 영역은 요청과 답이 쌓이는 곳입니다. 새 대화는 작업을 구분할 때 사용합니다. 중요한 결과는 별도 문서에도 저장하세요. 대화 목록만 믿고 원본과 최종본을 섞어 두면 나중에 어느 쪽이 확정본인지 헷갈립니다.

## 3. 오늘 할 일은 가짜 안내문 세 문장

실습 자료실의 교육 안내문을 읽으세요. 새싹팀 교육은 2026년 12월 3일 14시부터 15시, 온라인, 정원 12명입니다. 신청 기한은 12월 1일입니다. 녹화 여부와 접속 링크는 미정입니다. 교재의 사람·팀·거래는 모두 가짜입니다.

처음부터 실제 회사 문서를 넣지 말고, 이 짧은 자료만 사용합니다. 질문에 모든 배경을 길게 쓰는 것보다 답에 꼭 필요한 사실을 골라 전달하는 것이 중요합니다.

## 4. 답을 읽는 순서를 바꾸기

멋진 문장인지 보기 전에 날짜·시간·인원부터 찾습니다. 다음으로 입력하지 않은 사실이 추가됐는지 봅니다. 마지막에 말투를 다듬습니다. 틀린 내용이 있으면 그 부분을 집어 수정하세요. 같은 질문을 반복해서 마음에 드는 답만 고르는 방법은 검수가 아닙니다.

수정해도 불확실하면 원자료로 돌아갑니다. 모르는 내용은 미정으로 남겨도 됩니다. 이 습관을 졸업 실습까지 유지합니다.

## 5. 직접 해 보기

예상 15~25분. 먼저 [실습 자료실](/chatgpt-materials)에서 필요한 자료를 열어 보세요. 원문이 필요한 요청의 대괄호 부분은 실제 자료 전체로 바꿉니다.

1. 새 대화에서 원자료를 확인합니다.
2. 아래 요청을 붙이고 답을 받습니다.
3. 이어지는 수정 요청을 보냅니다.
4. 기대 결과와 대조하고 결과를 별도 MD·CSV로 저장합니다.

```text
다음 가짜 안내를 처음 듣는 동료에게 세 문장으로 설명해 줘.
새싹팀 교육: 2026-12-03 14:00~15:00, 온라인, 정원 12명.
신청 기한: 2026-12-01. 접속 링크와 녹화 여부는 미정.
주어진 사실만 사용하고 미정인 것은 미정이라고 적어 줘.
```

### 이어서 보낼 요청

```text
방금 답에서 날짜·시간·정원·미정 항목을 따로 뽑아 원문과 대조하는 표를 만들어 줘. 새 사실은 추가하지 마.
```

## 6. 기대 결과와 직접 검수

- [ ] 교육일 12월 3일과 신청 기한 12월 1일이 구분됩니다.
- [ ] 시간 14:00~15:00와 정원 12명이 유지됩니다.
- [ ] 녹화 가능·접속 링크 확정 같은 약속이 추가되지 않습니다.
- [ ] 원문과 결과를 직접 비교한 뒤 최종 답을 D01_첫대화.md로 저장합니다.

AI가 스스로 맞다고 평가한 문장만으로 통과 처리하지 마세요. 원자료를 열어 값과 근거를 확인합니다. 실제 지원 기능이 없는 경우 표·MD 본문으로 검수하고 기능을 실행한 것처럼 기록하지 않습니다.

## 7. 막혔을 때

| 증상 | 확인과 수정 |
| --- | --- |
| 입력창이 안 보임 | 로그인과 현재 작업 공간을 확인하고 공식 웹에서 새 대화를 엽니다. |
| 답이 너무 김 | 세 문장, 동료 대상이라는 조건을 다시 지정합니다. |
| 기능 이름이 다름 | 대화 입력·새 대화처럼 목적에 맞는 기능을 찾고 유료 결제를 먼저 하지 않습니다. |

## 숙제

같은 자료로 한 문장 안내와 세 문장 안내를 각각 만들고, 두 답에서 유지된 사실 3개와 미정 항목 2개를 표시하세요.

제출용 메모에는 사용 자료, 처음 생긴 문제, 수정 요청, 최종 확인 근거를 함께 적으세요.

## 확인 퀴즈

### Q1. 첫 실습에 필요한 것은?

- A. 터미널 설치
- B. 공식 웹에서 대화를 시작할 수 있는 환경
- C. 회사 API 키
- D. 유료 플랜 결제

### Q2. 답이 자연스럽다면?

- A. 사실 확인을 생략한다
- B. 바로 배포한다
- C. 원문과 핵심 사실을 대조한다
- D. 항상 최신 정보이다

### Q3. 녹화 여부가 자료에 없다면?

- A. 가능하다고 쓴다
- B. 다른 교육 사례를 복사한다
- C. 확률로 정한다
- D. 미정으로 남긴다

### Q4. 새 대화를 쓰는 이유로 적절한 것은?

- A. 서로 다른 작업을 구분하기 위해
- B. 모든 대화가 자동 공유되게 하려고
- C. 답이 항상 맞게 하려고
- D. 요금이 사라지게 하려고

### Q5. 화면에 교재의 기능이 없다면?

- A. 무조건 결제한다
- B. 계정·조직 설정을 확인하고 대체 실습을 한다
- C. 계정 비밀번호를 질문에 쓴다
- D. 설치를 반복한다

## 정답과 해설

1. **B** — 이 과정은 웹 대화로 시작하며 별도 API 키가 필요하지 않습니다.
2. **C** — 문장의 자연스러움은 정확성을 보장하지 않습니다.
3. **D** — 근거가 없는 약속을 추가하지 않습니다.
4. **A** — 작업을 나누면 맥락과 확정 내용을 관리하기 쉽습니다.
5. **B** — 기능 제공 범위는 계정과 환경에 따라 다릅니다.
