# [강좌] D07. 메일·보고서 노가다 줄이기

> ChatGPT 웹 대화 중심 · 가짜 자료 실습 · 예상 25~40분
> 별도 터미널·API 키 없이 시작합니다. 기능이 없는 계정의 대체 실습도 포함합니다.

## 3줄요약

1. 회의의 결정·할 일·미정을 나누어 초안을 만듭니다.

2. 가짜 자료로 직접 실행하고 원문·기대 결과를 대조합니다.

3. 기능이 없으면 제공된 대체 실습으로 같은 검수 기준을 확인합니다.

## 1. 초안 작성과 발송은 별개의 일

회의 메모를 메일과 한 페이지 보고서로 바꾸는 일은 ChatGPT의 유용한 활용입니다. 하지만 글을 만들어 달라는 요청이 외부 발송까지 뜻하는 것은 아닙니다. 이번 실습은 문서 초안만 만들고 실제 메일·일정·외부 시스템은 건드리지 않습니다.

먼저 원문의 결정, 할 일, 미정을 나눕니다. 회의에서 의견으로 나온 사항을 확정된 약속처럼 쓰면 곤란합니다. 실제 받는 사람 주소나 연락처는 필요하지 않으며 가짜 인물의 이름만 사용합니다.

## 2. 담당자와 기한이 실무의 뼈대

가짜 메모에서 가람은 11월 25일까지 신청 현황표를 정리하고, 나래는 11월 27일까지 안내 초안을 준비합니다. 녹화 여부와 접속 링크는 미정입니다. 한 사람이 두 일을 맡았다고 쓰거나 기한을 교육일로 바꾸지 않도록 주의합니다.

업무 표의 열은 할 일·담당·기한·상태로 정합니다. 담당이 없는 새 과제를 AI가 자동 배정하면 안 됩니다. 누락된 담당과 기한은 미정으로 표시하고 확인 질문으로 남깁니다.

## 3. 보고서는 독자가 결정할 정보를 앞에

보고서에는 교육 일정, 준비 현황, 남은 확인 사항을 넣습니다. 메일은 읽는 사람이 다음에 무엇을 해야 하는지 짧게 보여 줍니다. 같은 사실을 사용해도 독자와 형식에 따라 순서를 바꿀 수 있습니다.

상사에게 쓰는 말투라고 불필요하게 긴 사과·미사여구를 붙일 필요는 없습니다. 먼저 사실이 맞는지 검수하고, 그다음 정중하고 간결한 표현으로 다듬습니다. 없는 예산 승인이나 녹화 제공 약속은 추가하지 않습니다.

## 4. 최종 확인은 원문과 두 산출물 세 장으로

원문·보고서·메일 초안을 나란히 놓고 날짜, 담당, 기한, 미정 항목을 확인하세요. 제목만 바꾼 파일이 아니라 각 목적에 맞는 두 결과물이 필요합니다. 파일 생성이 가능하면 실제 문서를 열고 잘린 표나 빈 페이지도 확인합니다.

지원되지 않으면 MD로 저장해도 충분합니다. 실제 발송을 하려면 받는 사람·첨부·문구를 사람이 별도로 확인하는 절차가 필요하지만, 이 강의의 완료 기준은 검수된 초안 저장입니다.

## 5. 직접 해 보기

예상 15~25분. 먼저 [실습 자료실](/chatgpt-materials)에서 필요한 자료를 열어 보세요. 원문이 필요한 요청의 대괄호 부분은 실제 자료 전체로 바꿉니다.

1. 새 대화에서 원자료를 확인합니다.
2. 아래 요청을 붙이고 답을 받습니다.
3. 이어지는 수정 요청을 보냅니다.
4. 기대 결과와 대조하고 결과를 별도 MD·CSV로 저장합니다.

```text
가짜 교육 안내문과 회의 메모만 사용해 줘.
1. 결정/할 일/미정으로 구분한 표.
2. 팀장용 한 페이지 보고서: 일정, 준비 현황, 확인 필요 사항.
3. 동료용 메일 초안: 제목과 본문, 짧고 정중하게.
담당·기한·숫자는 유지. 새로운 약속이나 실제 메일 주소는 추가하지 마.
모든 결과에 초안이라고 표시. 외부 발송이나 일정 등록은 하지 마.
[교육 안내문과 회의 메모 전체 붙여 넣기]
```

### 이어서 보낼 요청

```text
메일만 더 짧게 고쳐 줘. 가람 11월 25일, 나래 11월 27일의 할 일과 기한은 유지하고 녹화·접속 링크는 미정으로 남겨 줘. 원문 대비 새 사실이 추가됐는지 확인표도 붙여 줘.
```

## 6. 기대 결과와 직접 검수

- [ ] 가람의 신청 현황표 기한은 2026-11-25, 나래의 안내 초안 기한은 2026-11-27입니다.
- [ ] 보고서와 메일에 교육 일정이 같고 녹화·링크는 미정입니다.
- [ ] 메일은 초안 상태이고 발송 완료라고 쓰지 않습니다.
- [ ] 미정 항목을 후속 확인 목록으로 남깁니다.

AI가 스스로 맞다고 평가한 문장만으로 통과 처리하지 마세요. 원자료를 열어 값과 근거를 확인합니다. 실제 지원 기능이 없는 경우 표·MD 본문으로 검수하고 기능을 실행한 것처럼 기록하지 않습니다.

## 7. 막혔을 때

| 증상 | 확인과 수정 |
| --- | --- |
| 보고서에 예산 승인이 생김 | 원문에 없는 내용을 삭제하고 근거가 있는 결정만 남깁니다. |
| 담당이 바뀜 | 할 일·담당·기한 표를 원문과 먼저 대조한 후 초안을 다시 만듭니다. |
| 발송했다고 함 | 실제 작업 기록과 도구 결과가 없으면 초안 작성으로 바로잡습니다. |

## 숙제

같은 메모로 보고서와 메일 초안을 만들고, 공통 사실 5개와 형식 차이 2개를 기록하세요.

제출용 메모에는 사용 자료, 처음 생긴 문제, 수정 요청, 최종 확인 근거를 함께 적으세요.

## 확인 퀴즈

### Q1. 가람의 기한은?

- A. 12월 3일
- B. 11월 27일
- C. 11월 25일
- D. 미정

### Q2. 회의에서 결정되지 않은 내용은?

- A. 확정 약속으로 표현
- B. 미정과 확인 사항으로 분리
- C. AI가 결정
- D. 문서에서 무조건 숨김

### Q3. 메일 초안 작성 완료는?

- A. 외부 발송 완료와 같다
- B. 받는 사람 확인 불필요
- C. 자동 승인 완료
- D. 발송과 별개의 상태이다

### Q4. 말투를 고칠 때 유지할 것은?

- A. 원문의 사실과 담당·기한
- B. 이전 답의 오류
- C. 과장된 약속
- D. 임의의 날짜

### Q5. 최종 검수에 필요한 자료는?

- A. 메일만
- B. 보고서 제목만
- C. 원문·보고서·메일 초안
- D. 새로 만든 숫자표만

## 정답과 해설

1. **C** — 신청 현황표를 11월 25일까지 정리합니다.
2. **B** — 확정 사항과 미정 사항을 구분합니다.
3. **D** — 이번 실습은 실제 발송을 하지 않습니다.
4. **A** — 표현을 바꿔도 사실은 유지합니다.
5. **C** — 같은 사실이 두 결과물에 일관되게 반영됐는지 봅니다.

## 념글 박제
