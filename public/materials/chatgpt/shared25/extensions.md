# 확장 기능 심화 공통 샘플 — D22~D25

모든 이름·날짜·서비스·문서는 가짜다. 필요한 블록만 별도 파일로 저장한다. 아래의 파일 생성·조회 예시는 학습자가 연습 폴더에서 수행할 실습이며 실제 계정에 대한 실행 지시가 아니다.

## 1. 입력/회의A.md

```markdown
# 회의 A — 2026-12-01
- M01: 교육 안내문 초안을 민수가 12월 3일까지 작성하기로 함.
- M02: 신청서 항목 점검은 12월 4일까지 진행하기로 함. 담당자는 아직 정하지 않음.
- M03: 장소 후보 비교는 지민이 맡기로 함. 기한은 아직 정하지 않음.
- M04: 유료 광고 집행은 예산 확인 후 재논의하기로 함. 현재 보류.
```

정답 기준: 실행 3개(M01~M03), 담당자 미정 1개(M02), 기한 미정 1개(M03), 보류 1개(M04). 실행할 일의 상태는 '예정' 또는 같은 뜻의 표현을 사용할 수 있다.

## 2. 입력/회의B.md

```markdown
# 회의 B — 2026-12-02
- N01: 교육 자료의 출처 링크는 수진이 12월 5일까지 점검하기로 함.
- N02: 실습 파일 검수는 민수가 맡기로 함. 기한 미정.
- N03: 외부 홍보 메일 발송은 명단 검토가 끝날 때까지 보류하기로 함.
```

정답 기준: 실행 2개(N01~N02), 담당자 미정 0개, 기한 미정 1개(N02), 보류 1개(N03). 회의 A의 담당자·기한을 가져와 채우면 안 된다.

## 3. 검수/회의A_오류예시.md

아래는 **일부러 오류 3개를 넣은 검토 대상**이다. 제목이나 문구보다 회의 원문을 우선한다.

```markdown
# 회의 A 정리 결과 — 검토 대상
| 근거ID | 할 일 | 담당자 | 기한 | 상태 |
|---|---|---|---|---|
| M01 | 교육 안내문 초안 작성 | 민수 | 2026-12-03 | 예정 |
| M02 | 신청서 항목 점검 | 수진 | 2026-12-04 | 예정 |
| M03 | 장소 후보 비교 | 지민 | 2026-12-05 | 예정 |
| M04 | 유료 광고 집행 | 미정 | 미정 | 예정 |
```

오류: M02 담당자 추정, M03 기한 추정, M04 보류를 실행 업무로 오분류. M01은 정상이다. 원문의 표기만 바꾼 ISO 날짜는 오류가 아니다.

## 4. 훅 실습 파일

`normal-demo.md`:

```text
수정 전
```

`protected-demo.md`:

```text
교육용 고정 문장입니다. 실제 비밀정보가 아닙니다.
```

정답 기준: 훅 적용 중에는 지정한 수정 도구 호출에서 일반 파일 수정 허용, 보호 파일 수정 차단. 실습 전·후 파일과 훅 호출 기록으로 판정한다. 다른 도구의 수정까지 검사한 것으로 확대하지 않는다.

## 5. 가짜 연결 목록 — 실제 연결 아님

| 연결 | 도구 | 기능 |
|---|---|---|
| 연습 문서 | docs.search | 문서 검색 |
| 연습 문서 | docs.read | 문서 읽기 |
| 연습 문서 | docs.update | 문서 수정 |
| 연습 메일 | mail.send | 메일 발송 |
| 연습 일정 | calendar.create | 일정 등록 |
| 연습 DB | db.execute | 데이터베이스 명령 실행 |

과제: 교육 일정 문서 한 건을 검색하고 읽어 요약한다. 필요 도구는 docs.search, docs.read다. 나머지는 이번 업무에 필요하지 않다. 이 표는 MCP 도구의 실제 API 명칭을 보장하지 않는 역할 설계용 자료다.

## 6. 가짜 문서 조회 결과

```markdown
# 교육 일정 연습
문서ID: DEMO-DOC-01
수업1: 2026-12-10 10:00~10:30, 30분
수업2: 2026-12-10 10:40~11:40, 60분
상태: 검토용, 실제 예약 아님
```

정답 기준: 수업 2개, 교육시간 90분. 중간 휴식 10분은 교육시간에서 제외한다. 전체 시작~종료의 경과시간은 100분이다. 두 값을 혼동하지 않는다.

## 7. 공통 완료 기록 양식

```markdown
# 심화 실습 완료 기록
- 강의:
- 앱 화면·로컬/클라우드:
- 입력 파일:
- 만든 파일 또는 설정:
- 실제 실행한 기능:
- 예상 결과:
- 실제 결과:
- 확인한 증거:
- 확인하지 못한 부분:
- 원본 변경 여부:
- 실습 설정 해제·복구 여부:
```

스킬 호출·서브에이전트 위임·실제 서비스 조회를 하지 않았다면 했다고 쓰지 않는다. 예시 결과와 실제 결과를 나눠 기록한다.
